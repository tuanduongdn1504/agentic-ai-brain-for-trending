01The thesis

Every subsystem in this repository is well built. That is what makes the pattern legible. Four times, in four different corners, a discipline that one team plainly holds does not reach the team next door — and in each case the defect is sitting exactly where the practice stopped.

Each "absent" cell carries the extent of the search that produced it. A negative without an extent is not a negative.

In a large, well-engineered, multi-team repository, a discipline stops at the edge of the team that holds it. Find an internal seam — subsystem to subsystem, code to prose, feature to feature — and ask what carries the practice across it. Nothing does, unless something was built to.

This is the run's own argument arriving at its smallest scale. v258: code moves forward in time and never backward. v262: a practice does not transfer by proximity — the example sat in his own account for a month, unused. v264: it does not transfer between two directories of one repository, in one release, written by colleagues. Time, ownership, organisational distance — three axes, one mechanism. Practices travel only along paths someone builds for them.

02Claude Code as a workflow

examples/experimental/ holds five coding-agent adapters — Claude Code, Codex, Cursor, Hermes and OpenClaw — all landed in a single commit on 2026-06-04. The Claude one is 302 lines and works like this:

nat run --config_file config-relay.yml --input "..."
   └─ nemo-relay run --agent claude --plugin-config {...}
        └─ claude --print "<prompt>" --permission-mode plan ...

Relay observes the process → events.jsonl (ATOF)
   └─ inject_atof_jsonl() → toolkit telemetry → one Phoenix trace
        └─ nat eval → avg_workflow_runtime · avg_num_llm_calls · avg_tokens_per_llm_end

The trace covers the toolkit's workflow span and Claude Code's own agent, model and tool spans. It uses your local Claude Code credentials — nothing goes in the YAML. That is a measurement harness pointed at Claude Code, and nothing in 263 prior subjects is closer to the standing observability and cost threads.

The shipped config is the safest coding-agent integration in the corpus

Eleven lines, four deliberate decisions: permission_mode: plan · every mutating tool denied by name (Bash, Edit, MultiEdit, NotebookEdit, Write) · setting_sources: [project] so it does not inherit your personal Claude settings · max_budget_usd: 1.00. The safe configuration is the default and it still does the interesting thing — which is exactly what v247 could not manage.

And the defect is on the operator's exact thread

register.py:130-132 computes prompt_tokens and completion_tokens as len(text.split()) — whitespace word counts — and hands them back as ChatResponse.usage. Meanwhile relay_telemetry_bridge.py:243-256 extracts real usage from Relay's events for the trace and the evaluation.

Two token accountings in one run: the trace and nat eval are measured, the response object is invented. And the split falls exactly on the tested/untested line — the shared bridge got a 153-line test the day it was written; none of the five adapters has a single test.

03The best consent code in 264 subjects

The last three ships asked one question — is the declared rule enforced? — and got no three times: a protocol with no evidence records, a gate that could not fail, 403 tests nothing ran. utils/telemetry/consent.py is 310 lines and answers yes, with mechanism.

A three-TTY gate, with the failure mode written down

Interactive prompt — only if all three of stdin, stdout, and stderr are TTYs … The prompt itself is rendered to stderr, so a captured stderr would be invisible-but-effectful; gating on all three streams prevents that footgun.

Someone identified a control the user cannot see but whose answer still binds them — the precise class of defect this run has documented three times — named it, and closed it.

A version number whose only job is to expire consent in one direction

Stored decision, stale versionResultStated reason
disabledstays disabled"we never silently re-enable telemetry for someone who said no"
enabledre-prompts"a stale 'yes' should not silently authorize collection under a new (potentially broader) disclosure"

Then a second, opposite asymmetry: a failed write during the first-run prompt is swallowed, because you will simply be re-asked — but an explicit nat configure telemetry --disable reads back and raises if it did not persist. Both asymmetries are correct, and both are argued in comments.

The disclosure text lives inline in the code "so tests can assert on its contents and reviewers see any wording change in PR diffs." NAT_TELEMETRY_ENDPOINT=stdout prints the exact payload to stderr so you can read the wire before trusting it. The subsystem carries 1,363 lines of tests across eight files.

One real criticism: the prompt is [Y/n] and Enter opts you in. Against that — Ctrl-C and EOF opt you out, and every non-interactive context and every library import defaults to off.

04What the gates do — and a third species

copy-pr-bot mirrors an approved PR into a pull-request/NNNN branch, and that push runs CI across Python 3.11, 3.12 and 3.13. There is deliberately no pull_request: trigger, so untrusted fork code never touches NVIDIA's secrets or GPU runners. A gate and a gap, on purpose.

The strongest idea in the CI answers a question this corpus keeps asking

run_tests.py gives each of 86 discovered projects its own exactly-synced environment — uv sync --all-extras, "exact by default … removes extraneous packages" — then runs pytest inside it. For a project whose central claim is framework-agnosticism, the dependency isolation is the test of the abstraction, enforced by the runner rather than by discipline. The CrewAI adapter's tests cannot pass because LangChain happened to be installed.

And tests.sh independently implements the vault's own rule D41 correctly: set +e, run the command, capture $? on the very next line, exit with it. The set +e is not a bypass — it is what lets the real status survive.

05Pattern outcome — no mint

Counts unchanged: 46 top-level patterns / 12 confirmed Library-vocab · §C-1 12 · §C-2 38. Declined on four independent grounds, with inflation_check held and §28 doing none of the work.

  • Not world-first. Two prior-art lenses returned "partially" and "no". LangChain, LlamaIndex, Haystack, AutoGen, Semantic Kernel, Griptape and Dify all predate 2025-03-14, and the observability layer is Arize / Langfuse / LangSmith / Weave territory — several of which this toolkit integrates rather than replaces.
  • The corpus already ruled on the shape. v222: world-canonical is not world-first. v227 and v236: a form factor within a genre is not a new primitive.
  • Scale is not a class. The unusual thing is breadth, not a primitive.
  • The novel parts are components, not the product. The versioned consent record and the isolated-environment runner are the two ideas worth reusing, and neither is a capability the toolkit delivers to a user — v242's D25 applied to a component.

Closest collision, checked by hand: C29, the Agent Protocol Inspector (claude-tap, v173). It loses on the layer — claude-tap intercepts the HTTPS traffic; NeMo Relay wraps the process and emits lifecycle events. Different mechanism, different object.

Recorded for the next audit, not self-executed

NVIDIA/NeMo-Relay is arguably the more novel artifact — "visibility into and control over agent runs without requiring changes to the existing agent stack." A harness-agnostic middleware that wraps a third-party coding agent from outside. It is a separate repository, so it is a separate subject; a mint decision belongs to a ship that reads it.

06Method — the refuters fabricated five refutations

Every adversarial reviewer was told to "default to refuted when you cannot independently reproduce a claim." That instruction is what makes an adversary useful. It also converted broken environments into five confident false negatives, each with an evidence string indistinguishable from a real one.

New rule D51

An agent told to default to "refuted" cannot distinguish "this claim is false" from "my command returned nothing." A refuter's negative needs the same extent-of-search discipline as an assessor's, and the orchestrator must re-run it — because a refuter's failure mode is textually identical to its success mode.

And the sharper half: the same run was excellent on the other side of the line, catching a citation to type_registry.py:1546 in a 1,448-line file and an inflated "150+ exports" against an __all__ of 94. A refuter is reliable when refuting requires it to find something, and unreliable when refuting requires it to fail to find something. v241's D21 was a verifier confirming a wrong framing; this is the mirror image, from the same root cause — the verifier's output is a claim, not a check.

Error ledger — two, both mine, both caught pre-publication. An atif collision grep that lit up six vault files, every hit the substring inside RATIFIED — the fourth consecutive ship with this trap. And framing nvidia_nat_redis as "the package without tests" when it has no code: three files, a deprecation stub. Both the same shape — reporting the shape of a measurement without opening what it measured.

07The pilot ladder

Rung 0 · 30 min

Read five files, install nothing

consent.py whole · config-relay.yml · register.py:130-132 · documentation_checks.sh:19-21 · loader.py:138. Then run grep -rn "backwards compatib\|legacy\|kept for" against your own repositories: every hit is a claim about code that may no longer exist.

Rung 1 · 30 min

The asymmetric consent rule, into the ratified ADR

The candidate-LLM legibility ADR has a version and nothing that invalidates a stale consent. Stamp a disclosure_version; on mismatch a stored refusal stands and a stored agreement expires. Under Art. 50(4) — deployer duties, which are yours — that is not a nicety.

Rung 2 · 45 min

The split rule for evals/METHOD.md

A held-out split is a precondition of the optimizer, not a property of the harness. Anything that selects a prompt, threshold or config by score must be scored on data it did not select against. The counter-example is already in the corpus: v178 SkillOpt, whose defining feature is held-out gates that reject non-improving edits.

Rung 3 · 45 min

Audit your own exemptions

They wrote down where they were not aiming the linter, gave a defensible reason, and the drift appeared in the gap. So: list every grep -v, every excluded path, every clause that warns instead of failing. Write the justification beside each. Then look for drift inside each one — starting with 05 Skills/.

Never

Five things not to do

Do not put the MCP server in front of candidate data — no approval gate, no read-only mode, extent verified. Do not use nat optimize to tune anything a candidate could contest. Do not trust ChatResponse.usage. Do not expect Claude's reasoning blocks to survive the LangChain ReAct path — base.py:48-57 discards them. Do not read the GitHub releases page for dates; it returns 2024 for 2026.
