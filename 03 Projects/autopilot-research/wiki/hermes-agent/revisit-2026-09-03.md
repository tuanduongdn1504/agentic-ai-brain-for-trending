## Why a revisit at all

The operator submitted one Vietnamese video — `k8lz9P3MrlM`, holetex, *"Hermes Agent: Cài Trợ Lý AI Cá Nhân Từ Số 0 (Không Cần Biết Code)"* — and asked whether the queue was free. It was. But the topic **already existed**, and the anchor was the same language, genre and framing as the *prior* bundle's anchor (a VN no-code "A-Z" tutorial). So instead of a new topic, this became a **replication test**: do the four claims the corpus graded FALSE belong to one creator, or to the whole genre?

The operator then elected the **widest** of three offered scopes — a full 6-source re-drain — over the recommended anchor-only revisit, accepting a stated overlap risk. **That risk did not materialise: 0 of 6 videos overlap the prior bundle** (1 creator overlap, different episode). The wide scope is what made the replication test possible at N=6 instead of N=1.

## ⚠️ The Ollama Cloud trap — the most operator-relevant finding

Two sources independently present Ollama as the route to **local, private** inference. Both are wrong, and the error runs in the direction that matters:

> The documented Ollama integration is **"Ollama Cloud"** — a **cloud-hosted service requiring an API key**, default endpoint `https://ollama.com/v1`. A base-URL override could in principle point at a local Ollama, but that use is **not documented as supported**.

So the most-recommended "keep it local and private" path in this bundle **ships your data to a third party by default**, and the local variant is an undocumented configuration. This lands directly on the topic's standing deployment blocker — **data residency and subagent isolation remain undocumented** ([[caveats-and-corrections]]) — and it sharpens it: the *appearance* of a local path makes the residency risk easier to walk into. For anything touching candidate PII under the hireui candidate-LLM legibility ADR, this is a hard stop until someone verifies the endpoint by inspection rather than by tutorial.

## Verification-process failures (10)

Recorded per Rule 12. **Six of the ten are agents asserting things that were not true** — and one of those reached the wiki before I caught it.

1. **My claim cap was skewed, not random.** `CAP=34` sorted on a boolean (`load_bearing`), so ties fell to insertion order and coverage was decided by which gatherers finished first. Result: **100% of t5-tina-huang (largest reach) and 100% of t3-tonbi excluded, and 8 of the operator's 9 anchor claims excluded.** Caught by self-audit; fixed with a second 133-agent run. **The excluded sources turned out to be among the least accurate** — the skew was actively hiding the worst material.
2. **Worst-verdict-wins scoring inflated MISLEADING by ~46%.** The first run reported 19 MISLEADING of 34 (56%); by majority rule the same panels give 13. **9 of the 19 rested on a single lens.** Cause: the framing lens's *modal* verdict is MISLEADING (18 of 34 on its own), so a most-severe-wins rule promotes one instrument's bias to the verdict. Fixed by re-scoring to majority and re-calibrating the framing lens in run 2. **Only 11 of 34 first-run panels were unanimous.**
3. 🔴 **The docs grounder fabricated a platform enumeration** — 20 named platforms including Matrix, Mattermost, DingTalk, Feishu, WeCom, Weixin, QQ Bot, Yuanbao, BlueBubbles, Teams and Google Chat, attributed to the README. **The README contains none of them and no "N platforms" string at all.** It also attributed "60+ built-in tools" to a docs page it *simultaneously listed under its own failures as unreadable*. **I propagated this into `channels-providers-deployment.md` before re-checking the README myself and reverting it.** The corpus' standing rule — verify collisions and counts yourself — was violated and then enforced.
4. **Completeness critic confabulated a 4-source pattern**: "four sources agree Hermes launched in February 2026", naming t6, t5, tonbi and t1. `grep -in "februar"` across all six transcripts returns **exactly one hit** (t6). It had conflated "launched in 2026" with "launched in February 2026".
5. **Same critic confabulated a 3-source pattern** on "71 skills" (t6, t2, t1). `grep` returns **exactly one** — t4, reading a number off the Desktop *Skills and Tools* panel on camera.
6. **Drift-audit critic performed circular verification**: it "confirmed" Desktop's minimum OS versions (macOS 12+, Windows 10-11) by reading **the prior wiki**, which is not a primary source. `apps/desktop/README.md` names three platforms with no version floors. A wiki cannot be evidence for itself.
7. **The desktop grounder asserted a code path that 404s** — `apps/desktop/src/plugins/hermes-bots/`. It was quoting an *archived* repo's claim about where its code was going. `apps/desktop/` itself is real (HTTP 200).
8. **A gatherer mis-cited a timestamp** — F4 at VN [01:23]; the actual quote is at [00:55] in both language tracks. Minor, but the headline finding rests on that quote, so it was re-verified by hand.
9. ⚠️ **GitHub API rate limit exhausted mid-run.** Unauthenticated limit is **60 requests/hour**; it reached **0 remaining**, while 248 agents had been instructed to `curl api.github.com`. Verdicts late in each run may rest on the supplied digest rather than a fresh check, and **a rate-limit UNVERIFIED is indistinguishable from a genuine one.** `raw.githubusercontent.com` has separate, far higher limits and should carry file reads.
10. **One agent hard-failed** (`StructuredOutput` retry cap, 5 attempts) — that claim was adjudicated on 2 lenses instead of 3.

⚠️ **Token budget breached, loudly (Rule 6).** Nominal caps are 4,000/task and 30,000/session. Actual: **16.42M subagent tokens across 248 agents** (7.52M + 8.90M), plus main-loop. The caps have been obsolete for this project since at least the v0.18 build (1.83M, 44 agents); they are stated here as breached rather than silently ignored.

## Deepen candidates

- ⭐⭐⭐ **Clone the repo and settle the file-level questions by inspection** — memory filenames, the real built-in skill/tool counts, whether `apps/desktop` bundles Bot Mode, and whether the Ollama endpoint can be pointed at localhost. Six of this drain's UNVERIFIED verdicts collapse the moment someone runs `git clone`. **Every remaining ambiguity in this topic is document-shaped, and the document is a clone away.**
- ⭐⭐⭐ **Use `raw.githubusercontent.com` (and/or an authenticated token) for all fan-out verification.** The 60/hour unauthenticated API ceiling is a hard structural limit on any workflow above ~20 agents, and it fails *silently* into UNVERIFIED.
- ⭐⭐ **Adopt majority-with-severity-tiebreak as the corpus default panel rule**, and record per-lens verdicts. Worst-wins overstated this ship's MISLEADING count by 46%.
- ⭐⭐ **Rank-then-cap must sort on a total order.** A boolean sort key silently delegates coverage to completion order. If a cap is unavoidable, stratify by source so no source can reach zero.
- ⭐⭐ **Re-drain a topic on a deliberately different query to find what the first query structurally could not see.** That is exactly how [[hermes-desktop]] surfaced — three Desktop sources appeared under an *install*-shaped query where the prior *comparison*-shaped query had produced none.
- ⭐ **A browser-capable fetch path** for JS-rendered first-party sites (Nous Portal, the docs site). Three of this drain's unresolved items are blocked on exactly this, and `curl` cannot fix it.
- ⭐ Read the **v0.19.0 / v0.20.0 / v0.21.0 release notes in full** — this drain read only their summaries, and "Security & Reliability" sections were spotted but not mined.
- ⭐ The high-reach sources the rubric dropped, listed in `_sources.md` — especially Tonbi's *"Better than OpenClaw? Testing Hermes Agent w/ Qwen 3"* (18,072 views), the pool's only **critical-comparison** stance, a stance this bundle has **zero** of.
