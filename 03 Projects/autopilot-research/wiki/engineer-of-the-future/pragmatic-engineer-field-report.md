# The Pragmatic Engineer's Field Report — What Actually Changed in December 2025

> **Source:** Gergely Orosz (author of *The Software Engineer's Guidebook*; writes **The Pragmatic Engineer** newsletter; ex-Uber/Skyscanner/Microsoft-Skype/JP Morgan), "Software Engineering + AI = ?", **Sonar Summit 2026** (`ubrfeaLEVVA`).

## FUD in both directions

- **Hype:** Zuckerberg — "AI will replace mid-level engineers soon" (Joe Rogan, Jan 2025, confirmed); *Wired* framing vibe coding as coming for jobs (Will Knight, June 2025); a VC declaring a threshold crossed.
- **Anti-hype reality:** an agent adding excess observability cost a small company a few thousand dollars; a security tool wrongly flagged the last-4-of-a-credit-card as PII (CTO killed the tool); founders reverting AI because output got "harder to review."

## The company-by-company tour (office visits, Oct 2025)

- **Cursor** — ~40–50% of Cursor's code written by Cursor; Linear tickets auto-one-shotted; agents ≫ tabs internally.
- **OpenAI** — unlimited ChatGPT/Codex; parallel Codex agents the norm; a "fix-it" button one-shots a PR. **>90% of the Codex app is generated by Codex**; a typical Codex engineer runs **4–8 parallel agents** (head of Codex = **Thibault "Tibo" Sottiaux**). "AGI is a *when*, not an *if*" culture.
- **Anthropic** — a **research** company that "happens to produce the most-used dev tools"; wants people to "feel the raw model." **Claude Cowork was built in ~10 days, largely by Claude itself** (team of four).
  - ⚠️ **Correction:** Gergely attributes "stopped opening my IDE / Opus 4.5 wrote every line of ~200 PRs" to Boris Cherny (creator of Claude Code). That quote is actually **Hamel Husain's**; Cherny only *replied* "I feel this way most weeks." News outlets misattributed it to "the Claude Code creator." See [[engineer-of-the-future/caveats-and-corrections]].
- **Google** — everything custom (Cider / Cider-V IDE; "critique" code review; internal code search); a tool "Jetski" (Google's Antigravity variant on the monorepo); **prepping infra for ~10× the lines of code** into production.
- **Amazon** — Amazon Q Developer Pro; "Kiro" (spec-based); **MCP servers everywhere** (API-first → MCP trivial); Claude hosted internally; PR-FAQ writing.
- **Meta** — VS-fork; **"Trajectories"** surfaces the *prompt history* behind vibe-coded diffs in code review (a mild privacy flap; one engineer prompts in Polish so fewer colleagues can read it).
- **Traditional companies + independents** — surprisingly **higher daily AI-tool usage than big tech** (a central bank ahead of a tech-first company because "our mission is to understand these tools"). Independents: **Armin Ronacher** (creator of Flask; early Sentry engineer) now prefers being "an engineering lead to a virtual programmer intern"; **Simon Willison** (Django co-creator; coined "prompt injection") — "coding agents actually work now — run an LLM in a loop with compilers/tests/linters."

## The December-2025 "breakthrough"

- **Karpathy** Oct 2025: "the models are just not there… it's slop." **Feb 2026:** "programming is becoming unrecognizable… you're spinning up agents, giving tasks in English, reviewing their work in parallel."
- **Cause (per Willison):** **Opus 4.5 (Nov 24 2025) + GPT-5.2 (Dec 11 2025)** tipped an invisible capability line — agents crossed from toy to daily-useful.
- Others echoing the shift: **Adam Wathan** (Tailwind CSS), **DHH** (Ruby on Rails), a Google distinguished engineer, **Mitchell Hashimoto** (Ghostty; co-founder HashiCorp) — "I never want to hear that AI isn't faster ever again."

## The open questions

- Are token-burning devs actually more productive? (A head of eng: "no real difference.") Willison: **it takes a surprisingly long time to get good at these tools**, and "if you start with a theory of how LLMs work, it'll hold you back."
- Will code review / pull requests survive? **Peter Steinberger** (creator of **OpenClaw**; **joined OpenAI Feb 2026**): "I don't like pull requests anymore… I prefer **prompt requests** — share the prompt, I'll run it and merge if it's good."
- **Kent Beck** (~50 years in computing): comparable to microprocessors→mainframe, the internet, the iPhone — "but faster"; what's cheap vs expensive has flipped. **Martin Fowler** (Thoughtworks; *Refactoring*): won't wipe out software dev, but a change like **assembly → high-level languages.**

## The conclusion

- LLMs will write most code, but **experienced engineers do the prompting/guiding/controlling.** Cursor research (**Suproteem Sarkar, University of Chicago** — *not* "Eric"): **senior engineers are more effective with agents; agents *amplify* existing output, they don't replace it** (~39% more PRs merged, no rise in reverts).
- You'll need **much more verification** than you can do by hand → tools like **Sonar/SonarQube** — the same verification-gap Osmani cites (see [[engineer-of-the-future/osmani-answerability-thesis]]).
- **Less valuable skills:** language/framework-specific depth, implementing well-defined tickets, rigid adherence to old best practices. **More valuable:** curiosity/experimentation, business interest, **strong fundamentals** (to guide agents + know when *not* to hand over the wheel).

## Key Takeaways

- A real **December-2025 breakthrough** (Opus 4.5 + GPT-5.2) flipped coding agents from "slop" to daily-useful across the whole industry.
- **Verified internal stats** corroborate Cursor's talk: Codex >90% self-generated, 4–8 parallel agents; Anthropic Cowork built ~10 days by Claude.
- **Senior engineers are amplified, not replaced** (UChicago/Cursor research); verification becomes the constraint → verification tooling required.
- Emerging practice: **"prompt requests" over pull requests**; **fundamentals + judgment** are the durable skills.
- ⚠️ The "stopped opening my IDE" quote is **Hamel Husain's, not Boris Cherny's** — a misattribution corrected here.
