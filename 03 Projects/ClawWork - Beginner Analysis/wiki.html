ClawWork

An AI agent starts with ten dollars, is handed a real professional job, and is billed for every token it thinks with. Earn enough and it keeps working. Hit zero and it is bankrupt.

HKUDS/ClawWork Data Intelligence Lab @ HKU MIT · Python GOAL-ALIGNED 3/4 1 new §C standalone, N=1

The mechanism

Cost moved inside the objective

In nearly every agent benchmark the cost of thinking is somebody else's problem — a lab pays the API bill and the score ignores it. ClawWork inverts that. The same balance that receives an agent's wages also pays for its inference, so an agent that reasons beautifully but expensively simply runs out of money.

Each simulated day the agent is dealt one real professional task from OpenAI's GDPval dataset and chooses between two moves: work for income now, or learn to improve later. Submitted work is graded by an LLM judge against occupation-specific rubrics and paid at quality × estimated_hours × BLS_wage — but only if quality clears 0.6. Below that, nothing.

The finding

The cost axis does not hold

ClawWork's entire pitch is cost efficiency. So the pricing code is where to look — and it prices every model identically:

input_token_price = 2.5 · output_token_price = 10.0 — per million tokens, with no model-specific price table.

Unless an OpenRouter response happens to return a pre-computed cost, every model on the board is billed at the same rate. The published Cost column therefore measures token volume far more than it measures money — and because the runs mix direct and OpenRouter configs, it is not even internally consistent. The headline claim rests on the weakest part of the implementation.

Landscape

Not the first to do this

Andon Labs' Vending-Bench established the form — an agent runs a business for a simulated year, scored on its final bank balance — and Vending-Bench 2 is already cited inside this corpus, in the GLM-5 entry. Anthropic's Project Vend put Claude in charge of a real vending shop in its own office. GDPval is OpenAI's dataset, not ClawWork's.

What belongs to ClawWork is the combination: genuine professional deliverables rather than a retail sim, an agent that pays for its own inference, an explicit invest-or-earn choice, bankruptcy as terminal failure, and a wrapper that applies the same accounting to a live chat agent across nine channels.

Assessment

What survives scrutiny

Real

  • An 876-line ledger with per-channel cost records and three JSONL stores.
  • A 829-line evaluator: per-occupation rubrics, a hard payment threshold, 2 MB artifact caps, and an explicit refusal to fall back to heuristics.
  • MCP as the internal tool bus; LangGraph orchestration; sandboxed code execution.
  • A real published dataset underneath — OpenAI's 220-task GDPval gold subset.

Not

  • Roughly 37–40 commits, all between 16 Feb and 3 Mar 2026 — quiet for about five and a half months since.
  • A flat token price applied to every model.
  • README says the judge is GPT-5.2; the code default is gpt-4o.
  • README says "44 sectors"; GDPval is 44 occupations across 9 sectors.
  • trading/ contains a single empty __init__.py.

Corpus

A prediction from v38, confirmed

HKUDS is not a new name here. DeepTutor was wiki v38, and that entry sketched a vertical-stack hypothesis for the lab: engine (nanobot) → infrastructure (LightRAG) → apps. ClawWork lands precisely on the predicted app layer — a same-lab benchmark built on the same-lab engine. The vault's own earlier reading, validated by a later independent ship.

One correction worth recording. An automated summariser asserted during this build that ClawMode wraps "nanobot, Anthropic's agent framework." That is false. nanobot is HKUDS's own framework — inspired by OpenClaw, reimplementing most of it in roughly 4,000 lines against OpenClaw's ~430,000. Left standing, that single sentence would have flipped criterion (a).

OpenClaw itself is Peter Steinberger's, and Steinberger already authored a corpus subject — CodexBar, v159. So the repo's title invokes a framework built by a prior subject's author, while the shipped integration path targets the lab's own clone of it.

What to do with it

Two ideas, no installation

This is a read-and-borrow subject. There is no component here to adopt, and running it costs real money to watch a simulation you can understand faster by reading it.

  • Take the eval gate. File-backed rubric, hard pass threshold, artifact must exist, and a flat refusal to degrade to heuristics — that is a shippable shape for gating any LLM feature, and it is what the vault's ratified candidate-LLM legibility policy already demands.
  • Take the inversion. Give every LLM feature a cost ledger and a value threshold it has to beat. Then price per model — the mistake here is as instructive as the idea.

And the fence. The structure — classify a task into an occupation, estimate hours, apply a wage, have a model grade the output, pay proportionally — must never be pointed at people. Borrow it for grading an AI's own work; not for scoring a candidate.
