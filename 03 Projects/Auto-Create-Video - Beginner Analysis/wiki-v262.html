A correction I owe the record

The operator queued this as the sixth mranex repository, and I said in my own previous message that it would take the same-author control to N=6. That was wrong, and one command settles it.

$ git log --all --format='%an <%ae>' | sort | uniq -c

All thirty-four commits are by Ho Quang Hai. Zero by mranex. The rendered GitHub page confirms it — "forked from hoquanghai/Auto-Create-Video", one star, no description. The subject of this page is the upstream, and the credit is his.

New rule

A repository's namespace is not a claim about its authorship. Before attributing a repository to the account hosting it, run git log --format='%an <%ae>' | sort -u and check the page for a fork notice. Forks, transfers and org membership all put other people's work under a given name.

I nearly skipped that command because five URLs in a row had been genuine. It is one line, and it inverted the ship.

This paragraph originally claimed he forked this repository and then created four more projects with no tests — "the example was in his own account the entire time." The dates do not support that. A fork's clone holds upstream history only up to the fork moment, so this HEAD's date (2026-05-02) is a lower bound on the fork, not the fork date. D50: a fork's clone gives you a lower bound on the fork date, never the fork date.

What survives: the repository is in his account, it has real tests and CI, and his own five projects have none. The contrast needs no timeline. What does not: that the example preceded his later work — and the next ship found a second fork in the same account whose HEAD is 2026-06-24, necessarily after all five of his projects.

The rule, stated fairly

The previous ship established that code moves forward in time and never backward — an improvement reaches project N+1 by copy-forward and never reaches N−1, because nothing carries it back. This extends it sideways: it does not even move forward from a repository you own.

But forking is not a commitment to adopt — people fork to read, to bookmark, to try once. So this is not a character finding. The honest claim is structural: a practice does not transfer by proximity. Having the example in your account, in your language, in your domain, in the same month, is not having the habit. Practices transfer by doing, not by possessing.

And that closes the arc. The previous ship's lesson was that a protocol without a gate is decorative — nine excellent sections, not one of them a precondition, zero evidence records ever written. This one's is that an example without practice is inert. Together: declaration is not enforcement, and possession is not practice. Those two sentences are the entire failure mode of the preceding five repositories.

The defect, and it is a remarkable callback

package.json
"test": "vitest run --passWithNoTests"

That flag makes the command exit zero when no tests are collected — and test.yml runs exactly npm test. Move a directory, rename a suffix, edit the vitest config, and the Tests badge stays green on an empty suite, on every push, silently.

The callback: at v261 the fleet's synthesis asserted that pytest against nonexistent paths "will run zero tests and exit 0." I rejected that as contrary to pytest's documented exit codes, and I was right about pytest. But the mechanism it described is real — and it is here, opted into deliberately, in the one repository of the six that actually has tests.

And this one is worse

A gate that cannot fail is worse than a gate nobody invokes. The previous ship's verification command fails loudly and was therefore never run by anyone. This one cannot fail loudly and runs constantly.

If you take the workflows, drop the flag. If you need it, assert the collected-test count against a floor instead.

The finding

Everything the code can check is right. Everything only the prose asserts is inflated. The test count, the frame dimensions, the dependency versions and the SFX tiers are correct to the digit. The template count is doubled, the theme system does not exist, and a whole rendering stage is advertised with no code behind it.

He built real gates and aimed every one of them at the code. The prose has no gate, so the prose is where the drift lives — and a hand-reconciliation performed once, even one explicitly titled "to match current codebase", did not converge. A gate's aim, not its quality, decides what rots.

Which sharpens the whole six-ship conclusion: the five repositories before this one had no gates anywhere, and both their code and their docs drifted. This one has gates on the code, and its claims are honest precisely where something checks them. Tests do not make you honest. They make you honest about the things they test.

Verdict

Goal-aligned 3/4, cleanly. A Claude Code skill is the recommended entry point, Claude is the content engine, and the AI-versus-deterministic boundary is exactly the question hireui's first LLM feature has to answer. Read and borrow — and this is the first subject in six whose engineering practice is worth copying rather than just cautioning against.

What to take, in one sentence: put the model where judgement is required and deterministic code everywhere the output must be reproducible — then write the boundary down, in the code, not just in your head. For hireui that means the model may summarise, explain and draft; it may never do the arithmetic a candidate could contest. Plus two patterns worth stealing outright: negative fixtures as first-class test data (three files that exist to be rejected), and mocked HTTP for provider tests, which is what makes an eval gate affordable rather than theoretical.

Hand-verified throughout, with a thirteen-agent fleet used for breadth on claims, determinism, code quality, tests, the skill and the pipeline — each assessment followed by an adversarial review aimed at its own citations and numbers.
