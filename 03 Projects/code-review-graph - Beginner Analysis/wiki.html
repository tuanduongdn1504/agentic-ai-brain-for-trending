01 The problem it solves

An AI reviewer that reads files one-by-one burns huge token budgets and still misses cross-file impact. The bet: pre-compute the code's structure once into a graph, then answer an agent's review questions — “what breaks if I change this?”, “who calls this?”, “which tests cover it?” — by traversing the graph and returning only the relevant slice. That is the exact “token-reduction, 100% local, read-only graph via MCP” shape of Library-vocab #23.

Headline benchmark (README, primary source): ~82× median per-question token reduction (range 38×–528×) across 6 real repositories.

⚠️ The author's profile summary states a different metric — “6.8× average context compression across 23 languages” — an aggregate framing, not the per-question figure. README primary; both page-stated §37.4; neither grounds a #52 claim.

02 Architecture (source-verified from pyproject.toml v2.3.7 + README)

Parse → Graph → Watch → Serve. Tree-sitter (tree-sitter + tree-sitter-language-pack) → AST → an in-memory networkx graph (NOT SQLite — the variant vs codebase-memory-mcp v172) → watchdog re-parses only changed files (<2s) → a fastmcp-based MCP server (mcp+fastmcp) exposes 30 MCP tools so the agent queries the graph, not the files.

Blast-radius / impact analysis — the distinctive feature

When files change it traces callers, dependents, and affected tests. Benchmarked, and unusually honest about it:
