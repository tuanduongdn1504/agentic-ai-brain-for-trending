What it is

Your whole voice stack, running locally

Voicebox clones a voice from a few seconds of audio (or 50+ presets), speaks in 23 languages across 7 TTS engines (Qwen3-TTS, Qwen CustomVoice, LuxTTS, Chatterbox + Turbo, TADA/HumeAI, Kokoro), transcribes + dictates into any app via a global hotkey (local Whisper), composes multi-track “Stories,” and refines dictation with a bundled local Qwen3 LLM (0.6B / 1.7B / 4B). Privacy is the pitch: “models, voice data, and captures never leave your machine.”

The honest (c) caveat. The hard AI is all upstream — Qwen3-TTS (Alibaba), Whisper (OpenAI), Kokoro, Chatterbox, HumeAI/TADA, Qwen3. Voicebox is the substantial orchestration / desktop-UI / MCP-server layer over those models, not model research. The local LLM is Qwen3 — not Claude. Claude appears only as an MCP client.

The corpus-relevant core

A first-party MCP server for coding agents

Introduced in v0.5.0. This is why voicebox lands on-goal: its primary function is a human voice studio, but it exposes that studio to an agent — “any MCP-aware agent can call into your local Voicebox install” to speak in a voice you cloned.

⚠ The fence — “no consent lock”

Voicebox clones an arbitrary voice from a few seconds of audio with no consent gate and no ethics note in the README — a real impersonation / voice-fraud / deepfake surface (a #66 dual-use note).

hireui must never clone a candidate's or interviewer's voice. Recruitment is exactly where synthetic-voice misuse is most dangerous. If a voice feature is ever built: preset voices + explicit, logged consent only, behind the candidate-LLM-legibility ADR + a data-residency review. Local-first is a positive for the user's own data — keep it that way.
