01 — what it isA workbench, not a button

Ten stages, each writing its intermediate result to a per-stage JSON cache, each editable in the GUI before the next stage consumes it. The README's warning block opens by refusing the category it belongs to — "ĐÂY KHÔNG PHẢI LÀ MỘT CÔNG CỤ ĂN SẴN KHÔNG NÃO", this is not a brainless ready-made tool — and the design-philosophy section attacks one-click translators for deforming art and mangling speech bubbles.

The numbering below is not decoration. It is the actual pipeline, and the right-hand column is what the code marks stale when you hand-edit that stage.

  • 01Detection — layout and speech-bubble regions → marks 5 stages stale
  • 02OCR Prepare — normalise and crop the text regions
  • 03OCR — recognise source text on the crops → marks 4 stages stale
  • 04Translation Init — build the translation records
  • 05Translation — send to a provider, reconcile the response
  • 06Mask Prepare — build the text-removal mask
  • 07Inpaint — erase original text with LaMa-manga
  • 08Render Prepare — lay out the text objects
  • 09Render — typeset onto the cleaned page → marks 2 stages stale
  • 10Export — write the finished page

02 — the headlineThe second commit imported a different program, and the dependency file still describes it

Commit two landed five minutes and fifty-two seconds after Initial commit: 68 files, 8,675 insertions. They are not a manga library. They are a Flask web application — app.py, templates/index.html, static/js/app.js, .dockerignore, a trained model/model.pt, its training notebook, eight example pages, and .jules/bolt.md. The repository is not a fork, and no attribution file has ever existed in its history.

The web app was deleted in one commit on 18 May. That commit did not touch requirements.txt — whose entire history is six commits, all four days earlier or more.

measured · ten of twenty-four

Direct importers across all 152 Python files: Flask 0, flask-socketio 0, python-socketio 0, python-engineio 0, Werkzeug 0, gunicorn 0, tqdm 0, cryptography 0, sentencepiece 0, huggingface-hub 0. gunicorn's own PyPI classifiers list only MacOS and POSIX — a UNIX-only web server pinned into a project whose sole launcher is a Windows .bat file.

Deleting a program is not deleting its dependencies — and a dependency list is the last place anybody looks for dead code. The purge removed 100% of the web app's source and 0% of its install cost.

It is still being paid for in bandwidth, too. .git is 22 MB against a working tree whose largest asset class is 9.2 MB of fonts. The biggest blobs ever written are model/model.pt at 6.2 MB, eight example PNGs at about a megabyte each, and static/img/back.jpg — every one of them deleted, and every one of them in every clone forever.

04 — the good designA check that is declared, persisted, displayed, and deliberately not enforced

Three hand-written constants declare the blast radius of each kind of manual edit — and the mark is written into the cached artifact, in machine-readable form, naming the stages: 

mmt_core/detection_edit.py:29  DOWNSTREAM_STALE_STAGES = ["ocr","translation","inpaint","render","export"]
mmt_core/ocr_edit.py:23        DOWNSTREAM_STALE_STAGES = ["translation","inpaint","render","export"]
mmt_core/render_edit.py:29     DOWNSTREAM_STALE_STAGES = ["render","export"]

detection_edit.py:107          payload["downstream_stale"] = list(DOWNSTREAM_STALE_STAGES)

Not an mtime comparison. Not in-memory state. The GUI reads it and renders it as a warning. And then it stops: 36 mentions, five write sites, and zero enforcement — no stage runner gates on it, no raise, no abort. The README says so in its own troubleshooting section: the cause is that you edited an earlier stage and have not re-run the later ones; the fix is to remember to re-run them.

the synthesis of six ships

v250 called six rules "non-negotiable" and gated one. v252 headed a block "Automated, Zero Tolerance" and automated none. v247 committed a CI gate its own merge history violates 66 times out of 82. v254 built a weekly job and aimed it at the one decidable thing nobody doubted.

This subject has an unenforced check and claims nothing else. The label matches the mechanism, and the human it defers to is in the loop by design.

An unenforced check is a defect only when something claims it is enforced.

The real defect is a different one: the stage sequence is declared four or more times — three literal lists plus the GUI's panel ordering — with nothing reconciling them, and the three lists do not even share a convention. Two are strictly downstream; render_edit includes its own stage. Defensible on the merits, indistinguishable from a typo on the page.

05 — the payoffThe segment-alignment guard, at five layers

Send N regions to a model in one request and get a list back. If that list is shifted by one, or merged two entries, or dropped an empty one, every subsequent item is attributed to the wrong region — and nothing crashes. In manga you get a character speaking someone else's line. In a CV parser you get one candidate's employer attached to another's degree.

LayerWhereWhat it does
1indexed_textsevery item carries a stable index, not just text
2prompt_studio.py:31–36five prohibitions: preserve keys, count, order; do not merge, split, drop or invent; no commentary outside the structure
3gemini_translator.py:373the expected count is interpolated into the prompt itself
4openai_compatible_translator.py:355per-item index check, not just length — "item index mismatch at position N"
5deepseek_translator.py:450on mismatch, pad or truncate with the originals
why layer 3 is load-bearing

The reconciliation is a zip(), and Python's zip silently truncates to the shorter sequence. In context_memory.py the length check sits at line 91 and the zip at line 94 — three lines apart, for exactly that reason. Remove the guard and the misalignment becomes invisible.

Untranslated-but-aligned beats translated-but-shifted. That is the call most implementations get wrong, and it is a paragraph to copy, not an installation.

06 — the gapThe flagship feature is unreachable because a dataclass lacks a field

The README's OCR section leads with "Online LLM (Claude, GPT, Gemini)" — send the crop straight to a vision model — and recommends it in the document's most memorable line: "Giàu thì cứ Claude mà vã", roughly if you're rich, just go hard on Claude.

The authoritative registry has three entries: PaddleOCR-VL via llama.cpp, DeepSeek-OCR via llama.cpp, and Chrome Lens. Across all 54,977 lines, claude appears six times, all in one hardcoded model list — in the translator, not OCR.

unreachable by construction

The two llama.cpp clients already post an OpenAI-shaped chat/completions payload with an image_url data URI, so the wire format is right. But OCRConfig has no api_key field at all, and no code path sets an Authorization header. There is nowhere to put the credential.

This is a mismatch, not displacement. Nothing in the world moved: the feature was described and never built, and the description is the part users read.

08 — the testsOne real test, excluded by the project's own rules

No CI has ever existed — not one .yml file in any commit on any ref. There is exactly one test file, and three separate things make it incapable of producing a signal.

  1. It asserts exact string equality against four live third-party translation services.
  2. pytest is not in requirements.txt — the documented install cannot run it.
  3. .gitignore line 49 is test_*.py. git check-ignore --no-index confirms the rule would exclude it; it survives only because it was tracked by the same commit that added the ignore file.

That ignore rule is the project's real testing policy, written down: tests are local scratch, not repository content. Set against v255 — fourteen test files that ran green and asserted nothing — both deliver exactly zero signal, reached from opposite ends.

10 — the humanDitme GPT

On 17 May at 01:56 the author committed a 121-line file under a subject line that is Vietnamese profanity aimed at a language model. The file is a hallucination filter: DeepSeek-OCR is a document OCR model, so pointed at a speech bubble it sometimes returns document structure instead of dialogue. 

STRUCTURED_TAG_MARKERS = ("<table","</table","<thead","<tbody","<tr","<td",
                          "<svg","<path","<math","<figure","<chart")

class OCRTextFilterResult:  text: str;  rejected: bool;  reason: str = ""
# reasons: empty_ocr_output · structured_json_non_text · structured_markup_non_text
#          coordinate_geometry_non_text · structured_hallucination_non_text

A naive pipeline would have typeset a plausible HTML table into a speech bubble and shipped it. This converts a confident wrong answer into a loud, named rejection carrying its cause — and it is scoped honestly, returning unmodified text for every provider except the one whose failure mode it was written against.

fourth null · and the most instructive

The corpus's silent detector — grep -rni "silent" — returns zero here, as do the Vietnamese equivalents. But the doctrine it looks for is unmistakably present in this file. v255 narrowed the detector's domain to artifacts whose authors wrote down their reasoning about failure; this author did exactly that, in five reason-strings and a commit-message obscenity, and the grep still finds nothing.

The detector finds an English word, not a discipline. Grep the reason-strings instead — rejected, reason=, _non_text — which found this file instantly.

the fourth row is the sharpest — and I missed it

detectors/matching.py defines six functions and that is not one of them. The symbol now appears exactly twice in the whole repository, both times inside the file that cannot resolve it. So the module is unimportable — and the failure is latent, because nothing imports it. A critic pass found it; I verified it before accepting it.

This is what "no CI, ever" costs, in one line. A 152-module Python project with a module that has been unimportable since 17 May, and nothing in the world would tell you: no CI, no test that imports the package, no linter. One python -c "import detectors.comic_text_detector" would have caught it the day it was made. The file is not merely dead — it is broken, and the brokenness is invisible precisely because the deadness is total.

Each still looks authoritative. A dependency list looks like a statement of what the program needs. A "class-level cache for heavy models" comment looks like a design note. A committed .bat looks like how you start the server. All three are fossils, and none of them says so.

the counter-example, in the same repository

downstream_stale carries its own context: the mark is written into the very artifact it invalidates, it names the invalidated stages in machine-readable form rather than implying them, the GUI states it to the person who must act, and the README declares that acting is the human's job. Nothing about it depends on knowledge that lives somewhere else.

An artifact is safe when it carries its own context, and dangerous when its context lived somewhere else and has since gone.

That names what "declared" actually buys you — and it identifies the failure mode that is worse than staleness. A deleted rationale leaves an artifact that is currently correct and unmaintainable, because staleness can be detected by comparison and absence cannot be detected at all.

The uncomfortable part is that the vault has the same defect. Running the inventory script written at the previous ship returned one failure: five state files present on disk and named nowhere in the index — artifacts whose reason for existing lived only in the session that wrote them. Same shape as requirements.txt, found in under a second, because a machine was finally asked to look.
