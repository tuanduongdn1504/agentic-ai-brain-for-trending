The finding

third consecutive ship in one dependency graph — and the corpus's first lateral recursion

package.json declares 17 peer dependencies, the @deepseek-ai/* set pinned at ^0.1.0-rc.6 — the same release-candidate pin v236 dsh-TUI carried, one prerelease ahead of the rc.5 recorded at v235. That is a lockfile edge, not a README citation.

But the shape is new. Every prior corpus recursion ran vertically: a port (v207 → v208), credited priority (v231 → v232), runs-inside (v235 → v236). Here, v236 and v237 are unrelated sibling plugins in the same host, with no dependency on each other — two strangers extending one kernel from opposite directions within four days.

What this proves about v235

v235's headline claim was "Everything is a Plugin." v236 showed a stranger could replace the UI seam. v237 goes further: a plugin can publish its own service on the host context and become an extension host in turn. That is the claim actually cashing out — the kernel is re-entrant, not merely swappable.

What it is

explorer · editor · terminal · git · browser · sub-agent topology — session-isolated

A right sidebar plus bottom panel: a lazy-loaded file tree with CodeMirror editing and inline preview (images, Markdown with Mermaid, HTML, PDF, Office), a real terminal (xterm.js + node-pty, not an emulation), a Git panel with staging and diffs, a sandboxed multi-tab embedded browser, and a sub-agent topology view. Everything is scoped per conversation session. The core is ~325 KB at startup; terminal, editor and Mermaid load on demand.

Its built-in tabs are registered through the same public API third parties use — the order values below are real, and are what the section rail on this page is numbered by.

The extension API

the reason to read this repo even though you should not install it

A consuming plugin registers a tab in five lines. The host is an optional peer dependency, so this code is inert — not broken — when better-sidebar is absent:

export const inject = ['betterSidebar']

export function apply(ctx: Context): void {
  ctx.effect(() =>                       // disposer runs on HMR / unload
    ctx.betterSidebar.registerTab({
      id: 'my-plugin:db',             // namespaced
      title: 'Database',
      order: 50,
      component: ({ scope }) => <DbView sessionId={scope.sessionId} />,
    })
  )
}

Seven decisions worth stealing

  • Dogfooded API, no privileged path. The built-in tabs and viewers register through the same public API as third parties — 吃自己的狗粮, "eating our own dog food." Built-in ids are simply non-overridable; a duplicate registration throws.
  • Graceful absence. Declared as an optional peer dependency, so ctx.betterSidebar is undefined when it isn't installed and consumer registration silently skips.
  • Capability gates, not version sniffing. features: readonly string[] advertises badge, tabLifecycle, updateTab, pluginSettings, urlTarget… Consumers ask can you do X, not are you new enough.
  • Disposal is mandatory. Registration must be wrapped in ctx.effect() so the Cordis fiber unregisters on hot reload or unload.
  • Type-only across bundle boundaries. import type {} merges the context augmentation and is erased at build; a build-purity gate blocks value-imports from other plugin namespaces, and cross-plugin require() is blocked by the loader.
  • Orphan degradation. A persisted tab whose plugin has gone renders as a labelled placeholder — "plugin not loaded", plus a close button — and auto-restores when the plugin returns, instead of corrupting layout state.
  • Settings are part of the contract. A registered tab declares toggles (host prefs), pluginToggles (plugin-local, persisted under pluginSettings[id]) or a custom panel — so extensions get first-class settings UI without touching host code.

Boundary & CI

the fourth consecutive ship handing the vault machinery for its own invariants

AGENTS.md states the rule in the imperative: 禁止修改 DeepSeek Harness 源码 — zero writes to the DSH checkout, no harness-package modification, no commits to official branches. Mounting happens only through cordis.patch.yml, which does exactly one thing: inserts a plugin row into the host's bundle stack at profile boot. No host core file is touched.

Stronger than v236's gate

v236 mechanised non-invasiveness with static checks. v237's plugin-mount job is an integration contract test: pnpm build && pnpm pack && pnpm test:mount packs the tarball, mounts it into a real DSH instance on a scratch profile, and renders it headlessly under Playwright Chromium — asserting the root mounts, no error bars, no page or plugin console errors, panel expansion works, and that the terminal and editor lazy chunks actually load.

The pattern across four ships in a row: v234 gave the vault staleness tracking; v235 doc-verification gates; v236 CI boundary gates; v237 build-the-real-artifact-and-mount-it. All four point at the same deferred backlog — the C22–C27 stale rows and the retire pass the corpus keeps postponing.

Why (b) is MODERATE, source-verified not inferred

dsh.plugin.json declares contributes: { tools: [], skills: [] } — both arrays empty. Despite being a large, well-engineered plugin it contributes no agent tools and no agent skills. The agent gains nothing; the human gains panels. That single line is what holds the tier below STRONG, and it converts "adds no agent capability" from a judgement into a fact.

The v216 discriminator, applied a third time: Codex-Dream-Skin v216 was rated OFF-GOAL because it was CSS wallpaper with zero functional surface. This implements terminal, git, filesystem, editor, browser and sub-agent-monitoring surfaces behind a public API with a CI mount gate — MODERATE, not FAIL.

Pattern outcome: no mint

v236 recorded a deferred watch axis — "sanctioned in-process UI-seam replacement via a host agent's own plugin kernel." v237 is a second instance, but the axis needs generalising: v236 replaced the front door; v237 adds a panel and negotiates for the slot rather than seizing it. Generalised to "sanctioned in-process UI-layer plugin on a host agent's own extension kernel" → N=2, recorded and not self-promoted. A promotion is an audit act.

The §C mint alternative — recorded, and declined

"Second-Order Extension Host — a third-party plugin that re-exposes its own public, capability-gated extension API so further third-party plugins extend the plugin rather than the host." Genuinely distinct on mechanism, and corpus-first by grep. It still loses:

  1. §C vocabulary is agent-capability-shaped. Second-order extensibility is a software-architecture property — and contributes is empty.
  2. Emphatically not world-first. VS Code extensions have exported APIs to other extensions for roughly a decade; Eclipse extension points predate that; Backstage, Obsidian and Figma all do it.
  3. §28 anti-inflation. "Plugin that hosts plugins" is first only because the circle is drawn there.
  4. The precedent chain runs five deep — lobehub v222, hermes-webui v227, Codex-Dream-Skin v216, dsh-TUI v236, now this.
  5. Weak anchor. One plugin in a two-week-old ecosystem, among rival right-panels, from an org shipping 106 repos.

Recorded instead as a second deferred watch axis — "plugin-as-platform" — and flagged to the badly overdue audit.

Supply chain

genuinely two-sided, and worth stating both ways

Positive — the publish-side exemplar

npm Trusted Publishing via OIDC: pnpm publish --provenance --access public, with no NPM_TOKEN secret in the repo, provider/org/repo/workflow pinned at npmjs.com, and the git tag required to match package.json exactly. Together with the zero-source-write rule, the build-purity gate and the real-host mount test, this is the publish-side complement to pi v228's consume-side hardening playbook — the corpus's two strongest supply-chain positives now cover both directions.

The sandbox model is also considered rather than absent: embedded content runs in opaque-origin sandboxed iframes with CSP, sandbox status is shown in the UI, and unlocking is deliberate and temporary.

Negative — why you still should not install it

  • A prepare lifecycle script, and node-pty — a native module that compiles at install.
  • Sandbox-escape settings exist at all (browserNoSandbox, htmlViewerNoSandbox, htmlViewerDefaultUnsafe) inside a panel that also holds a real shell and an embedded browser. Disclosed and default-safe, but one toggle away.
  • 17 peer dependencies pinned to a release candidate of a host still labelled a developer preview with breaking changes promised.
  • A roughly two-week-old public plugin ecosystem with at least six competing, operator-undisclosed directory sites — one of which v236 already caught publishing the wrong licence for a different plugin.
  • Not source-cloned. Treat the tree as untrusted until inspected.

The project also volunteers its own gaps — no file watcher, no git push/pull/fetch, terminals remount when dragged between panes, unusable below a 768 px viewport. A clean instance of honest-deficiency disclosure.

Pilot

read-and-borrow · not a hireui component · do not install

Installing this means a plugin with a prepare script and a native build, against a release-candidate 17-package peer set, inside a two-week-old ecosystem — for a nicer file panel on an agent you do not run. The value is entirely in reading it.

One-thing path · A1 → B5 → B6

  • A1 — read docs/external-plugin-guide.md and AGENTS.md. Thirty minutes, zero install. You are reading it for the seven design decisions, not the sidebar.
  • B5 — lift the public-API rules into hireui's agent-nativity spec. Namespaced ids with non-overridable built-ins; a features[] list consumers query; optional-peer graceful absence; mandatory disposers; type-only imports across bundle boundaries; your own features using the public API; orphan degradation. Composes with palmier-pro v192's ToolExecutor template and geti v213's first-party skill-suite template.
  • B6 — steal both CI gates. Pack the artifact you actually publish, mount it into a real consumer, drive it headlessly before you tag. And publish with OIDC Trusted Publishing plus --provenance, holding no long-lived token.

Also worth taking: the build-purity gate as a mechanical way to enforce an architectural boundary code review keeps missing; the ~325 KB startup budget published as a contract rather than a hope; and — the one piece that touches product directly — the sandbox-with-visible-unlock model, for any untrusted candidate-supplied content hireui ever has to render.
