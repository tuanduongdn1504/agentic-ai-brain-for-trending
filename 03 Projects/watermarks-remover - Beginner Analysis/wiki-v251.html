01 — The headlineThree detectors, three closed loops

The project exists because Anthropic began watermarking Claude's output. It has now shipped three independent detection paths. Each one is valid only against a mark generated with the same key and config the tool itself controls. None can be pointed at the thing the tool exists to remove.

service/scripts/detect_text_watermark.py:8-10
It is an independent verification harness: detection is only valid against the SAME scheme config + keys used at generation. It cannot certify that a vendor detector will fail on the given text.
service/scripts/markdiffusion_harness.py:12-15
Detection is only valid against the same scheme config, model, and keys used at generation — it cannot certify that a vendor detector will fail on the given image.
service/scripts/detect_gumbel.py:21-25 — added the day after the original ship
detection is a same-key replay… A negative result establishes nothing: unwatermarked text, another provider's key, and human text all sit at chance. This detector is not a vendor oracle.
service/scripts/bench_synthid_text.py:20-22 — the benchmark's own header
Google retired SynthID text watermarking on its API in Aug 2026, so no vendor tier exists.

bench_synthid_text.py is 52,787 bytes of real measurement apparatus. It computes a clear rate, score deltas, lexical divergence, length ratio, numbers preserved, and clears per million tokens, and emits report.md, results.json and results.csv.

The gap

None of those files exist in the repository. benchmarks/ holds exactly eleven: one README, two shell scripts, eight 500-byte corpus texts. The instrument ships. No reading from it does.

Verified at the vendor, not the repo

Anthropic's own support page confirms two techniques — embedded text watermarks and signed C2PA file metadata — across API, Claude, Claude Code, Cowork and Tag, worldwide, for models launched on or after 2 August 2026. And on detection: “We'll share details on detection mechanisms in forthcoming technical documentation.”

The repository's central caveat is not modesty. The vendor confirms it.

03 — The lineEvery guard on the file is code. Every guard on the world is prose.

One grep over the entire Python surface, for the vocabulary of the project's own ethics document:

grep -rn "consent\|authoriz\|you own\|ethic\|fraud\|academic" --include=*.py .10 hits

All ten are _authorized() bearer-token checks in the two HTTP servers. Not one line implements “content you own.”

What is compiled is everything decidable from bytes: SSRF with IPv4-mapped IPv6 unwrapping and per-hop redirect revalidation, zip-bomb caps at 128 MiB checked per member and cumulatively, unknown-format and binary-as-text refusals, body and batch limits.

The ethics file is titled “Intended use”, not “Policy”, and closes by disclaiming liability for misuse. That is an admission of non-enforcement, and it is the right one — “do you own this content?” is not decidable from the artifact. The project compiles what can be compiled, leaves the rest as prose addressed to a person, and does not pretend the prose is a gate.

04 — The replicationWhat the first pass got right, and what it got wrong

This ship was rebuilt from scratch against the same subject. Every claim from the original was tested against its own pin, not against today's HEAD — the only fair test.

16 / 16
Quotations and file:line citations, checked at the original pin. All correct.
0 / 4
Counts and directory inventories. All four wrong.
Wrong

“An agent skill that ships zero code.” The repository ships two skills. remove-ai-marks/ is genuinely code-free and says so. clean-user-facing-text/ ships four Python scripts — 1,038 lines — including a vendored, byte-identical copy of the 724-line Layer A engine, run locally with no service at all.

It compounds: the byte-equality test the original correctly cited and recommended as a takeaway exists precisely because a skill ships vendored code. The evidence against the headline was inside the artifact the headline's own lesson was drawn from.

Wrong

“106 of 128 commits.” At the pin, by name, the author holds 80 of 128. No method produces 106 against that denominator — HEAD gives 81/140, all refs give 108/167. The numerator came from one ref population and the denominator from another.

Verb

“Redirects refused.” They are followed, up to a limit, with the target revalidated and re-pinned on every hop. The security property is real — the origin is pinned after the first hop, so cross-origin redirects are rejected — but “refused” is not what the code does.

Half

“Format matrix checks both ways.” Docs → code is clean: no phantom formats. Code → docs is not. The dispatcher accepts 41 extensions; the README table names 21, omitting .xlsx, .pptx and the entire twelve-extension text class.

Held

Everything quoted. All four README hedge citations, rewrite_text.py:495, vendor-notes.md:47, how-claude-marks.md:21, test_lightweight_skill.py:79-85, the 52,787-byte benchmark, 23,605 lines / 465 tests / 0.69:1, 61 trailer lines across 36 commits with all four AI-tool tallies, zero continue-on-error, the 128 MiB caps, the empty benchmarks/, the ethics grep, the licence-derived Docker column.

The transferable finding

The failure is structural, not carelessness. Reading a file and quoting it is reliable. Enumerating a directory and generalising from one member is not. An inventory check only stays true in the direction it runs.

06 — SecurityLow, and better than most

Zero CORS anywhere in the repository. Both HTTP servers default to loopback and warn on any other bind. Authentication fails open only when unconfigured, only behind loopback, and says so. Containers run read-only, non-root, on tmpfs. The installer is 102 lines and touches no network. Three CI workflows with zero continue-on-error and zero || true, plus pip-audit and CodeQL.

One gap, unchanged: a fetched web page enters the agent's context and nothing treats it as untrusted text. Low severity — the worst realistic outcome is a bad clean — but the sentence is missing.

07 — VerdictRead and borrow. Do not install.

Goal-aligned, no mint, counts unchanged. The block is purpose, not security: the engineering here is better than several tools this corpus has piloted, but recruitment is precisely the context the subject's own ethics file places out of bounds.

Take three things, install nothing

A “Verifiable today?” column in the feature matrix, answered before each feature ships. It is the smallest artifact that discharges an eval-gating requirement that still has no implementation.

Put the caveat in the API response, not the docs. They compiled theirs into a note field that travels with the result. Documentation is read once by whoever integrates; a response field is read every time, by everyone downstream.

A byte-equality assertion with the incident in the comment. Their test records why it exists, and the test immediately after it records the drift that already happened.

Never

  • Point it at candidate CVs, cover letters or portfolios.
  • Cite its removal as verified — its own matrix answers “No”, and it publishes zero results.
  • Cite the star or fork figures as verified. Page-stated only; the API is mocked here.
  • Build a candidate-facing AI-authorship detector on its stylometry scorer. The forensic-readiness study measures baseline false-negative rates of 70–83% with nobody attacking. An absent mark is not evidence of human authorship, and a false accusation on a hiring decision is not recoverable.

08 — Not establishedWhat this did not settle

Star and fork accuracy, and therefore any velocity claim — page-stated, API mocked. Whether removal defeats any real vendor detector. The author's role beyond his public profile. Issue and PR contents. The EU Code of Practice publication dates. No subject code was executed.

And one method limitation worth stating plainly: this rebuild was meant to run blind, with the agent fleet given no prior findings. It was not fully blind — this vault's context file is injected into every worker and carries the earlier summary. The workers derived their evidence independently and one of them contradicted the earlier headline on its first pass, but the blindness claim does not hold. A blind replication cannot be run inside a workspace whose state file is auto-loaded into the workers.
