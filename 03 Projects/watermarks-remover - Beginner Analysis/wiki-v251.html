01

The finding

They built a rigorous instrument to measure whether watermark removal works. That instrument is structurally incapable of measuring the one watermark the tool exists to remove. Rather than hide this, they wrote it into the README four times and into two of their own Python files' runtime output.

The instrument is real

bench_synthid_text.py is 52,787 bytes — the fourth-largest file in the repository. It generates a watermarked and an unwatermarked corpus, runs removal variants, and measures clear rate (before-positive → after-negative), score suppression, quality cost as lexical divergence and length drift, and dollar cost at given prices. It emits results.json, results.csv and report.md. That is a properly specified experiment.

And it cannot be pointed at Claude

Detection, per detect_text_watermark.py:8, is “only valid against the SAME scheme config + keys used at generation.” The benchmark plants a watermark with a key it controls, removes it, and detects with the same key — a closed loop. Anthropic has not published its algorithm or keys, which the repo itself states at how-claude-marks.md:21.

Until vendors ship public detectors and keys, no tool can honestly certify “this fails the official check.”

README.md:739 — and again at :480, :651, :808, plus rewrite_text.py:495 and markdiffusion_harness.py:14

That last detail is the one worth keeping. The usual drift shape is a hedge buried in a reference file while the front page makes a bald claim. Here the hedge is in the README's top-level prose and compiled into strings the code prints at runtime — so it reaches the user, not just the reader.

The corresponding gap

No results are committed. benchmarks/ holds a README, two shell scripts and eight seed texts of roughly 500 bytes each. Nothing matching results* or report.md is tracked. The instrument ships; no reading from it does. Two fair readings: they built the measurement and never published a number, or they declined to publish a number they could not honestly generalise. The README quoting zero efficacy percentages is consistent with the second — but the absence is real either way.

Every guard that protects the file is code. Every guard that protects the world is prose.

This is the correct call, not a shortcut

The rule this corpus arrived at one ship ago: you can only compile the part of your standard that becomes a lie when violated; the rest stays prose. Apply it. “Do you own this content?” is not decidable from the artifact. The bytes of a PNG do not carry ownership. No amount of engineering makes that checkable.

The rule's second clause is when you leave one in prose, do not call it non-negotiable. This project passes that too. Its ethics file is titled “Intended use”, and it closes by disclaiming liability “for potential misuse by users” — which is an explicit admission that the constraint is not enforced.

Why it matters for the set

Five consecutive ships have turned on which guarantees a project compiles and which it leaves as prose for a language model to honour. This is the first to face a genuinely undecidable constraint — and it handles both clauses correctly. The previous ship drew the boundary; this one stands on the far side of it and says so.

The prose itself is unusually disciplined. ethics.md:18: “A removed mark does not mean the content was never AI-assisted.” And in the vendor reference, addressed to the model reading it: “Do not invent algorithm claims.”

And the README argues against its own headline feature

If the plan is to rewrite the text with a cheaper model anyway, why pay for a premium model in the first place? Generating directly with the cheaper model is simpler, cheaper, and produces the same — or better — end result.

README.md:757 — from the section titled “Disclaimer: what removing a text watermark costs”

The argument is technical, not performative. Statistical marks live in word choice, so removal means rewriting a substantial fraction of the text, which flattens tone and precision — “the result cannot exceed the rewrite model's ceiling.” The section ends by telling you when to skip Layer B entirely.

Fifteen thousand people starred a watermark remover whose own documentation dismantles the reason they starred it.

05

The boring parts, which are good

clean pass

CI gates are wired and none soft-fail. Three workflows; continue-on-error = 0 and || true = 0 in all of them. pytest -q runs the whole suite, plus ruff lint and format checks, OpenAPI validation, a Windows smoke test, pip-audit, and CodeQL. Second consecutive clean pass on this test.

no triad

Authentication is not broken. Default bind is 127.0.0.1; there are no CORS headers anywhere, so a browser cannot reach it cross-origin. Auth does fail open when no key is set — but only behind a loopback bind, and it prints “warning: no API key set” rather than staying silent.

strong

SSRF hardening is better than most production code. It resolves the host, unwraps IPv4-mapped IPv6, strips zone identifiers, rejects on is_global, and refuses when nothing resolves. Redirects are refused outright so an Authorization header can never be re-sent to an unvalidated host.

exemplary

Licence hygiene closes a three-ship set. The Docker image table has a “Published?” column derived from each upstream's licence — including one dependency that “ships no LICENSE”, correctly treated as all-rights-reserved and never published. Repeated in the compose file three times, a README section, the changelog, and the sidecar's own docstring.

465 tests

36 test files, 9,233 test lines against 13,305 service lines — a ratio of 0.69 : 1. Only five skip markers in the entire suite, so the “a skipped test reports as success” hazard does not meaningfully apply.

The silent-leak finding

A one-command detector this corpus carries — grep -rni "silent" — returns six hits, and the species is new: a false success, the most dangerous failure a provenance stripper can have.

ExifTool writes PDFs incrementally… the original metadata bytes stay in the file verbatim, and exiftool itself can undo the edit. The command exits 0, viewers show no metadata, and the file gets larger, which is the tell. For a provenance-stripping tool that is a silent leak.

README.md:788 — and the same paragraph opens tests/test_pdf_structural_rewrite.py

The fix follows exiftool with qpdf --linearize, and when qpdf is absent the clean still runs but says so. Elsewhere the doctrine is stated outright: “Known scope limits (documented, not silently mishandled)”, followed by an exact list of what is not handled.

06

Defects

“Google confirmed” over-states its source

The vendor notes claim Google confirmed the API no longer watermarks text “and DETECT_TEXT_WATERMARK is rejected on current (3.x) models.” I opened the cited developer-forum thread. It supports “Generated text from the API is NOT SynthID-watermarked” and “Native text watermarking is not planned at the moment” — but it says nothing about DETECT_TEXT_WATERMARK, and the responder's Google affiliation is not established on the page. A forum answer of unverified affiliation was upgraded to a vendor confirmation. The same file warns, three lines later, “Do not invent algorithm claims.”

  • No committed benchmark results — the instrument ships, no reading from it does.
  • A filename that outlived its meaning. bench_synthid_text.py's own first docstring line reads “Benchmark for MarkLLM text-watermark removal.” A fossil of the pivot.
  • Seven of 27 service scripts are never named in the 65 KB README — though most are internal modules, so this one is weak.

An error of mine, logged

I flagged the SynthID scorer sidecar as “an entire second HTTP server undocumented in the README” because its filename appears there zero times. Wrong — the README documents it by role, as wr-synthid-score, and discloses its non-commercial licence in four places. This is the same trap that caught this corpus one ship ago: a filename convention that omits its parent defeats inventory reasoning. The fix, both times, is to stop diffing filenames and read the parent document.

07

Verdict

Rating
GOAL-ALIGNED · 3/4 no mint counts 46/11 unchanged

Affiliation fails; goal relevance, rigour and corpus value are all strong. No new capability class is minted: metadata scrubbing is exiftool's decades-old core function, the commercial “humanizer” industry predates this, and the differentiating machinery is external — MarkLLM, MarkDiffusion, CtrlRegen and reverse-SynthID are all upstream projects loaded from user-supplied checkouts. This repository is the wiring and the honesty layer, not the removal engine.

Security
LOW

Loopback default, no CORS, real SSRF and XXE and zip-bomb guards, non-root read-only containers, env-only keys, redirect refusal, and an installer that writes to exactly one directory with staging and rollback and no network access.

Pilot
READ AND BORROW · DO NOT INSTALL

Not on security grounds. The engineering here is better than several tools this corpus has actually piloted. The blocker is purpose.

The operator ships a recruitment product handling candidate data under a ratified policy requiring every candidate-touching model path to be legible, audited and human-in-the-loop. EU AI Act Article 50 transparency obligations are live in that market. And recruitment is precisely the context the subject's own ethics file places out of bounds — it names “misrepresenting AI assistance where disclosure is required” as not appropriate. There is no configuration in which this belongs near that product.

08

Take three things, install nothing

Borrow 01

A “how would we know it worked?” column

Put per-capability verifiability inside the capability table itself, and answer No where you must. This discharges the eval-gating clause of the ratified model-use policy, which has demanded it for months and still has no implementation.

Borrow 02

Put the caveat in the response, not the docs

Their “cannot certify” sentence is compiled into two Python files, so it reaches the user at runtime. For a candidate-matching explanation feature, the confidence caveat belongs in the API response body — every downstream consumer then inherits it.

Borrow 03

Assert byte-equality on duplicated files

A test asserts their two vendored copies are identical, and the comment records the drift incident that caused it. This vault has a chapter file whose name has been wrong for sixty-seven versions and nothing has ever noticed.

The direction inversion

This tool removes marks from output you generated. A recruitment product's live question points the other way: detecting AI authorship in candidate input — CVs, cover letters, take-homes. Same map, opposite direction.

Read that way, the useful half is the one nobody stars: image_meta.py and container_meta.py total 153,786 bytes of per-format inventory of exactly which bytes carry provenance across twenty-odd formats — that is what an upload pipeline must preserve rather than silently destroy on re-encode. score_stylometry.py is zero-LLM cadence scoring: detection with no model call and nothing leaving the box.

But the hard limit belongs in the same breath. Their own matrix answers No to “Verifiable today?” for statistical text marks, and their ethics file says “a removed mark does not mean the content was never AI-assisted” — whose converse binds equally: an absent mark is not evidence of human authorship. Stylometric AI-detection is a documented source of false accusations against non-native English writers. Read this to understand the terrain; do not deploy it against applicants.
