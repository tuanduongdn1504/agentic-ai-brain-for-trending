## 1. What it is, in one paragraph

An **agent skill plus a stdlib-only Python HTTP service** that strips AI provenance marks from text and files: invisible Unicode carriers (Layer A), statistical token-sampling watermarks via model rewrite (Layer B), and C2PA / EXIF / XMP / document-property metadata across ~20 container formats. The skill itself ships **zero code** — it is a thin client that drives the service over HTTP on `127.0.0.1:8765`, so the agent host needs no Python.

**Scale (hand-counted):** 144 tracked files · **23,605 lines of Python** across 68 `.py` files · 2,503 lines of Markdown · a **65,768-byte README** · 128 commits on `HEAD` (154 across `--all`) · **exactly one git root**.

## 2. The headline: they built a real measurement instrument, and it cannot be pointed at the thing the tool exists to remove — and they say so, six times

This is the finding that organises everything else.

**The instrument is real.** `service/scripts/bench_synthid_text.py` (52,787 bytes, the 4th-largest file in the repo) is a genuine benchmark harness. Its docstring (`:1-25`) describes generating a watermarked *and* unwatermarked corpus, running removal variants, and measuring:

- **clear rate** (before-positive → after-negative) per variant
- score suppression (mean/median delta)
- quality cost (lexical divergence, length drift, number/URL survival)
- wall time, estimated tokens, optional USD at given prices

It emits `results.json` / `results.csv` / `report.md`. That is a properly specified experiment, not a gesture.

**And it cannot measure the headline use case.** `service/scripts/detect_text_watermark.py:8-10` states the constraint plainly: detection is *"only valid against the SAME scheme config + keys used at generation. It cannot certify that a vendor detector will fail on the given text."* The benchmark plants a watermark with MarkLLM under a key it controls, removes it, and detects with the same key. That is a closed, self-consistent loop.

Anthropic has not published its algorithm or keys — the repo's own `references/how-claude-marks.md:21` says so: *"Anthropic has not published the algorithm"*. Therefore **the one watermark that motivated this repository's existence is, by construction, the one its benchmark cannot evaluate.**

**They say so, repeatedly, and in the code.** `grep` finds the hedge in SIX places — four in the README and two inside Python that emits it at runtime:

| Location | Text |
|---|---|
| `README.md:739` | *"no tool can honestly certify 'this fails the official check.'"* |
| `README.md:480` | *"it cannot certify a vendor detector will fail"* |
| `README.md:651` | *"it cannot certify a vendor"* |
| `README.md:808` | *"It cannot certify that vendor detectors will fail."* |
| `service/scripts/markdiffusion_harness.py:14` | *"it cannot certify that a vendor detector will fail"* |
| `service/scripts/rewrite_text.py:495` | *"cannot certify removal against a vendor detector."* |

This is the **inverse of the usual drift shape**. The normal failure is a hedge buried in a reference file while the README makes a bald claim. Here the hedge is in the README's top-level prose *and* propagated into the code's own output strings.

⚠️ **The corresponding gap: there are no committed results.** `benchmarks/` contains only `README.md`, two shell scripts, and 8 seed texts of ~500 bytes each. `find` for `results*` / `report.md` returns nothing; `git ls-files` confirms none are tracked. **The instrument ships; no reading from it does.** Two fair readings: (a) they built the measurement and never published a number, or (b) they refused to publish a number they could not honestly generalise. The README quoting **zero** efficacy percentages is consistent with (b) — but the absence is real either way.

## 4. The ethics surface is 100% prose — and that is defensible

**The decisive check.** Grepping Python for ethics-shaped words (`consent|authoriz|you own|ownership|ethic|fraud|academic`) returns **only HTTP `Authorization` header handling** — a completely different sense of the word. Not one line of code implements *"content you own or are authorized to process."*

**What IS gated in code — all technical safety:**

| Guard | Evidence |
|---|---|
| XXE | `audit_website.py:76` — *"sitemap declares a DTD / entities; refusing to parse"* |
| SSRF | `audit_website.py:211` — *"refusing non-public address"* |
| Zip bomb | `container_meta.py:771,785,808` — `MAX_ZIP_DECOMPRESSED_BYTES = 128 MiB`, per-member **and** cumulative budget |
| Unknown format | `format_dispatch.py:74` — callers *"refuse unless"* explicitly opted in |
| Binary-as-text | `inspect_text.py` / `clean_text.py` refuse ZIP containers |
| Body / batch caps | `server.py:74,79,573,810` |

**So the ledger is exact: every constraint that protects the FILE is code; every constraint that protects the WORLD is prose.**

### Is that a defect? No — and this is where it earns its place in the v246→v250 set

v250's rule: *you can only compile the part of your aesthetic that becomes a **lie** when violated; the rest stays prose.* Apply it here. **"Do you own this content?" is not decidable from the artifact.** The bytes of a PNG do not carry ownership. No amount of engineering makes that checkable. By v250's own criterion, leaving it as prose is **the correct engineering choice**, not a shortcut.

v250 added a second clause: *when you leave one in prose, do not call it non-negotiable.* Does this project overclaim? **No.** `references/ethics.md:32` says the developers *"disclaim any liability for potential misuse by users"* — which is an explicit **admission that misuse is possible**, i.e. an acknowledgement of non-enforcement. The framing throughout is *"Intended use"* (the file's own H1), not *"enforced policy."*

⭐ **This is the first member of the v246→v250 code-vs-prose set to face a genuinely UNDECIDABLE constraint, and it handles both clauses correctly.** v250 articulated the boundary; this one stands on the far side of it and does not pretend otherwise.

### The ethics prose itself is unusually disciplined

`references/ethics.md` is 32 lines and does real work:
- **Not appropriate:** *"Academic fraud or misrepresenting AI assistance where disclosure is required"*, *"Circumventing lawful transparency or platform disclosure rules"*, *"Claiming cleaned content is 'human-written' for compliance theater"* (`:14-16`)
- `:18` — *"A removed mark does **not** mean the content was never AI-assisted."*

## 6. The v246 `silent` detector replicates a 6th consecutive time — with a new species

`grep -rni "silent"` returns 6 hits. The species here is a **false success**: a tool that exits `0` while the data survives — the most dangerous possible failure for a provenance stripper specifically.

`README.md:788-800` and `tests/test_pdf_structural_rewrite.py:1-8`:

> ExifTool writes PDFs **incrementally**. `exiftool -all=` appends a `%BeginExifToolUpdate` block that frees the Info object and drops `/Info` from the trailer — *"but the original metadata bytes stay in the file verbatim, and exiftool itself can undo the edit with `-PDF-update:all=`. The command exits `0`, viewers show no metadata, and the file gets larger, which is the tell. For a provenance-stripping tool that is a silent leak"*

The fix: follow exiftool with `qpdf --linearize`, which re-serialises from the object graph. **And when `qpdf` is absent the clean still runs but says so** — a loud warning instead of a silent lie. This is the v246 doctrine (convert a confident-wrong-answer mode into a loud one naming cause and remedy), arrived at independently, and it is **code with a test**, not prose.

⭐ `service/scripts/av_meta.py:16` states the doctrine as a principle: **"Known scope limits (documented, not silently mishandled)"** — followed by an exact enumeration of what is *not* handled (legacy QuickTime without `ftyp`; ID3v2.2 falls back to whole-tag drop; ID3v1 not handled).

## 8. Anti-drift: a byte-equality test, with the incident that caused it

`text_unicode.py` (21,089 bytes) exists **twice** — `service/scripts/` and `skills/clean-user-facing-text/scripts/`. `md5` confirms identical (`3a08c7fb19409a964658ec44e6c30ce8`); neither is a symlink.

The pin is a **test** (`tests/test_lightweight_skill.py:79-85`):

```python
def test_vendored_text_unicode_is_identical_to_service_engine():
    # The Layer A engine is vendored byte-for-byte; only the CLI wrappers
    # (clean_text.py, inspect_text.py, common.py) may differ. Any engine
    # change must be applied to both copies in the same commit.
    assert service == vendored
```

⭐ And **the drift already happened** — `:89` is a regression test with the incident recorded: *"the vendored copy once blanket-stripped RTL isolates/marks and VS16 after arrows, corrupting legitimate text."*

Compare the corpus's three answers to the same problem: **v243 ToolJet** used a symlink (drift structurally impossible); **v244 OpenSandbox** did it by hand twice, differently; **this** uses a byte-equality assertion. The symlink is stronger, but this version carries something a symlink cannot: **a record of the failure that motivated it.**

## 13. The defensive inversion — the most useful thing here

⭐ **This repository is an excellent map of where AI provenance marks live.** The detection half is genuinely separable from the removal half:

- `/inspect` and `/detect` HTTP endpoints (read-only — they return a report, not a cleaned file)
- `inspect_file.py`, `inspect_text.py`, `inspect_image.py`
- `detect_text_watermark.py` (MarkLLM harness), `score_stylometry.py` (zero-LLM cadence/burstiness scoring — **detection only, no model required**)
- `audit_website.py` / `audit_dir.py` — sweep a directory or a site for AI marks, with SARIF output
- `detect_before` / `detect_after` options on `/clean`, so a clean carries its own before/after evidence

For a defender the interesting artifact is `image_meta.py` + `container_meta.py` (**153,786 bytes combined**) — a per-format inventory of exactly which bytes carry provenance in PNG, JPEG, WebP, AVIF, HEIC, BMP, GIF, TIFF, SVG, PDF, DOCX, XLSX, PPTX, EPUB, ODT, HTML, MD, MP4/MOV/M4A/M4V, WAV and MP3. That is the reference you would want when building a system that must **preserve** provenance.
