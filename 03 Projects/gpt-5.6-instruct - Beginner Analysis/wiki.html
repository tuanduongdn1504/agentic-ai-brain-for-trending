1 · What it is

A versioned set of "unrestricted" system-prompt files (v5 recommended, v35 specialized), a Python installer (codex-instruct.py) that writes them into Codex CLI's official model_instructions_file config field, and a 360-case harness that measures how reliably the model stops refusing. Stated strategy: reframe disallowed tasks (security research / pentest / reverse-engineering / software cracking / NSFW fiction) as "local sandbox tasks" and suppress refusal rhetoric.

2 · The mechanism (attack class, for defense)

  1. Config-layer system-prompt override. Codex's model_instructions_file key replaces the CLI's built-in instructions with a user file — a legitimate customization feature, here weaponized.
  2. Weaponized payload reframes disallowed requests + suppresses refusals.
  3. One-command install makes every subsequent Codex session silently load the override until restored.
Efficacy is bounded (the honest part MDX-Tom's own README omits): a sibling's ANALYSIS.md notes model_instructions_file cannot override OpenAI's true system prompt, and API-layer classifiers operate independently of the prompt. So the pack reshapes the softest layer it controls — the claimed 120/120 measures refusal-avoidance on a self-selected bank, not true unrestricted capability. Defensive lesson: never put safety-critical logic in a layer an untrusted party can replace; keep an independent gate outside the prompt.
