The Unwired Checks

citrolabs/ego-lite  ·  150 files  ·  ~26,800 lines  ·  MIT + a closed binary

A team wrote the most thoughtful instructions for an AI agent in this corpus — including a rule that says stopping when the human intervenes is not a failure but the correct outcome. Then they built a mutation tester, a prose linter and a token-leak scanner aimed at their own worst failure modes, and wired none of them to anything.

What it is

One browser, two occupants

ego lite is a Chromium-based macOS browser built so that a human and any number of external AI agents can share a single browser. It partitions itself into Task Spaces — isolated browsing contexts, each owned by either agent or user, each inheriting your login state by default. You browse in front; agents work behind; neither steals the other's tabs.

ego-browser is the open half: a Node.js CDP harness that any agent CLI drives by writing a JavaScript snippet into a heredoc. It presents a deliberately Playwright-shaped API, so anyone who knows Playwright already knows it.

The browser itself is a closed-source .dmg. And the project says so, unprompted, in the two files a reader and an agent open first.

The thesis

That is their own doctrine, one of four named Design Principles in CONTRIBUTING.md:

The sharpest finding

A gate its own history contradicts

main-pr-source.yml is nine lines and one rule: pull requests into main must come from the dev branch. It landed on 2026-06-01 and sits on main.

66/82 PR merges into main since the gate was added that came from branches the gate is written to reject — including HEAD itself. Sixteen came from dev.

And four sources of truth about one process, no two agreeing: the workflow requires dev; CONTRIBUTING.md:322 agrees; CONTRIBUTING.md:283 tells you to "branch from latest main"; the pre-commit hook gates on origin/dev; and main and dev have diverged — 32 ahead, 20 behind.

Follow the contributing guide, branch from main as a cloner gets it, and the project's own pre-commit hook blocks your first commit — then the CI gate rejects your PR.

What is not claimed Whether that workflow is configured as a required status check lives in GitHub branch-protection settings, which are not in the repository. So this is a measurement, never an accusation: the rule this repository commits and the history this repository records disagree 66 times. That is v244's D28 run in reverse — an absent config file is not an absent check, and a committed CI rule is not an enforced one.

The best artifact

An agent contract that governs behaviour

skills/ego-browser/SKILL.md is, on the merits, the strongest agent-facing contract in this corpus — ahead of v246's llms.txt, because it does something an API reference cannot: it tells the agent how to behave.

The write probe

Before writing substantial content into a rich editor, perform a tiny write probe, then verify it. If the probe appears in the title bar, toolbar search, hidden input, or any wrong field, stop using DOM/input helpers for that surface — and switch technique. It converts "I filled the form and the document is unchanged" from a confident wrong answer into a detected one, for the price of one small write. The second half is the part everyone omits: on failure, change technique, not parameters.

Failure as the correct outcome

A "user is controlling" error is a hard stop on the whole task — not an obstacle to route around. It means the user has deliberately taken the browser back, often because your current approach is going wrong. Honoring it is the correct outcome here; pushing the goal forward anyway is the failure. SKILL.md — Control handoff

That is written by someone who has watched an agent grind past a human's intervention. Naming deference as success, rather than as a constraint, changes what a completion-seeking model is optimising for.

And then the two gaps

A prose guardrail on an unguarded primitive The same ownership table records that takeOverTaskSpace has no ownership check, and the mitigation is a sentence: "Never call it on your own to grab control back — it will seize the browser away from the user." Verified at helpers.ts:347-353. So the most consequential action in the system — an agent taking the browser from the human using it — is prevented only by an instruction addressed to a language model. That is the exact inverse of v246's rule: where you cannot make a failure loud, move the setting into the artifact so it cannot be set wrong.
Not one word about a hostile page The product loop is: read an untrusted web page → an LLM decides → it writes JavaScript that runs against your authenticated sessions. A grep for malicious, hostile, untrusted, prompt inject across SKILL.md, AGENTS.md and CONTRIBUTING.md returns nothing. There is no SECURITY.md. They reasoned at length about one adversary — an impatient agent that might trample its user — and not at all about the other.

Security & supply chain

The boundary is drawn well; the risk is the premise

No broken-auth triad, and structurally so. ego-browser opens no port and no socket — the transport is a function the app injects. It notably declines the usual shortcut of exposing Chrome's --remote-debugging-port, which is exactly the failure mode this corpus documented at v231 and v232. The authorization model therefore lives in the closed app and cannot be audited: the open layer can neither be faulted for lacking auth nor credited with having it.

The residual risk is the product's own premise. Inside a Space that inherits your logins, js() is arbitrary evaluation and browserFetch() returns authenticated response bodies to any origin. With the silence above, prompt injection from page content is the entire threat model.

Two precise smaller items: .env is auto-loaded from the installed skill directory into agent-script environment; and validating a site-learning imports it, so the validator executes learning JavaScript in CI — correctly configured as pull_request, not pull_request_target, so fork PRs run without secrets. That is the right choice and worth saying.

Supply chain is mid-table with two standouts: exactly one runtime dependency (acorn, reused three ways), and a mutable latest.tar.gz URL made immutable by a committed SHA256 — better than v246's pinned-but-unverified, far better than v234's plaintext installers. Against that: caret-ranged deps, and a .dmg at an opaque fixed filename with no version in it, so you cannot pin, diff, or name what you installed.

Prior art

Not world-first, and no mint

Each component is occupied. A daily-use browser whose agent reaches your real logins: Claude in Chrome, ChatGPT Atlas, Perplexity Comet. Isolated parallel workspaces in one browser: Arc Spaces — the name is literally Arc's — Firefox Multi-Account Containers, Chrome profiles, and the entire anti-detect category, whose product is multi-profile isolation. An externally drivable browser: CDP, Playwright, Playwright MCP, browser-use, Vercel's agent-browser. Arc and Brave already ship first-class agent APIs, Arc's with a declarative permission system ego lite does not have.

What is actually distinctive is narrower than the marketing: the per-Space ownership state machine — agent | agentDelegatedToUser | user, with handoff, takeover and claim as first-class operations, a tabulated policy, and a doctrine naming deference as success. I did not find that primitive elsewhere. But an absence of evidence is not evidence of firstness, and a combination is not a capability class.

NO MINT on four grounds: form-factor-within-a-genre; a combination is not a class; the distinctive machinery is not in the subject; and the N=1 gate. Recorded but not executed: a deferred watch axis for human+agent shared-state co-habitation with per-workspace ownership handoff — repeatable well beyond browsers, and a real candidate if a second implementation ships. A promotion is an audit act.

The verdict

Do not install. Borrow four things.

The fence that makes this safe for an operator whose laptop holds candidate data is a profile with no ATS and no mail logged in — and that fence is also the refutation. The only configuration in which it is safe is the one that deletes the reason to use it. Its feature is inheriting your real logins; decline that and you have a closed binary from a team the repository never names, driving pages you don't care about, which Playwright already does in the open on three platforms.

Candidate sourcing — the use case that would pay for itself — fails on the ratified policy (no injection defence, no read-only mode, no approval gate), on asymmetric account risk, and on unestablished accountability.

Method

Nine errors, five of them mine

All five of mine were caught before publication, and three were suspicions that did not survive checking: that the version-normalising workflow was operative (it has never fired), that dev was the integration branch (main is ahead, and they have diverged — that wrong hypothesis became the sharpest finding), that the style linter was theatre, that SKILL.md documented four non-existent helpers (my grep could not answer it — recorded unverified), and that the unmentioned paid tier was a second omission (it sells support, not features).

The fleet contributed four of its own. The critic "corrected" my file count of 148 to 173 — by counting .git internals as repository files, which is this vault's signature error shape committed by the agent assigned to hunt it. Adjudicate a counting dispute with a command, not with authority. It also called the closed binary libneedle — that is v246's binary, imported from the context I supplied to ground it. The lesson there is mine: context supplied to ground an agent can also contaminate it.

v246's method finding replicates — and the fix works Last ship, agents asked to check claims rubber-stamped seven of eight against a brief that told them to default to refuted, while the agents asked to read the code caught the worst error. So this ship replaced the verify stage with a contradiction stage: each agent received the mapper's report as a suspect document, was told its job was to produce corrections by independent reading, had to open and confirm at least six specific citations, and had to file a read receipt naming files and line ranges. It returned corrections and receipts instead of confirmations. Do not ask an agent whether a claim is true; ask it what the claim gets wrong, and make it show you what it read.
