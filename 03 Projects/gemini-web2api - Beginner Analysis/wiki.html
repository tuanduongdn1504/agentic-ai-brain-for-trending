How it actually works

This is pure HTTP protocol reverse-engineering. There is no browser anywhere in it — and that is the sharpest distinction from the corpus's previous instance of this class, which drove a real UI inside an anti-detect browser and scraped the DOM.

01
Call Gemini's own internal RPC
The same batchexecute-family endpoint the web page hits when you type into it — /_/BardChatUi/data/assistant.lamda.BardFrontendService/StreamGenerate, with bl, hl, _reqid, rt=c.
02
Reconstruct Google's web-client auth
Send the raw Cookie header, parse SAPISID out of it, then compute and send Authorization: SAPISIDHASH {ts}_{h} — Google's own scheme, reimplemented from observation.
03
Parse the wrapped RPC stream
Scan for the "wrb.fr" marker, deserialise the nested JSON at arr[0][2], pull text from inner[4], regex-detect BardErrorInfo.
04
Translate into three API shapes
OpenAI chat completions, the OpenAI Responses API (for Codex CLI), and Google's native /v1beta shape (for Gemini CLI) — with tool calling, streaming and image input on top.

Mimicry is header-level only: a spoofed User-Agent, X-Same-Domain: 1, and matching Referer/Origin. No patched browser, no TLS fingerprinting.

Fragile by construction

The shipped config pins a Google internal build identifier — boq_assistant-bard-web-server_20260716.08_p0 — which Google rotates. And unlike the mature upstream library in this space, there is no __Secure-1PSIDTS rotation: cookies are loaded statically from a file. Keeping it alive needs a live session cookie, a current XSRF token and a current build ID, all harvested from a real logged-in page. The repo ships a browser extension whose entire job is that refresh.

The security posture — read this

The install is benign: standard library plus one optional dependency, MIT, no curl|bash, no compiled binary, no postinstall script. Materially safer than v231, which pulled a black-box Chromium from an anonymous vendor. The concern is entirely the runtime posture.

Together: a service that can spend your Gemini entitlement — and, in cookie mode, holds your live Google session — binds to every interface, accepts any origin, and authorises everything when unconfigured.

The risk asymmetry

  • Anonymous mode exposes no account of yours. There is nothing for Google to ban; the pressure lands on Google's IP-level throttling — which the bundled Cloudflare Worker path exists to spread across ~300 edge locations.
  • Cookie mode exposes a real Google account, with no token rotation, from a file behind an open-by-default listener.

Neither README carries a terms-of-service, legal or account-ban disclaimer — weaker disclosure than v231, which at least conceded ban risk. Credential-hygiene warnings do exist, but only inside the extension and Cloudflare READMEs: “Cookie 等同于你的 Google 账号凭证.”
