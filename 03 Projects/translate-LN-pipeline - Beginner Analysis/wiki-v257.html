The architecture, in one sentence

The tool builds clean JSON, renders an optimal prompt, and stops. You copy it into Claude, GPT or Gemini yourself; you paste the answer back; it checks the syntax and files the result. The README is emphatic that this is the design and not a missing feature — "đây không phải công cụ dịch tự động không não", this is not a brainless auto-translator. The human is the transport.

Strip the light novels away and what is left is a prompt-engineering system: thirteen versioned templates numbered as a pipeline, a render engine with variable injection and a three-level override chain, a response parser, a step registry that separates AI steps from deterministic local ones, a persistent entity canon spanning a whole book series, a confidence field requested from the model, and a review-flag service. There is no computer vision anywhere. That is why this ship rates goal-relevance STRONG where the sibling rated MODERATE.

The gate that cannot fire

Two release paths skip any row not marked "success" — release_builder.py:354,364 and release_service.py:140,150. Correctly written, consumed in two files. And in the generation that ships, artifact_store.py:25 writes {"item_id": …, "status": "success", "result": …} — the status is a literal, assigned at write time.

the sharpest form of a recurring theme

The only code in the repository that can write "failed" is src/pipeline.py:28 — generation 1, whose API call can raise. In generation 3 the sole writer of that field is a constant, so the gate can never exclude anything, and nothing about it looks broken.

A gate can outlive its signal source. v250 aimed a gate at the wrong thing; v252 labelled unautomated rules "Automated"; v256 kept artifacts whose context had been deleted. This one is a working gate reading a field whose only varying writer belongs to a generation that is no longer the product.

What is genuinely good here

one loop closes, and the model opens it

prompts/03 instructs: if an important term appears in the segment but is not in the volume glossary, put it in missing_glossary_candidates for human review. review_flags.py reads exactly that field and raises a warning the UI shows. Prompt, schema and gate all agree on one string, and the loop runs from the model's own uncertainty to a human's screen.

⭐ That is the pattern to take, and it is better than thresholding a score: ask the model to admit its gaps into a named field, then gate on that field. It is greppable, testable, and it is the only escalation mechanism in this repository that actually works.

The prompts themselves are strong — a role line, injected genre, explicit scope fences (do NOT translate; do NOT overwrite existing canon), a precedence rule where existing canon outranks new guesses, a conflict protocol that marks contradictions rather than overwriting, and two-tier status semantics that tell the model how a downstream model will consume the field. Every canon entry records which chapters and volumes it came from — the artifact carries its own context, which is exactly the rule the sibling repository broke four times.

The response parser strips markdown fences and, on failure, walks the string with correct quote-and-escape handling to recover the outermost JSON object. The secrets posture is clean: the config stores "api_key_env": "DEEPSEEK_API_KEY", the name of a variable, never a key. The Calibre export checks its subprocess return code instead of assuming success.

The durability claim, and its reader

The README's section on data safety is headed "Cơ Chế Nạp Dữ Liệu & Khôi Phục Siêu Bền Bỉ" — super-durable loading and recovery — and argues for the JSONL row format on precisely this ground: one JSON object per line makes reads and writes independent, so a single bad line cannot ruin the whole file. 

def read_jsonl(path: Path) -> list[Any]:
    if not path.exists():
        return []
    return [json.loads(line) for line in path.read_text(encoding="utf-8").splitlines() if line.strip()]
the fleet found this one and I had walked past it

A list comprehension with a bare json.loads and no per-row try. One malformed line raises and the caller loses every row in the file — exactly the failure the format was chosen to prevent, argued for by name, one section above. And the blast radius is the whole application: the artifact store, the progress calculation, the review flags and the editor index all read through it, so one corrupt line takes out an artifact's history, its progress and its flags together.

⭐ The .bak mechanism is what actually delivers the durability this paragraph promises — just not for the reason, or in the file, the README names.

The habits are the constant; the quality is the variable.

Everything that replicates is bookkeeping — ignore rules, duplicated declarations, committed machine-specific artifacts, dead generations, absent CI, unmeasured numbers. Everything that diverges is care applied to a particular surface — this dependency list is clean and that one cannot resolve; that response validation is excellent and this one is absent. Discipline attaches to whatever the developer was thinking about; structure fails everywhere else. That is a more useful model of AI-assisted solo development than either repository alone could support, and it is why the control was worth a ship.
