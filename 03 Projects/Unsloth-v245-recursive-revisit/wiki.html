03

The best Claude Code integration in the corpus

unsloth start claude points Claude Code at a locally-served model. Almost every line of the environment it builds is a decision, and three of them are worth stealing outright.

Credential hygiene · start.py:146

It deletes your Anthropic key on the way past

_CLAUDE_ENV_UNSET = ("ANTHROPIC_API_KEY", "CLAUDE_CODE_OAUTH_TOKEN") — the child process is launched without them, so a request cannot silently fall through to Anthropic and be billed, and the local endpoint never sees the real key. Same for OPENAI_API_KEY, CODEX_API_KEY, CODEX_ACCESS_TOKEN.

This is the exact inverse of four consecutive prior subjects — v207, v208, v231, v232 — every one of which existed to harvest or re-expose precisely that credential. First subject in the corpus to treat a vendor credential as blast radius to shrink. Two lines.

Integrity · start.py:4359

It refuses to lie to Claude's own safety check

IS_SANDBOX is left unset on purpose: Claude refuses bypass mode as root unless a sandbox is detected, and we don't want to falsely claim one on the user's host.

And in CI, where it is true: “the CI runner IS the sandbox, so declare it.” They set the flag exactly where the claim holds and refuse to set it where it doesn't.

The finding · agent-guides-drive.sh:568–613

A Claude Code default breaks prompt caching — and they wrote a CI test that proves it

Claude Code ≥ 2.1.36 sends an x-anthropic-billing-header injected at the front of the system prompt. It changes every request, so the cached prefix moves, so every request is a miss. Unsloth ships CLAUDE_CODE_ATTRIBUTION_HEADER=0 plus --exclude-dynamic-system-prompt-sections, and then built an A/B in CI: Phase A asserts a cache HIT with the suppression; Phase B strips it and asserts a MISS.

It requires the unfixed configuration to fail — a regression test on the claim, not on the fix. Verdicts are read from the llama-server log, sliced by a byte offset captured immediately before the measured turn so an earlier turn's reuse cannot leak in.

Both knobs are real and undocumented: open Anthropic docs issues #50085 and #45930. Neither string appears in the current settings docs.

Convergence · N=3, cross-organisation

Three unrelated projects found the same defect independently — one of them is ours

Unsloth · musistudio/claude-code-router PR #1220, “Fix: use CLAUDE_CODE_ATTRIBUTION_HEADER to avoid breaking cache” · and farion1231/cc-switch issue #2025 — corpus subject v73. Same undocumented default, three separate workarounds.

Measurement · the vault's own open question

~28k tokens, of which ~18k is tool schemas

measured via claude -p /context, the default prompt is ~28k tokens of which ~18k is “System tools” alone … --tools is the flag that restricts which schemas are sent.

Anthropic's docs confirm the central claim — “To restrict which tools are available, use --tools instead.” One clause of theirs is now inaccurate: a bare name in --disallowedTools does remove the tool from context. This vault has been reasoning about a ~54K tool-catalog floor since v167 and asking for a measurement since v238. Here is the instrument.

The guardrail — read before acting

The mechanism transfers; the number does not. The “~90% slower” figure is measured against local llama.cpp on a CPU runner at ~16 tok/s, where a miss means re-prefilling from scratch. The documentation issue is explicitly scoped to ANTHROPIC_BASE_URL — third-party, proxied and local endpoints.

Do not claim this cuts an Anthropic bill. First-party effect: NOT VERIFIED.

04

The inversion — your model as a subagent inside Claude Code

unsloth start claude --as-subagent does not repoint Claude Code. Claude keeps Anthropic's model and gains a tool: a plugin is written to a session-scoped directory and claude launches with --plugin-dir and exactly two pre-approved tools.

Two variants, and the second is the interesting one — a read-only plan-mode subagent (“Investigate the assigned task with read-only tools … Do not modify files”), with its own test and a follow-up hardening commit. Codex gets a mirror MCP server whose routing instructions override its built-in spawn_agent. Pi gets a 409-line TypeScript extension shipped inside the wheel.

This is the exact inverse of v235. deepseek-harness shipped Claude Code as a subagent of the runtime and left a delegation axis logged as deferred. Unsloth runs the arrow the other way. Same axis, opposite direction, different economics: v235 buys capability, this buys cost and privacy — and the plan-mode variant buys cheap reconnaissance before expensive reasoning, which is the one version of this that is obviously worth doing.

05

Executable documentation, and the sentence that beats it

A CI job installs and drives six real coding agents — claude, codex, hermes, openclaw, opencode, pi — against a live server. The mechanism is the point:

Self-updating: we obtain the exact env + command from unsloth start <agent> --no-launch and run THAT, so a recipe change is exercised automatically.

Eleven ships have handed this vault a piece of verify-vault-docs. Every prior piece either prevented duplication (v243's symlink, v244's renderer) or detected it (v239's linter, v240's build gate). This is a third kind: remove the prose from the loop. The documented recipe is a command's output, so there is nothing left to lint.

Around it: a three-way failure taxonomy that separates flaky installs from real drift, a curl | bash that downloads-then-executes so a truncated fetch can never run a half-written installer, the Hermes installer pinned to a full commit SHA, and GNU/BSD-portable secret redaction “so the redaction is never silently skipped.”

But the most valuable thing in 1.75 million lines is in a file about Kaggle GPU quotas.

Rule minted — D32 · the payoff

The workflow header is the source of truth. … If the two ever disagree, the workflow is right and this file is stale; fix this file.

When two documents must carry the same fact and mechanisation is impractical, declare which copy wins — inside the copy that loses.

Prevention needs the two copies to be the same artifact, which fails the moment they serve different readers. Detection needs a checker written and maintained. Declaring subordination costs one sentence, and converts a silent contradiction into a resolved one: the reader who finds the disagreement is instructed, not misled.

And the rule has already been tested — by the file that states it

BUDGET.md and the workflow header now disagree on the headline number, and not subtly:

The workflow says why, at :136-137: “An earlier revision of this block ran 40% for ~23 GPU-h/week, sized against a 40h allowance from before the Studio leg existed.” A second GPU consumer appeared, the allowance was re-split — and BUDGET.md still teaches the 40% arithmetic. The prose drifted on the exact number it exists to justify.

Which is the proof, and it is better than the rule. The declaration did not prevent the drift. It made the drift harmless and self-diagnosing: a reader who finds the two disagreeing is told, by the stale file itself, that the workflow wins and this file is the one to fix.

Set that against v243, the control condition. ToolJet had the doctrine — “Stale context is worse than no context” — a same-PR update policy, and a template. No precedence line, no linter. Its one committed plan file cited three non-existent documents for eight weeks, and it misled. Unsloth has no linter either. Same failure mode, opposite outcome, and the entire difference is one sentence.

Applied here, today: _state/03c-projects-v61-v183.md has held entries through v245 for sixty-two versions. v239 found the defect, v240 built the check, v242 named the rule, v243 shipped the symlink, v244 handed us a third instance — and the file is still called -v183. The rename is still right. One header line fixes the ambiguity now.

One more thing worth taking: how they disable a test

legs.py keeps a grpo Kaggle leg written and deliberately unwired, in an UNWIRED: dict[str, str] whose value is the reason — the verbatim error (torch.AcceleratorError: CUDA error: an illegal memory access was …), the reproduction rate (“one session in three” on Turing), what was ruled out, and the condition for re-wiring. A disabled test that says why it is disabled, in a data structure, is the strongest honest-deficiency disclosure this corpus has recorded — the opposite of a silently-skipped test.

The triad, finally broken properly

This corpus has recorded a broken-authentication triad three times — bind 0.0.0.0, wildcard CORS, auth fails open. v244 was the first positive counter-example, and its answer was a consent gate around an insecure default. Unsloth's answer is better: it does not have the insecure default.

Rule minted — D33

The broken-auth triad is not additive. The CORS leg looks identical to v231/v232 — and it is far less dangerous here, for a reason located somewhere else entirely: grep set_cookie across the backend returns nothing. The session travels as an Authorization: Bearer header, and a browser does not attach that cross-origin on its own.

Leg 3's severity is set by the token transport — cookie-borne is critical, header-borne bearer is minor. Ask how the token travels before weighting the CORS finding. NOT VERIFIED: whether the frontend persists the JWT in localStorage, which would make XSS the real vector.

And the calibre of the work

Measured in WebKit: with Starlette's 600s default, a state-changing request still REACHED the server after remote access was stopped (Chromium/Firefox/Edge re-preflighted). Keep the stale window short so revocation is nearly as immediate as every other trust signal here.

They found a browser-specific revocation gap in their own remote-access kill switch, measured which engines exhibited it, and set the preflight cache to 60 seconds.

Supply chain: a new corpus high-water mark

pi v228 held this title with min-release-age=2. Unsloth's .npmrc sets 7 — N=2 on the technique — with save-exact, a pinned registry, audit-level=high, “use npm ci (never npm install)”, and zero npm lifecycle scripts across all three package.json files. But the reason it takes the title is that it documents its own defeat condition:

this does NOT block an ambient NPM_CONFIG_REGISTRY env var: npm and bun honor that at a higher precedence than this project file. That is exactly why Unsloth does not read NPM_CONFIG_REGISTRY and instead exposes one deliberate, explicit opt-in.

The best security comment states what its control does not cover.

The tag list dates the identity flip

For twenty months this project tagged months: July-2024, July-Mistral-2024, 2025-02-v2, March-2026 — twenty-four milestone tags, no product versions. Then on 2026-03-20 it cut v0.1.0-beta, eleven days after AGPL landed on studio/ and three days after cli/ became unsloth_cli/. Fifty-three beta tags followed in five months, including eight in five days.

A library that ships continuously tags months. A product that ships installers needs version numbers, and a desktop- tag. The versioning scheme changed because the artifact did. Two schemes still coexist, one per identity: _version.py — “the single source of truth” — reads 2026.8.18, while the app is v0.1.800-beta. The product line has never left beta, on a 73.7k★ project shipping signed installers.

The pattern matters more than the fixes. This vault already carries D26 and D27 for exactly that family and I made four of them in one ship. The adversarial verify stage caught three; I caught the rest. That is the case for the verify stage in one sentence: the errors it finds live in the commands, not the prose, so re-reading your own draft will never surface them.

11

What to actually do

⚠️ Read-and-borrow. The licence ambiguity makes Unsloth a non-component for hireui — the v214 / v188 / v243 precedent. Nothing below installs anything.

  • M1 — strip the credential. Any script that sets ANTHROPIC_BASE_URL also unsets ANTHROPIC_API_KEY and CLAUDE_CODE_OAUTH_TOKEN. Two lines; closes accidental billing and key leakage at once.
  • M2 — measure the prompt. claude -p /context in the vault root, then diff against --tools "Bash,Read,Edit,Write,Grep". The first real measurement of the ~54K floor v167 established and v238 asked for.
  • M3 — apply D32 today. One header line in _state/03c-projects-v61-v183.md naming the entries authoritative and the filename stale. Four ships diagnosed this; one sentence resolves it while the rename stays on the list.
  • M5 — make verify-vault-docs a generator, not a linter. The structural payoff.

🔴 Never point it at candidate data. Never -H 0.0.0.0 without --secure. Never meter a routed Claude Code with cache_read_input_tokens — on the Anthropic path Studio never sets it, so it reads 0 on every request regardless of the truth.

—

Blunt

A fine-tuning library became an agent host in ninety days and this vault only found out because someone asked for a wiki. v23 filed it OUTSIDE-SCOPE with “Direct adoption: NONE” — a defensible reading of a training framework in April. By July it was writing Claude Code plugins. Nothing in our criteria changed; the file was simply closed, and a closed file does not get re-read. That is the finding, and it is about us: the one verdict that ends the conversation is the one that most needs an expiry date.

What they built is genuinely good, and better than this corpus's usual band. They point Claude Code at a local model and delete your Anthropic key on the way — after four consecutive ships whose whole business model was harvesting exactly that credential. They refuse to set IS_SANDBOX on your machine because it would be a lie, then set it in CI where it isn't. They found an undocumented Claude Code default that moves the system-prompt prefix every turn and kills the KV cache, fixed it, and wrote a CI test that fails if the unfixed version stops failing — and two other projects, one of them our own v73, found the same thing independently. Their .npmrc documents its own defeat condition. Their CORS preflight window is sixty seconds because somebody measured WebKit still landing a state-changing request after the kill switch was pulled.

And the most valuable thing in 1.75 million lines is one sentence in a file about Kaggle GPU quotas: “If the two ever disagree, the workflow is right and this file is stale; fix this file.” We have spent eleven ships collecting machinery for a problem that a sentence solves. _state/03c-projects-v61-v183.md has been lying about its own contents for sixty-two versions. v239 found the defect, v240 built the check, v242 named the rule, v243 shipped the symlink, v244 handed us a third instance — and the file is still called -v183, because every proposed fix was a project. Unsloth's fix is not a project. It is a line of prose that tells the reader which of two disagreeing things to believe, written into the one that's wrong. Do that today, and keep the rename on the list.

The catch is boring and real: the licence. pip install unsloth ships a uniformly AGPL CLI inside a wheel stamped Apache-2.0, and the README calls the AGPL side “certain optional components.” Nobody is hiding anything — it is in the sidebar, and v23 wrote it down in April — but the sentence people will rely on is not the sentence the packaging supports. So: take the five ideas, install none of it, and note that the two best-engineered repositories this corpus has read back to back both ended up with prose that disagrees with their build. In both, the build was the honest one.
