The finding

Governance, not architecture, produced the ecosystem

The corpus spent seven consecutive ships documenting a plugin ecosystem around this runtime — a TUI, a sidebar, a 13-package web suite, a 1,390-entry catalogue, a desktop client that swallows the host whole. It never read the 23-line file that explains why any of them exist.

“DeepSeek Harness is still at an early stage and under active development. We are sorry that we cannot accept external pull requests at the moment. However, contributing code to this repository is far from the only way to help.”

“Contribute to the ecosystem: Create a plugin that excites you… Associate your GitHub project with the dsh-plugin topic to help others discover your plugin.”

“We do not believe that packages in the official repository are inherently more important than packages created by the community… an idea, an official showcase, and a source of inspiration, but not a mandate from us.”

CONTRIBUTING.md — verbatim

“Everything is a plugin” is not only an architecture. It is a contribution policy: the core is closed to outside code, and the plugin surface is the sanctioned channel — with the host naming the exact GitHub topic string that the community catalogue would later index.

The mechanics agree. Of 1,008 pull-request merges, 939 arrive from deepseek-harness/… branches and 69 from deepseek-ai/… — every one internal. And github.com/deepseek-harness is a real GitHub organisation with zero public repositories. The commit history is fully public; the review record is not.

The errata ledger

What v235 said, and what the source says

Each of these was listed under v235's own heading “Caveats, load-bearing.” Four were inherited from third-party commentary. One was derived from the source. Only that one holds.

Squashed-merge history · “contributor-hostile”

Refuted

“The whole codebase ‘arrived as one squashed merge’… Real provenance opacity.”

One root commit of 48 insertions across 5 files, then genuine incremental development: monorepo infra → vendor Cordis as source → abstract service interfaces → implement the agent loop. Zero non-merge commits carry a (#NNNN) squash suffix; PR merges run continuously from #1 to #2620; the reflog shows no force-push or rewrite. An adversarial verifier instructed to refute this refutation could not. The real barrier is a stated closed-PR policy — openly declared, not history opacity.

Ecosystem compatibility ~19% (41 of 219)

No in-repo basis

“Ecosystem compatibility ~19% — 41 of 219 integrations succeeding.”

Repo-wide grep for 19%, 41 of 219, 41/219: zero hits in any Markdown, JSON or TypeScript file. No compatibility matrix, report or verify script computes such a figure. The number is not the project's — and the vault's own v240 ship catalogued 1,390 plugins.

~10× token usage versus Pi

No in-repo basis

“The single most important number for anyone considering running it.”

No in-repo support — and the project's only token mechanism could not settle it either way. packages/llm/token-meter/README.md discloses that its estimate is “approximate — content without reusable provider usage is priced by character count plus structural overhead, not an exact provider tokenizer.” A ~4-characters-per-token heuristic cannot substantiate or refute a 10× claim.

A confirmed context-duplication bug

Fixed before the release it was cited against

“A confirmed context-duplication bug.”

An architecture note dated 2026-08-11 records the problem and its fix: “Session owns one contiguous Event window and publishes both Chat and Trajectory snapshots through Session.views; it does not run a second Trajectory history source.” v235 rated rc.5, released 2026-08-13. The fix predates the release.

No evaluation harness · BENCHMARK.md is a 3-line stub

Confirmed at rc.7

“BENCHMARK.md is a 3-line stub, no eval harness, zero evaluation claims.”

Adversarially verified and it holds. Still 3 lines. The only performance test measures web-UI rendering over a 500-turn history; the evaluator.ts files evaluate JavaScript closures for plugin loading, not agents. Zero quantitative accuracy or success-rate claims anywhere. This is the one caveat v235 derived from the source itself — and the only one that survives.

Correction

Two headline figures were bilingual double-counts

Every decision note ships three times: X.md, X.zh.md, X.i18n.yaml. A count that ignores the pairing inflates by the number of languages.

“Decision records”

693 English + 692 Chinese = 1,385. Real notes: 693 — 516 implemented, 143 archived, 25 proposed, 11 rejected.

“Lines of docs”

170,752

Correct as “all Markdown,” but English-only content is ~1.9× smaller than the figure implies.

The subject was more careful about this than the vault. Its postinstall registers a custom git merge driver named, verbatim, “DeepSeek Harness bilingual pairing records” — the project wrote a merge driver to keep the triples in sync, while the vault counted the translations as extra records.

The trap is live: an independent agent in this run, counting naively, produced “1,389 decision records (not 1,386 claimed)” — landing in the same bucket. The hand count stood.

The structural gap

Identity is verified end to end. Effect is unmeasured end to end.

This runtime tests its own plumbing harder than most production software and evaluates its agent not at all. Placed beside the vault's two previous ships, that becomes a hole spanning the whole stack.

The host · v242

816 spec files, ~299K lines of test code against ~245K of source, 723 snapshot fixtures, 4 numbered postmortems, 11 recorded rejected decisions.

No evaluation harness.

The catalogue · v240

1,390 curated entries compiled to a public registry API, read live by a separate org's storefront and by a tool inside the agent.

Checks metadata.

The installer · v241

~10 structural gates: lifecycle scripts rejected, SHA-512 integrity, repository backlink, exact-version pinning, approval gate.

“They do not review the plugin… for malicious or unsafe behavior.”

The plumbing is exactly what can be unit-tested, and model quality is what cannot be without an eval harness — so the coverage boundary follows the architecture rather than betraying carelessness. But the consequence is that nothing anywhere in this stack measures whether a plugin makes the agent worse. Security and quality are both unmeasured, for the same structural reason: the only party positioned to measure them is the one that closed its pull-request queue.

Rules derived

Three rules the vault did not have this morning

D23

Declare the language basis of every count.

In a bilingual repository, a naive count over files or lines inflates by the number of languages. Detector: check for .zh.md / .i18n.yaml siblings before quoting any file or doc count.

D24

A version-number delta is not a code delta.

Measure between the release commits, not between the labels. Six ships inferred maturation from a semver ladder that covered 69 minutes and no code.

D25

An un-cloned subject's caveats are hearsay.

When an analysis discloses “not source-cloned,” every critical claim inside it inherits that disclosure. v235 was honest about the gap, then let unverified commentary carry its entire risk assessment. The clone is the only arbiter.

Disposition

Verdict

GOAL-ALIGNED INCLUDE 3/4 · NO MINT · counts 46 / 11 UNCHANGED · GA:100 · §35 CLEAR

No mint — the ninth consecutive decline on this chain

Tested adversarially and refuted on three grounds. Eclipse RCP/OSGi (2001–2004) is decisive prior art for a self-extending plugin system whose shell is itself a plug-in. The architecture is credited to a third party — the README says the design is “powered by Cordis,” and vendor/cordis/LICENSE reads “Copyright (c) 2021-present Shigma.” And the repository claims novelty nowhere: minting would over-claim on the subject's behalf.

Recorded and not self-executed: the stale Graduated / Least-Privilege Tool-Exposure row — at N=1 for ~100 wikis, raised at v238, declined at v241 because that candidate's enforcement was unimplemented — now has an implemented N=2 candidate here, where the highest-privilege toolset is absent from every shipped tree and activation is gated on capability injection: “a composition missing it never activates the tools.” A promotion is an audit act.

Pilot posture: read and borrow. Install nothing. Developer preview with breaking changes promised; no evaluation harness; telemetry opt-out and default-on; a postinstall; PRC-default egress; closed to external pull requests, so a downstream fix has no upstream path.

Never point it at candidate data, and never treat a catalogue listing or topic tag as a safety signal — nothing in this ecosystem reviews plugin code.

Do not cite: “~19% compatibility”, “~10× tokens”, “a context-duplication bug”, “1,386 decision records”, or any star figure.

The subject is better engineered than v235 could show, and worse documented in exactly one dimension than v235 reported. The difference between those two statements is one git clone — and the revisit's real product is not a re-rating of DeepSeek's runtime but four corrections to the vault's own record, and a rule that explains why they happened.

Method. Full source clone with history (201MB, HEAD 99f6f02fecdb…). A 14-agent workflow — 11 succeeded, 3 schema-failed on surfaces already hand-covered; ~1.60M subagent tokens, 485 tool uses, 426s — plus hand-verification of every load-bearing number. Seven errors caught, three of them the vault's or mine.

§37.4. This environment mocks the GitHub API. Stars, forks and watchers are page-stated, never verified, and support no viral-velocity claim.
