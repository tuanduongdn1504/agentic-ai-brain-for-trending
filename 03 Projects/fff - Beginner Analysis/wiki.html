The thesis

Pay the walk-and-index cost once, not per query

ripgrep and fzf are command-line programs: every call forks a process, re-reads .gitignore, re-stats directories, and rebuilds its state before it can answer. Fine for one grep from a shell — wasteful when an AI agent runs hundreds of searches per session. fff keeps the index and file cache resident in one long-lived process, so every search after the first hits warm memory.

500k-file Chromium checkout · per query

ripgrep spawn 3–9 s
fff (warm) < 10 ms

⚠ Author-stated · warm-cache vs cold-spawn · methodology unpublished · not a viral-velocity claim. The README itself: "if you run one grep from bash, rg is still the right tool."

For a coding agent the payoff is two-sided: latency (warm queries) and tokens — "fewer grep roundtrips, less wasted context." That second half is why fff sits on the vault's claude-api-cost-optimization thread.

The agent-facing surface

Three MCP tools + a search-discipline prompt

fff-mcp (stdio) holds one resident FilePicker for the process lifetime, discovers the git root, runs a background watcher, and answers with three tools. It also hands the agent a system prompt that is, in effect, a portable "how to search a codebase" skill — you can steal it without installing anything.

grep# DEFAULT — file contents · auto regex-detect · 3-stage fallback on 0 hits
find_files# fuzzy file names · frecency-aware · auto-retry shorter query
multi_grep# OR across literal patterns · SIMD Aho-Corasick
 
# the README's ffgrep/fffind names are the Pi extension's — MCP registers the above

The system prompt (borrow this verbatim)

  • Search bare identifiers only — InProgressQuote finds the definition and every usage; struct ActorAuth narrows and misses enums/traits.
  • Never use regex unless you truly need alternation — .*/\d+ almost always return 0 within single lines.
  • Stop after 2 greps → READ the code. "More greps != better understanding." (token-spend discipline, encoded in the tool)
  • multi_grep for name variants — one call for ['ActorAuth','actor_auth'], not three greps.

Output is shaped for tokens too: frecency labels hot/warm/frequent, a "(NNKB — use offset)" coaching tag on big files, and def-body auto-expansion so results often answer without a follow-up Read.

The knowledge · under the hood

Why it's genuinely fast

  • Fuzzy path matching — neo_frizbee (the SIMD Smith-Waterman matcher behind blink.cmp, ~6× fzf), a 16-byte SIMD-chunk arena with cross-corpus chunk dedup, and an ~11-component score (base + frecency + git + distance + filename + combo + alignment).
  • Content grep, 3 modes — plain (SIMD memmem), regex (Rust regex, ripgrep's engine), fuzzy (Smith-Waterman per line → typo-resistant: shcema finds schema).
  • multi-pattern OR — SIMD Aho-Corasick: any of N patterns in one linear pass.
  • Frecency (Firefox 2008 idea) — LMDB store, 128 timestamps/file, exponential decay: 10-day half-life for humans, a sharper 3-day half-life in AI mode; git-touch warm-up.
  • Memory for speed — mimalloc, contiguous arena string storage, mmap content cache (~360 B/file → ~36 MB per 100k files). The RAM tradeoff is the mechanism.
  • Live index — a debounced background watcher (FSEvents/inotify/ReadDirectoryChangesW) talking to libgit2 directly, not spawning git.

One core, many surfaces: a stable C ABI, Node/Bun (Result<T>), Python (PyO3, abi3), Neovim (mlua) — with a real aiMode flag that switches grep parsing, decay, and output shaping for agents.

Read before piloting · honest caveats

The gaps, in plain view

  • "No traditional test suite" — the author's own AGENTS.md (limited unit + integration coverage) — a real gap for a correctness-critical library.
  • Benchmark is warm-vs-cold + author-stated, methodology unpublished, not independently replicated. Directionally fair for the resident-process case; treat the numbers as marketing.
  • Adoption is author-stated — README says "powers opencode, nushell"; a web check found community opencode plugins and no nushell reference.
  • RAM bites — cache accumulation (issue #437), scan-blocking (#477). Cap it with --max-cached-files.
  • Maturity — v0.9.x, nightly cadence, ~40% crate docs. A startup update-check network call (--no-update-check to disable). Pin a tag.
  • Correction (my own): Kovalenko authored date-io, not the MUI-X date pickers or react-imask (unconfirmed) — attribute only the confirmed projects.

Install is responsibly built, though: install-mcp.sh is pinned to v0.9.6 and SHA-256-checksums every platform binary before install, no sudo. Not a blind curl|bash.
