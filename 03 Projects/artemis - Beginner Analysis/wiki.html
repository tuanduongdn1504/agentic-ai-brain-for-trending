The rule

Nothing here is careless

This repository is rigorous about everything it can compute and silent or wrong about everything it can only assert — and because the assertions are unusually well written, they read as guarantees.

The computed parts are genuinely excellent; several are the best in twenty ships. The asserted parts are false in the specific way that good prose is false: nobody re-reads a sentence that already sounds right.

Which is which is predictable. Statements co-located with the thing they describe are correct — all twenty-one mobile-use attribution headers, living inside the files they describe, which is why they survived a revert aimed at something else. Statements living in a different file from their subject are wrong or gone: the CI claim in CONTRIBUTING.md, change-in-prod in a config, a 99% figure in a README describing a harness that had already been deleted — and a NOTICE that credited two upstreams from outside them, and took both down when one revert removed the file.

Severity, fairly

All artifacts were sha256-pinned throughout and uv verifies hashes. This was availability and internal-infrastructure disclosure, not an integrity compromise.

And the gate they finally wrote

It is very good — 68 stdlib-only lines so it can run before installation, checking the scheme as well as the host. But it is invoked at exactly one place tree-wide: inside python-quality, the only job that never installs npm. The two jobs that do run npm ci never call it, and there is no needs: to sequence them.

Finding 04 · the trust boundary

Described in detail, computed nowhere — and the description is the exploit

The operator prompt is 25,027 bytes of genuinely superior thinking about the agent not deceiving itself: “never write an action’s expected outcome as if it had already been observed”, “never construct state to satisfy” an assertion. Word counts in those bytes: password 0 · payment 0 · privacy 0 · personal 0 · refuse 0.

It is a magnificent document about truthfulness that contains nothing at all about harm — on an agent that taps a phone logged into mail, messages, photos and banking.

1
The prompt declares the screenshot “the primary source of truth”, and tells the model a --- User Guidance --- block in its observation “outranks the task plan”.
2
OCR and accessibility text enter that same observation with no escaping of the --- delimiters. Any app rendering that literal string issues a privileged instruction.
3
open_link — one of the twelve actions the model may emit — reaches execute_shell(f"… -d '{url}'") unescaped at unified_controller.py:224, while shlex.quote is used twice elsewhere in the codebase.
→
Text on the screen of an arbitrary app becomes arbitrary adb shell execution on the device.
And the absence is test-enforced

The only occurrence of the phrase “Untrusted Screen Content & Instruction Priority” anywhere in the tree is a unit test asserting it is not in the prompt — and the word trust is in the test’s own name. The fair reading is that the block existed in an internal build and this is a do-not-reintroduce guard. Either way a regression test now actively prevents the boundary from coming back.

And that test does not run on push or pull request. A test that forbids adding a safety boundary, which never executes.

Finding 05 · the fence

locked_app_package locks nothing, and the proof is one line

git grep "get_locked_app_package" over the entire repository, tests included, returns exactly one line: the def itself. Zero call sites. The lock is applied at launch and never again.

The sharpest detail

data_engine/engine.py:901-909 stamps the foreground package onto every recorded step, for the search surface. The value is measured every step, written to the database, and never once compared against the fence that exists to constrain it.

Pilot

Read and borrow. Install nothing.

✕Never cite the 99%+ AndroidWorld figure in any form. No harness, no dependency, no methodology, no model named.
✕Never point it at a phone holding real accounts. No untrusted-content boundary, no approval gate, and a documented escalation token.
✕Never rely on locked_app_package as a fence. Its accessor has zero call sites.
✕Never deploy playground/backend_manager/ as shipped — published JWT key, 123456 OTP bypass, Docker socket mounted into a root container.
✕Never assume its tests ran. They do not run on push or pull request.
✕Never wire it to candidate data. A screenshot pipeline over a phone is the worst possible surface for PII.
Worth taking

The shape of check_dependency_sources.py: walk the lockfile, assert the scheme as well as the host, and run before the install — a supply-chain check that runs after you have installed is theatre.

The anti-self-deception clauses into hireui/evals/METHOD.md — especially “take no extra actions for assert: lines and never construct state to satisfy one”, the best anti-gaming clause in the corpus. Take the negative lesson with it: a prompt can be rigorous about epistemics and completely silent about harm.

Blunt

A Google-owned repository, written almost entirely by one person in a month, built a device-control agent with a VLM that double-checks the target crop before a tap lands, a supply-chain gate better than anything in the last twenty ships, and an operator prompt so disciplined about self-deception it forbids the agent from claiming an outcome it has not observed.

Then it deleted its benchmark harness and added a 99% claim in the same commit; told contributors that pull-request CI runs a test suite it had switched off eighty minutes earlier; shipped a JWT signing key whose own value says change-in-prod; and wrote a unit test to keep the prompt-injection boundary out of the prompt — a test that never runs.

Every one of those failures is a sentence. Every one of the successes is a computation. The engineering is not the problem and the care is not in doubt — the problem is that this team, like most teams, proofreads its code and merely re-reads its prose.
