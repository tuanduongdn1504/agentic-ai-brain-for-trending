The wiki that maintains itself — for agents, not humans.

OpenWiki is a CLI that runs an autonomous documentation agent: it inspects your codebase and git history, writes an agent-readable wiki into your repo, wires it into AGENTS.md / CLAUDE.md, and keeps it current via a daily human-review PR. It is a productized, code-scoped version of this vault's own founding pattern.

what it is

One breath

“OpenWiki is a CLI that writes and maintains documentation for your codebase, built specifically for agents.” — README, verbatim · author: LangChain, Inc. (≈$1.25B; NOT Anthropic) · launched ~2026-07-01

The thesis: agents write better code when they understand the repo — but you don't want the whole repo in one giant instruction file. OpenWiki maintains a separate, linkable, agent-consumable knowledge layer that the instruction file merely points to. It is the closest commercial mirror of what this vault does by hand (Karpathy's LLM-Wiki pattern), pointed at source code instead of curated knowledge.

The system prompt IS the product. A ~130-line doc-authoring doctrine encoding grounding (“ground every claim in source or git evidence”), read-only subagents (default 1–2), a temporary plan file, git-heavy discovery, no-thin-pages, and a surgical update mode (a soft diff budget; may be a no-op). It's the single most borrowable artifact in the repo — liftable straight into a vault skill with zero install.

the maintenance loop

Diff-scoped updates, human-gated, no churn

A GitHub Action turns OpenWiki into a scheduled, unattended, human-review loop — the exact shape of the loop-engineering v189 discipline. It opens a PR; it never auto-commits to your default branch.

.github/workflows/openwiki-update.yml
# daily cron → inspect the diff since last run → open a review PR
on: { schedule: [ cron: "0 8 * * *" ] }
run: openwiki --update --print   # model: z-ai/glm-5.2 (cheap)
then: create-pull-request → branch openwiki/update

# the anti-churn guard (src/agent/utils.ts):
# SHA-256(openwiki/) before == after  →  no metadata write, no PR
+ metadata written ONLY if the docs actually changed

The content-snapshot no-op guard is the reusable gem: hash the whole openwiki/ tree before and after; write metadata (and open a PR) only if it changed. That is the concrete answer to “how do I run an agent on a daily cron without daily noise” — portable to any scheduled loop, including this vault's autopilot.
