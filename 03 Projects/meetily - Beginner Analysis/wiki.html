The notetaker domain is off-goal. The architecture underneath is the prize.

A consumer meeting-notetaker sits outside the vault's agent-substrate — so no §C mint (the TimesFM v193 / GLM-5 v176 off-domain-goal-adjacent discipline). But its provider-agnostic LLM client and templated map-reduce summarizer are a near-perfect blueprint for hireui's first LLM feature, and the app itself is a genuine privacy-first Scrum / recruitment notetaker.

What it is

One concrete subject, its audience, its single job.

Most meeting-AI tools send a bot into your call and upload everything to their cloud. meetily refuses both moves. It runs as a native desktop app, records the audio your machine already hears (microphone and system output, mixed), runs speech-to-text on-device, and only touches a network if you point the summary step at a cloud LLM — and even that's optional, since Ollama summarizes locally too. The pitch is data sovereignty: your sensitive discussions shouldn't live on servers you don't control.

One dispatcher, seven providers

The whole reason to read the source: generate_summary() in summary/llm_client.rs fans out to 7 providers through one clean match — the exact "vendor seam" pattern hireui's first LLM feature needs.

■ 5 providers share one OpenAI-chat code path (URL + Bearer header differ)  ·  ■ Claude gets its own shape (the 10% that's genuinely different)  ·  ■ local sidecar bails out before any HTTP. Abstract the 90%, special-case the 10%. That's the discipline.

A summarizer that survives long transcripts

Cloud + short transcripts get a single pass; local + long transcripts get a 3-pass map-reduce (summarize each chunk → synthesize → fill the template). Chunks reserve 300 tokens for prompt overhead and keep a 100-token overlap so nothing's cut mid-thought. A content fingerprint skips re-summarizing unchanged input; an English-summary cache means switching output language translates rather than re-summarizes. Templates are just JSON sections — daily_standup, retrospective, standard_meeting ship in the box.

Doc-vs-code nuances caught by hand Timeout is 300s but the error string still says "60 seconds." Claude's max_tokens is hardcoded to 2048 regardless of transcript size. Both minor, both real — worth knowing before a 2-hour meeting.

Corrected — "analytics on by default" An agent flagged enabled: true as a critical privacy discrepancy. Wrong: init_analytics() only fires when the frontend opt-in store is true, and it defaults to false with a forced-off migration. "Off by default" is accurate. The real (low) finding: the PostHog write-key is exposed in the public repo — standard for client SDKs, and meeting titles / paths / device names are stripped before send.

Landscape

Leader on Windows + simplicity; not the one to wire into an agent loop.

No single open-source winner. meetily leads on Windows parity, zero-setup, bot-free capture, MIT. Hyprnote / Anarlog leads on developer integration — it ships a CLI + REST API + MCP server; if you ever wanted a meeting assistant inside a Claude Code loop, that's the one, because meetily exposes no MCP. Screenpipe (SSPL) does broader 24/7 capture. Cloud tools (Otter, Fireflies, Fathom, tl;dv) win on convenience, lose on privacy.
