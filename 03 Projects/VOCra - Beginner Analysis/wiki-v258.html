The subtraction

VOCra never sends every frame to the OCR model. It crops to the subtitle region, compares consecutive frames with SSIM at a 0.95 threshold, and drops the near-identical ones, because a subtitle sits still for dozens of frames. Only the survivors cost money.

The README claims this removes up to 90%+ of duplicate frames. Nothing in the repository measures it — no counter, no log, no benchmark, searched across all 75 Python files, both Markdown files and the config.

That is not a video trick. It is the general shape, and it is the one genuinely new thing to take from this subject: put a cheap deterministic comparison in front of every expensive model call, and only pay for what is actually different.

the guard and the guarded arrived together

The .gitignore that commit removed had __pycache__/ on line 2 and *.py[codz] on line 3. The commit that deleted the ignore rule is the commit that added the first eighty files it named. Not an oversight in the ordinary sense — the guard was removed and the guarded files landed in the same change.

⚠️ This is not a story about someone shipping junk. The result of that commit is the current, cleaner architecture, and on several axes it is the best-built of the three siblings. It is a story about what survives a rewrite: the code was replaced deliberately, and the documentation, the ignore rule and the version file were casualties nobody came back for.

the correction that improved the ship

I attributed the surviving plan to the novels repo. It is VOCra's own file. Checking git ls-files '*.md' in all three clones settles it: the novels repo has exactly one Markdown file, its README, and has never had a planning document of any kind.

Which makes the last row measurable: the repository with the most written-down reasoning is the best-built one, and the repository with none is the worst-built one. Three points from one author is a hypothesis, not a law — but the mechanism is legible, because a plan fences the surfaces it names.

Code moves forward in time, never backward

The per-item alignment guard is traceable across all three repositories, so its travel can be measured rather than guessed.

  • Invented in the manga tool on 2026-05-15, in a commit titled New, raising on a mismatch between the number of items sent and returned and on any item whose index does not match its position.
  • Carried into VOCra, created eleven days later, with a near-identical error string — and in two further independent code paths.
  • Never reached the novels repo, which has zero alignment guards across all 47 of its Python files, and which was committed to six times after that date, including on the last recorded day of all three repositories.
the steelman, and it only partly holds

The novels tool is render-and-paste: a human carries the prompt to a chat model and pastes the reply back, so there is no in-process request object to compare against, and its button honestly says check syntax. A literal port is genuinely harder there.

But it renders a numbered batch and imports a JSON reply, so the count of returned items is checkable against the count sent — and it is not checked. The barrier is not architecture alone; it is that nothing in a copy-forward workflow ever runs in reverse.

The corollary is the transferable part: an improvement invented in project N reaches N+1 by copy-forward and never reaches N−1, because no shared library, package or dependency carries it back. The oldest repository keeps the oldest mistakes permanently, even while being actively edited.

the three-point contrast is exact

The manga tool wrote a stale-stage list into its cached JSON, surfaced it as a GUI warning, and enforced nothing — a message to a human. The novels tool had no staleness mechanism at all. This one deletes the artifacts and resets the flags.

So the repository with the most written-down reasoning is also the only one of the three that enforces its own invalidation — the same correlation as the planning documents, reached from a completely unrelated surface. The fleet found this one; I had not read that file.

The timeout is on the wrong call

burner.py invokes ffmpeg two ways. The short probe, _run_capture, is subprocess.run(…, timeout=timeout) — with timeout a required keyword-only parameter. The long-running video encode, _run_ffmpeg_stream, is a Popen followed by a bare process.wait() with no timeout at all.

the same shape as everything else here

The call that finishes in milliseconds is guarded by a mandatory timeout; the call that can run for hours has none. A stalled ffmpeg hangs the encode indefinitely. And this is not ignorance of the parameter — the author made it compulsory in the helper directly below. The discipline exists, and it was applied to the surface that did not need it.

The subsystem got better. Its bug rode along.

The OCR layer is the same code in two generations, so the comparison is exact: 1,342 lines of ad-hoc clients in the manga tool became 971 lines here, with a 19-line Protocol defining the provider contract and a 17-line factory that raises on an unknown provider. Same subsystem, third project, 28% smaller and an actual interface.

And subprocess.Popen(["sh", str(bat_path)]) — the POSIX shell invoked on a Windows .bat file — is present in both, unchanged. Refactoring moves the shape and copies the content, and a defect inside a function body is content.

Verdict: read and borrow one idea

GOAL-ALIGNED 3/4, and (b) moves down to MODERATE from last ship's STRONG — deliberately. The novels tool was an LLM-workflow system wearing a domain costume; strip the video away here and what remains is computer vision. The translator package is about 490 lines of 9,641. NO MINT on five grounds, decisively domain-not-capability and not-world-first: burned-in subtitle OCR is long-established territory, and a 3-star, 6-commit, 2.4-day repository claims neither novelty nor canonical status. Counts unchanged at 46/11.

The fences are unusual: the licence is a README sentence claiming MIT with no licence file, and there is no dependency manifest at all — seven unpinned packages in a pip install line. So the one file carrying the grant and the dependency set is also the file whose first element is a broken placeholder. Read it; write your own code.

Put a cheap deterministic filter in front of every expensive model call — then measure what it drops, because a dedupe stage that silently discards the input you needed is exactly the failure nobody notices.
