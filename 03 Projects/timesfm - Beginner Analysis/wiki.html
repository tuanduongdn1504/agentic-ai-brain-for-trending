TimesFM

A pretrained decoder-only foundation model for time-series forecasting. Feed it (almost) any series → get a zero-shot forecast with calibrated prediction intervals, no training. LLM pretraining, transplanted to numbers-over-time.

01 The two on-goal bridges

Why this isn't purely off-goal — and where the pilot value hides.

1 · It ships a first-party Claude Code Agent Skill

The repo carries AGENTS.md + timesfm-forecasting/SKILL.md — a genuine, well-built Agent Skill (cp -r timesfm-forecasting/ ~/.claude/skills/), auto-discovered by any agent on the open agentskills.io standard. It lands on the exact agent-skills substrate the vault studies. Same meta-move as v192 palmier-pro — a product retrofitted to be agent-native (palmier-pro bolted on MCP; TimesFM bolts on a skill + a Vertex "dockerized endpoint for agentic calling").

2 · The realistic use is agent-orchestrated

TimesFM isn't a tool an agent "calls" like a calculator. The real pattern: Claude Code orchestrates the pipeline — read schema → write query → forecast → backtest (MASE/MAPE) → gate on accuracy → open a PR. That is an autonomous-agent-for-software task, with TimesFM as one component.

02 Architecture — TimesFM 2.5

200M-param decoder-only transformer. Source-verified from src/timesfm/.

DimensionValueNote
Parameters200Mdown from 2.0's 500M
Layers · dims · heads20 · 1280 · 16head dim 80
Positional / normRoPE · RMSNormpre-LN, QK-norm, fused QKV
Input patch32one patch = one "token"
Output patch128> input → fewer autoregressive steps
Context limit16,3848× the 2.0 window
Quantiles10deciles q10–q90 + mean (idx 0 = mean)
BackendsPyTorch · Flax+ a HF -transformers checkpoint
CovariatesXRegin-context linear reg. (dynamic/static)

History → 32-point patches → residual-block tokenizer → 20 transformer layers (KV-cache) → point head + quantile head. Long horizons come from autoregressive decode in 128-point output patches. Reversible instance-norm scales each series by its own mean/std. Property: TimesFM(aX+b) = a·TimesFM(X)+b.

03 The API you'll actually use

Source-verified 2.5 API — not third-party approximations.

import torch, numpy as np, timesfm
torch.set_float32_matmul_precision("high")

# load a pretrained checkpoint (~800MB, cached in ~/.cache/huggingface)
model = timesfm.TimesFM_2p5_200M_torch.from_pretrained("google/timesfm-2.5-200m-pytorch")

model.compile(timesfm.ForecastConfig(
    max_context=1024, max_horizon=256,
    normalize_inputs=True,              # always True
    use_continuous_quantile_head=True,  # calibrated PIs
    infer_is_positive=True,             # clamp >=0 for counts
    fix_quantile_crossing=True,
))
point, quantiles = model.forecast(horizon=24, inputs=[series_a, series_b])
# point.shape     == (2, 24)      median / point forecast
# quantiles.shape == (2, 24, 10)  idx 0 = mean, 1 = q10, ... 9 = q90
footgun

quantiles[..., 0] is the mean, not q0. q10 = index 1, median = index 5, q90 = index 9.

06 Honest caveats

All source- or issue-verified. Mostly install-fragility, not security.

  • Univariate at heart — multivariate is a workaround (per-series models or XReg); Moirai-2.0 does it natively, TimesFM doesn't.
  • Needs contiguous, regularly-sampled history, no gaps — interpolate first, and bring enough of it. Short/sparse series are a poor fit.
  • jax[cuda] is hardcoded in the flax/xreg extras → CPU-only installs break (issue #443). On Apple Silicon, torch has lingvo/ARM issues → use the Flax backend.
  • CI is build-only — the 6 tests/ files exist but aren't run in main.yml.
  • 2 of 3 bundled skill examples are stale — the anomaly + covariates demos import the legacy 1.x API the current package no longer exports; only global-temperature uses the 2.5 API.
  • No in-repo training code (weights + inference + a LoRA fine-tune example). "Not an officially supported Google product."
supply chain

Benign. Apache-2.0, no postinstall / curl|bash / telemetry; ~800MB weight download from HuggingFace on first use. The real risks are install-fragility, not security.
