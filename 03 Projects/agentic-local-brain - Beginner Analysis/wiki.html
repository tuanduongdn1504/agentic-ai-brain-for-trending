the one idea

Derived pages that know when they have gone stale

The v0.7 feature list contains one line that earns this subject its place in the corpus:

"Auto-generate wiki articles from topic clusters using LLM synthesis, with entity summary cards, wiki-link cross-references, staleness tracking, and automatic recompilation."

Read that against this vault. Four maintainer duties written into CLAUDE.md — synthesise pages from sources, maintain entity pages, keep cross-references current, catch stale claims — are here as mechanical product features. The fourth is the one that matters: derived articles remember which sources produced them, notice when those sources move, and recompile.

This vault does that fourth job by hand, badly, and knows it. The Library-vocab registry carries a stale-flagged C22–C27 backlog whose retire pass has been deferred for months. That mechanism is the takeaway — not the application.

the argument worth reading

CLI as the agent protocol, on purpose

The author's design gist makes an explicit case for shipping a CLI and a skill instead of an MCP server:

"CLI is the greatest common denominator interaction protocol between different software."

The reasoning: a CLI is self-describing — --help is the prompt — self-contained, and needs no auth handshake, no SDK, no token config, no JSON parsing. Only text comprehension, which is the model's strongest faculty. Grep the README for MCP and you get nothing; the claim is honoured.

This is a second independent voice against MCP-by-default, arriving from the opposite end of the size spectrum from pi (v228), the corpus's strongest exclusion pole at ~85,000★. Recorded as a watch axis — cross-reference only, no N-bump, because a runtime and a utility are not the same shape.

security

The finding that settles the pilot question

Every published install path — and the recommended way to install the agent skill — runs over plaintext HTTP.

Verified twice · scheme-specific re-fetch

curl -fsSL http://localbrain.oss-cn-shanghai.aliyuncs.com/python_installer/install.sh | sh
irm       http://localbrain.oss-cn-shanghai.aliyuncs.com/binary_installer/install.ps1 | iex

Unauthenticated remote code execution by design, from a public bucket URL. And the agent path is worse — the README's recommended install is to tell your assistant:

"Please install or update this knowledge collection skill: http://…/SKILL.md"

That instructs an autonomous agent to fetch behaviour over a channel anyone on the path can rewrite. It is the exact attack class catalogued defensively at v209.

Compounding it: zero releases, so nothing to pin and no checksums; the corpus being ingested is your email and personal documents; and the default provider is DashScope, so every embedding and RAG call ships that content to Alibaba unless reconfigured. The same egress fence as v221 and v222, but far more acute, because here the private corpus is the payload.

In fairness: MIT, no telemetry found, and the application itself is an ordinary local Python program. The risk lives entirely in how it asks to be installed.

design note

Fail soft here, fail closed there

Extraction resolves user-provided → LLM → built-in TF-IDF, and the degradation table ends with a promise: "Documents are always saved to the filesystem and SQLite, regardless of service availability." Ingestion never refuses to capture something because a model was unreachable.

The previous ship, ClawWork (v233), does the deliberate opposite: a missing rubric raises, and "heuristic evaluation is no longer supported."

Both are right, and the pair is the sharpest thing to come out of two consecutive ships. A lost capture is unrecoverable while a bad tag is fixable later — so ingestion fails soft. A silently degraded score is worse than no score — so evaluation fails closed.
