## PRIMARY — NEW Library-vocab standalone: "AI Supply-Chain Inventory / AI Bill-of-Materials Generator (governance/compliance layer for the agentic stack)" — N=1 CORPUS-FIRST
- **Definition:** a tool whose output is a **standards-serialized inventory of the AI components in a codebase/infra** — agent frameworks, MCP servers, LLM providers, model references/files, API keys, cloud-AI services, containers — discovered by scanning, **risk-scored**, checked against compliance frameworks (EU AI Act / OWASP), and emitted as **SBOM-standard artifacts (CycloneDX 1.6 / SPDX 3.0 / SARIF 2.1.0)**. The AI/agent analogue of a software SBOM.
- **Why CORPUS-FIRST:** across ~156 wikis no prior subject *generates an AI-BOM*. The corpus has the **operate-your-agent-stack** family — provider-aggregation (#18 #8: v73/v112/v117), capability-provision-for-agents (v149 Scrapling), orchestration (v150 Paseo), account/quota mgmt (v153 ai-switcher), observability/metering (v89/v109/v154), ambient/affective status (v154/v155) — but **no governance/supply-chain-inventory layer.** ai-bom adds it.
- **Distinct from:**
  - **Pattern #66 supply-chain-*awareness*** — #66 is a *discipline* observed *within* other subjects (a repo scans its own deps, declares provenance); this is a **dedicated AI-BOM *generator* product** whose entire output is the inventory. (ai-bom is also the purest #66 instance — an N+1 observation, below — but the *generator* is the new standalone.)
  - **v140 google_workspace_mcp tool-tiers** — gates one server's tool registration; not an inventory.
  - **the agentskills.io 57k chain / skill collections** — skill libraries, not scanners.
  - **#20 Token-Economy-Quantification** — quantifies tokens, not AI components.
- **Direction (load-bearing):** ai-bom **detects/audits** the agent stack (lists the MCP servers/agents/providers it *finds*) — the **opposite direction** from v149 Scrapling (ships an MCP server so an agent can *use* it) and from the v153/v117/v73 management-GUIs (which *control* agents). It is the v154 "observes vs controls" distinction at the governance layer.
