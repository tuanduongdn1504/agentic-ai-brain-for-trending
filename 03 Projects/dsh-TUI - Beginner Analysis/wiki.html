What it is

package.json says it plainly: "Claude Code style interactive TUI front door for DeepSeek Harness agents, built on the ported Ink core." Not a program — a front door bolted onto someone else's agent. The install line is the host plus the plugin:

npm install -g @deepseek-ai/dsh @deepseek-harness-tui/dsh-tui
dsh-tui

Author "Chimney" (ccch1mneyyy), bio 「试图用ai做点东西~」 — trying to make something with AI. No disclosed name, employer, or location. ~1.7k★ / 74 forks, page-stated.

Finding one: it runs inside last ship's subject

The vault shipped v235 deepseek-ai/deepseek-harness four days earlier. Its entire thesis was "Everything is a Plugin" — models, tools, skills, sessions, storage, the agent loop, and the UI all hot-swappable on Cordis, whose defining capability is disposability.

v236 is a stranger doing exactly that, to the UI seam. The proof is a lockfile edge, not a claim: 21 peerDependencies, every one @deepseek-ai/* at ^0.1.0-rc.6 — including @deepseek-ai/cordis, the rescoped kernel v235 documented. That is the most machine-checkable form of corpus recursion the corpus holds. It also sits one prerelease ahead of the rc.5 recorded at v235: the promised breaking-change treadmill, visible in a version range.

ReplacesThe UI seam, and nothing else

  • Mounts via Cordis; entry point stays light, runtime loads lazily
  • Declares injection points + a config schema
  • Unified cleanup on dispose
  • "Zero core changes… uninstall leaves no core patches"

ConsumesEverything that matters

  • The official DSH agent, model, tool, session and persistence services
  • House rule: 「不要在组件中复制 DSH Agent、session 或 tool 服务」 — do not replicate them in components
  • Skills, MCP, subagents, Goals, Todos — surfaced, not implemented

Underneath that sits the finding worth keeping. v235 flagged append-only session logs as an architectural guarantee. dsh-TUI proves the guarantee is load-bearing: 「Channel 只保留适合当前 TUI 的投影」 — the Channel keeps only a projection, while the host's session/event log owns history replay, streaming, rewind boundaries, and reconstruction after resume or fork.

So an independent front end implements time-travel and forking while holding nothing authoritative of its own. That is the cleanest external validation of an append-only design the corpus has seen — and it is the one idea to steal.

It clones the architecture, not just the look. Claude Code's own TUI is — per third-party reverse-engineering, not Anthropic documentation — a React app on a heavily forked Ink renderer with a Yoga layout engine and ANSI diffing. dsh-TUI's pipeline: Cordis profile → plugin → DSH services → channel projection → components → ported Ink renderer + Yoga → terminal, with 「差分输出」 differential output, virtualised message lists on cached row heights, replay merging, and CJK/emoji cell-width handling. Tellingly, there is no ink dependency — but Ink's entire dependency set is present. Vendored and modified, exactly as Claude Code forked it.

The placeholders are the tell: someone catalogued the command surface and shipped its shell. The imitation is incomplete and says so. This extends the grok-build v215 primitive-convergence axis to the presentation layer — convergence now reaches the rendering stack and the keybindings.

Why no mint

A §C standalone was drafted — "third-party replacement UI layer mounted as a first-class plugin inside an agent runtime" — and declined. It is genuinely distinct on mechanism: CodePilot v161 wraps a CLI from outside; hermes-webui v227 is a separate server fronting an install; Codex-Dream-Skin v216 was unsanctioned CDP injection; DeepSeek-TUI v72 is a standalone client for DeepSeek models. None mount in-process through the host's own kernel.

It loses anyway, on four grounds: the v227 / v222 / v216 precedent chain treats front ends as form factors, not classes; §C vocabulary is capability-shaped and this adds no capability; §28 forbids minting on a delivery mechanism; and the anchor is one plugin among ~1,120 in a four-day-old ecosystem that already contains a rival UI plugin. Recorded as a deferred watch axis, not executed.

The v216 discriminator Codex-Dream-Skin was rated off-goal for being decoration with zero functional surface. dsh-TUI implements the whole interaction layer — session lifecycle, streaming reasoning, observability, rewind-and-fork, tool cards, completion. Functional agent UX, not a skin. That is why (b) is moderate rather than fail.

The honest weaknesses

  • The hard parts are not here. Agent loop, model, tools, session, persistence — all upstream in v235.
  • No end-to-end tests with real credentials. Author-stated: integration needs manual terminal verification. The verify:* suite checks structure and boundaries, not behaviour.
  • Pinned to a release candidate of a preview whose own README warns in bold of breaking changes.
  • Documented limits: injected context invisible; model switch is a fork, not an in-place swap; exit doesn't await persistence; three inert commands.
  • "Official recognition" is author-stated — featured in DeepSeek Harness's WeChat account as a "beta user selected plugin." Not web-verifiable.
  • Not source-cloned. Repo page, README, package.json, docs/architecture.md, profile, directories, landscape search.

The ecosystem nobody should miss

Searching for this plugin surfaced something larger than the plugin: a DSH plugin land-rush. Within days of v235's preview, ~1,120 plugins are listed across at least eight competing directory sites, several reading as automated aggregation, none disclosing an operator.

Provenance failure, caught by hand One of those directories lists dsh-TUI as v0.3.3, BSD-3-Clause. The repo and package.json say v0.8.0, MIT — stale version and wrong licence. The repo is authoritative (the Kilo Code v177 precedent). Read the repo; do not trust the aggregators, and do not install from them.

This cuts both ways. It revises v235's picture — ~19% ecosystem compatibility and reviewers advising a 3–6 month wait — because adoption is clearly moving faster than that number suggested. It is also a supply-chain warning: a thousand unvetted plugins for a release candidate, indexed by anonymous sites with demonstrably wrong metadata.

Pilot: read and borrow, do not install

Installing means a global npm install of a v0.8.0 plugin against a four-day-old release candidate, 21 rc peer deps, a prepare script, and PRC egress on the host's default models. The payoff is a prettier terminal for an agent you don't use.

  1. Read docs/architecture.md and the feature inventory above. Twenty minutes, zero install.
  2. Write the invariant into hireui's LLM ADR: the event log is the source of truth; the UI holds only a projection. Two consecutive ships now converge on this, and the ratified candidate-LLM legibility ADR already demands it.
  3. Steal verify:boundary / verify:patch-surface: encode an architectural boundary as a build gate rather than a paragraph.

That third point lands on a pattern: this is the third consecutive ship to hand the vault machinery for enforcing its own invariants — v234's staleness tracking, v235's doc-verification gates, now boundary gates. Three in a row pointing at the same unattended backlog is not a coincidence worth ignoring.
