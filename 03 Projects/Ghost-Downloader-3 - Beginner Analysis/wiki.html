What it is

A next-generation consumer download manager / accelerator with a Microsoft-Fluent-Design GUI — think IDM / aria2 / Motrix, in Python. Paste a URL or magnet, it splits the file into concurrent segments, shows live speed & ETA graphs. Built by an 18-year-old as their first Python project, originally to help a Bilibili creator grab media.

It is a human-facing desktop utility — not a library, SDK, agent, coding tool, or agent infrastructure.

The "AI-boost", examined

The claim

  • Tagline: "An AI-boost … concurrent downloader."
  • Feature line: "IDM-style intelligent chunking, plus AI smart acceleration 🚀".

The reality

  • README gives no technical definition of the "AI".
  • pyproject.toml has zero ML libraries.
  • It's adaptive chunking — a ~20-year-old download heuristic, rebranded.

→ AI-washing. A clean textbook case of "labeled AI, isn't AI" — a real-vs-marketing calibration example, not an AI/LLM/agent subject. No Claude / Anthropic / MCP / LLM / agent anywhere in the repo.

Actually well-engineered (c) STRONG

  • Multi-protocol: HTTP · Magnet/BT (libtorrent) · FTP · M3U8 · MPEG-DASH · eD2k · QUIC/HTTP3.
  • Async core: asyncio on uvloop / winloop; nuitka-compiled; Inno-Setup installer.
  • Parsers: YouTube · Bilibili (yt-dlp) · GitHub · HuggingFace; M3U8 live-recording (FFmpeg / N_m3u8DL-RE).
  • Anti-crawling: browser TLS-fingerprint emulation (wreq) — same technique class as camofox v179 / Scrapling v149, but for its own downloads (not agent-facing).
  • Surfaces: a TypeScript browser extension · an aria2-compatible RPC interface · Android companion · plugins coming.

Caveats: the hard bits are upstream libraries it orchestrates; solo bus-factor-1 first project; not source-cloned; stars page-stated → not a viral-velocity claim.
