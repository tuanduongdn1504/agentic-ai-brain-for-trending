## Key corrections baked in *(myths your earlier drafts contained — study the corrected version)*

- **`weak` vs `unowned` (the #1 gotcha):** `weak` = **Optional**, auto-set to **nil** when the referent deallocates. `unowned` = **non-Optional**, does **NOT** nil out, and **crashes** if accessed after dealloc. Use `weak` when the reference can become nil; `unowned` only when it provably can't.
- **Structs have value *semantics* — but are NOT always stack-allocated.** A struct captured by a closure or stored inside a class lives on the heap while keeping value semantics.
- **`CGFloat` ≡ `Double` on modern 64-bit** (typealias); since Swift 5.5 they're implicitly interchangeable.
- **`map()` on a `String` returns an `Array`; `filter()` on a `String` returns a `String`.** You cannot index a String with an `Int` — use `String.Index`.
- **`UIColor` components outside `0...1` aren't rejected** — they're stored (extended-range / Display P3) and clamped when rendered in sRGB.
- **`Result<Success, Failure>`** makes error handling explicit at compile time (vs exception-based JS).

## Swift ↔ React Native / JS — the transferable core

| Swift concept | JS / React Native parallel |
|---|---|
| Value vs reference types (struct/enum vs class) | primitives vs objects; `{...}` copy vs shared reference |
| ARC (compile-time retain/release) | Garbage collection (runtime, reachability) |
| Retain cycle → `[weak self]` | closure-captured refs leaking listeners → null them out |
| Optionals (`?`, `if let`, `guard let`, `??`) | `null`/`undefined`, optional chaining `?.`, nullish `??` |
| Protocols / protocol-oriented programming | TS interfaces; duck typing; composition |
| Closures / `@escaping` | callbacks; async completion; storing a function to call later |
| `Codable` (`JSONEncoder`/`JSONDecoder`) | `JSON.stringify` / `JSON.parse` + DTO types |
| `Result` type | `Promise` / try-catch (but exhaustive at compile time) |
| Delegates | props callbacks / event handlers |
| DI (constructor/property/method injection) | props, context providers, DI containers |
| SwiftUI (`@State`, declarative views, structs) | React (`useState`, JSX, components) |
| `map`/`filter`/`reduce`/`compactMap` | `map`/`filter`/`reduce`/`flatMap` |
| async/await (Swift 5.5+) | async/await (Promises) |

## 1. Accessibility

**Interviewer:** Bạn có bao nhiêu kinh nghiệm test với VoiceOver?

**Candidate:** Tôi thường bật VoiceOver trong Xcode simulator hoặc thiết bị thật (Settings > Accessibility > VoiceOver) để kiểm tra ứng dụng. VoiceOver cho phép user điều hướng bằng cử chỉ—swipe phải/trái qua element, double-tap để activate, hai ngón swipe up để đọc toàn màn hình. Khi test, tôi chắc rằng tất cả interactive element có accessibilityLabel rõ, chứ không relies on icon hay visual cues; nếu không, VoiceOver sẽ chỉ nói "button" mà không nói nó làm gì.

*RN: AccessibilityInfo API để enable screen readers; testID + accessible props tương tự accessibilityLabel.*

---

**Interviewer:** Bạn sẽ giải thích Dynamic Type cho một iOS developer mới như thế nào?

**Candidate:** Dynamic Type cho phép user thay đổi text size toàn hệ thống trong Settings > Display & Brightness > Text Size, từ Small đến Extra Large, và có thể kích hoạt Accessibility Sizes cho kích thước lớn hơn. Thay vì hardcode font, dùng `UIFont.preferredFont(forTextStyle: .body)` hoặc SwiftUI TextStyle modifiers, và luôn set `adjustsFontForContentSizeCategory = true` để element tự động scale khi user thay đổi cài đặt. Điều này rất quan trọng vì người lớn tuổi hoặc có thị lực yếu cần đọc content dễ hơn.

*RN: React Native không có built-in dynamic type; implement bằng native bridge để đọc font scale từ hệ thống.*

---

**Interviewer:** Những vấn đề chính mà chúng ta cần giải quyết khi làm accessible app là gì?

**Candidate:** Thứ nhất, **missing labels**—image, button, icon không có accessibilityLabel khiến screen reader không biết element đó dùng để làm gì. Thứ hai, **text scaling failure**—hardcode font size hoặc fixed layout height gây text overflow khi user enable Dynamic Type hoặc Accessibility Sizes. Thứ ba, **poor color contrast và gesture-only interactions**—màu chữ trên nền không đủ contrast (WCAG AA yêu cầu 4.5:1), và swipe gesture tùy chỉnh không có keyboard alternative khiến người dùng switch control không thể thực hiện hành động. Ngoài ra, video thiếu caption/audio description, và touch target quá nhỏ (< 44x44pt, hiện Apple khuyến cáo 48x48pt) cũng là vấn đề phổ biến.

*RN: testID/accessible props, responsive font scaling, WCAG contrast checker, keyboard navigation cho accessibility services.*

---

**Interviewer:** Những accommodation nào bạn đã thêm vào app để làm nó accessible hơn?

**Candidate:** Tôi thêm accessibilityLabel trên tất cả image, icon button, và interactive element không có text, và dùng accessibilityValue trên slider/progress để VoiceOver nói giá trị hiện tại. Dùng `.accessibilityElement(children: .ignore)` để group related element hoặc `.ignore` để loại decorative element ra khỏi VoiceOver. Cho text size, luôn dùng `UIFont.preferredFont(forTextStyle:)`, set `adjustsFontForContentSizeCategory = true`, test ở tất cả Dynamic Type size. Cũng đảm bảo touch target ít nhất 44x44pt, kiểm tra color contrast bằng tool, thêm keyboard shortcut via UIKeyCommand để mọi gesture có keyboard alternative, và announce state change bằng `UIAccessibility.post(notification: .announcement, argument:)`.

*RN: accessibilityLabel + accessible boolean, accessibilityValue, scale text dựa trên native font scale, 48x48pt minimum tap target, keyboard handler cho gesture alternative.*

## 2. Data

**Interviewer:** Dictionary khác array như thế nào?
**Candidate:** Dictionary lưu trữ cặp key-value không có thứ tự, cho phép tìm kiếm O(1) theo key. Array là collection có thứ tự, truy cập theo chỉ số với O(1). Dictionary yêu cầu key phải Hashable; array thì không. Chọn dictionary khi cần fast lookup by key, chọn array khi thứ tự hoặc sequential indexing quan trọng.
*RN: objects {} vs arrays [] trong JavaScript.*

**Interviewer:** Sự khác biệt chính giữa classes và structs trong Swift là gì?
**Candidate:** Classes là reference types (heap-allocated), support inheritance, dùng identity-based equality (`===`). Structs là value types với value semantics; lưu ý structs không phải luôn trên stack — khi bị capture bởi closure hay store trong class, struct vẫn nằm heap nhưng giữ value semantics. Structs không support inheritance nhưng conform protocols được.
*RN: tương tự class vs object, nhưng JS không phân biệt value/reference cơ bản.*

**Interviewer:** Tuple là gì và tại sao chúng hữu ích?
**Candidate:** Tuple là collection kích thước cố định với phần tử kiểu riêng ở vị trí cố định. Dùng tuple không tên `(Int, String)` hoặc có tên `(count: Int, name: String)`. Hữu ích khi return nhiều giá trị từ function, hay pattern matching sạch sẽ. Ví dụ: `let (x, y) = (10, "hello")`.

**Interviewer:** Codable protocol làm cái gì?
**Candidate:** Codable cho phép encode/decode type thành JSON (hoặc định dạng khác). Swift tự động synthesize Codable nếu tất cả properties cũng Codable. Dùng `JSONEncoder()` để biến object thành JSON data, `JSONDecoder()` để parse JSON back thành object.
*RN: tương tự JSON.stringify/JSON.parse trong JavaScript.*

**Interviewer:** Array và set khác nhau như thế nào?
**Candidate:** Array là ordered collection, cho phép duplicates, `contains()` là O(n). Set là unordered, phần tử duy nhất, `contains()` là O(1), yêu cầu phần tử Hashable. Dùng set khi cần membership check nhanh hoặc no duplicates; dùng array khi thứ tự quan trọng.
*RN: Set tồn tại trong ES6+ JavaScript.*

**Interviewer:** Sự khác biệt giữa Float, Double, và CGFloat là gì?
**Candidate:** Float là 32-bit, Double là 64-bit có độ chính xác cao hơn. Trên 64-bit hiện đại, CGFloat là typealias của Double; từ Swift 5.5 trở lên chúng implicitly interchangeable. Dùng Double by default; Float chỉ khi cần tiết kiệm memory (hiếm). CGFloat không phải kiểu riêng biệt trên 64-bit.

**Interviewer:** Tại sao key decoding strategies lại quan trọng khi dùng Codable?
**Candidate:** `JSONDecoder.KeyDecodingStrategy` transform tên key trong JSON thành tên property trong Swift. Ví dụ, API trả về `user_name` nhưng Swift property là `userName` — dùng `.convertFromSnakeCase` strategy để JSONDecoder tự convert. Điều này giảm boilerplate so với phải viết custom `CodingKeys`.

**Interviewer:** Khi dùng arrays, sự khác biệt giữa map() và compactMap() là gì?
**Candidate:** `map()` transform mỗi phần tử, trả về array cùng size (có thể chứa nil nếu transform trả nil). `compactMap()` transform rồi filter bỏ nil, array kết quả có thể nhỏ hơn. Ví dụ: `["1", "two", "3"].compactMap(Int.init)` trả về `[1, 3]` (bỏ nil từ "two"). Cả hai return Array.
*RN: tương tự map và flatMap (hoặc filter + map) trong JavaScript.*

**Interviewer:** Tại sao immutability lại quan trọng?
**Candidate:** Immutability đảm bảo thread-safety mà không cần lock, giá trị không thay đổi sau khi tạo. Code dễ reasoning vì không lo side effects; state dự đoán được. Value semantics của struct + immutability giúp tránh subtle bugs từ shared mutable state.
*RN: const trong JavaScript khuyến khích immutability, nhưng không enforce ở runtime.*

**Interviewer:** One-sided ranges là gì và khi nào dùng?
**Candidate:** One-sided ranges bỏ qua một endpoint: `5...` từ 5 tới cuối, `..<5` từ đầu đến 5 (exclusive). Dùng trong array subscripting (`array[5...]`), pattern matching (`if case 1...10 = x`), hoặc loop (`for i in 5...`). Syntax gọn và rõ ý đồ.
*RN: không có direct equivalent trong JavaScript.*

**Interviewer:** Điều gì được hiểu khi nói strings là collections trong Swift?
**Candidate:** String conform Collection protocol, nên bạn có thể iterate, filter, map, count như bất kỳ collection nào. Tuy nhiên, String.Index không phải Int mà là bidirectional index, vì Swift xử lý grapheme clusters (emoji + combining marks là một character). `"hello".map { ... }` trả về Array; `filter` cũng trả về Array (không phải String). Indexing string bằng Int là impossible — phải dùng String.Index hoặc Array conversion.
*RN: JavaScript strings cũng iterable, nhưng indexing bằng số rất đơn giản.*

**Interviewer:** UUID là gì, và khi nào bạn dùng nó?
**Candidate:** UUID (Universally Unique Identifier) là 128-bit identifier duy nhất toàn cầu. Tạo random UUID bằng `UUID()`, hoặc từ string `UUID(uuidString: "...")`. Dùng khi cần track objects trên devices, syncing data, hoặc unique ID không dành riêng cho database. Thường lưu ở `UserDefaults`, Core Data, hoặc gửi tới server.
*RN: tương tự crypto.randomUUID() trong Node.js.*

**Interviewer:** Sự khác biệt giữa value type và reference type là gì?
**Candidate:** Value type (struct, enum) được copy khi gán hoặc pass to function; mutations tạo instance mới, không ảnh hưởng bản gốc. Reference type (class) dùng chung instance qua references; mutations visible to tất cả references. Value types dễ reasoning vì không có unexpected mutations từ chỗ khác.

**Interviewer:** Khi nào bạn dùng Swift Result type?
**Candidate:** `Result<Success, Failure>` enum bắt buộc xử lý error rõ ràng. Bạn either `.success(value)` hoặc `.failure(error)`. Dùng trong completion handlers, async operations, hoặc chaining results. Ví dụ: `func fetch() -> Result<Data, NetworkError>` làm error handling explicit và compile-time safe.
*RN: Promise/async-await trong JavaScript tương tự nhưng exception-based.*

**Interviewer:** Type erasure là gì và khi nào dùng?
**Candidate:** Protocol với associated type không thể dùng làm concrete type (bạn không viết được `[MyProtocol]`). Type erasure dùng wrapper (thường `AnyXxx`) để ẩn concrete type. Ví dụ: `AnyPublisher<Output, Failure>` trong Combine cho phép return different publisher concrete types từ cùng function. Hữu ích khi accept multiple concrete types matching protocol nhưng không care cái nào.
*Ưu tiên thấp cho RN.*

## 3. Design patterns

**Interviewer:** Bạn có thể giải thích delegates cho một Swift developer mới không?
**Candidate:** Delegates là một design pattern cho phép một object (delegator) ủy thác các tác vụ nhất định cho một object khác (delegate). Delegator gửi các message tới delegate thông qua một protocol được định nghĩa trước, cho phép delegate quyết định cách xử lý. Ví dụ, UITableViewDelegate và UITableViewDataSource cho phép UITableView hỏi delegate về số rows, cell content, v.v. Đây là cách iOS xây dựng các callback mà không cần closures hoặc hardcoding logic.
*RN: React props callbacks và event handlers hoạt động tương tự — component cha truyền callback xuống con, child gọi nó khi cần.*

**Interviewer:** Bạn có thể giải thích MVC và cách nó được dùng trên Apple platforms không?
**Candidate:** MVC chia một ứng dụng thành ba phần: Model (dữ liệu, logic), View (UI), Controller (quản lý cả View và Model, xử lý input). Trên Apple platforms, UIViewController là controller điển hình, nó quản lý một View hierarchy và cập nhật data. MVC đơn giản nhưng có thể dẫn tới Massive View Controller nếu logic không được tách riêng. UIKit sử dụng MVC mặc định, trong khi SwiftUI khuyến khích MVVM hoặc các pattern khác.
*RN: React tương tự, nhưng ít cấu trúc hơn — thường là components (views) + state management (model logic).*

**Interviewer:** Bạn có thể giải thích MVVM và cách nó có thể được dùng trên Apple platforms không?
**Candidate:** MVVM tách Model, View, và thêm ViewModel — một layer giữ toàn bộ presentation logic và state cho View. View không trực tiếp access Model; nó bind tới ViewModel thông qua Combine publishers hoặc @Published properties. ViewModel có thể dễ test hơn vì không cần UIView. SwiftUI + Combine làm MVVM tự nhiên hơn nhờ @ObservedObject và @StateObject.
*RN: React state management libraries (Redux, Zustand) là tương đương — state holder độc lập với UI components.*

**Interviewer:** Bạn có thể giải thích dependency injection cho một junior developer không?
**Candidate:** Dependency injection (DI) là việc truyền các dependencies mà một object cần vào nó, thay vì object tự tạo chúng. Có ba cách: constructor injection (tham số init), property injection (set sau), method injection (truyền tới method cụ thể). DI làm code dễ test hơn vì bạn có thể inject mock dependencies. Ví dụ, nếu ViewController cần một APIClient, truyền nó vào init thay vì `let client = APIClient()` bên trong.
*RN: Tương tự — truyền props, context providers, hoặc dependency containers.*

**Interviewer:** Bạn có thể giải thích protocol-oriented programming cho một Swift developer mới không?
**Candidate:** Protocol-oriented programming (POP) dùng protocols thay vì class inheritance làm primary building block. Protocols định nghĩa requirements mà bất kỳ type nào (struct, class, enum) có thể conform tới. POP khuyến khích composition thay vì hierarchy, tránh deep class inheritance chains. Protocols cũng hoạt động tốt với structs (value types), khiến code an toàn hơn.
*RN: Tương tự duck typing — TypeScript interfaces hoặc protocol-like patterns; JavaScript tự nhiên hỗ trợ composition.*

**Interviewer:** Bạn có kinh nghiệm gì với functional programming?
**Candidate:** Swift hỗ trợ functional programming tốt — map, filter, reduce, flatMap cho phép transform data mà không mutate original. Functional style khuyến khích immutability và function composition, ví dụ `let doubled = [1,2,3].map { $0 * 2 }` thay vì vòng lặp imperative. Combine framework là ví dụ của functional reactive programming — các pipelines của operators biến đổi giá trị theo thời gian. Functional approach làm code dễ lý luận và test hơn.
*RN: JavaScript/TypeScript tự nhiên functional — map, filter, reduce, rest parameters, higher-order functions là cơ bản.*

**Interviewer:** Bạn có thể giải thích KVO và cách nó được dùng trên Apple platforms không?
**Candidate:** KVO (Key-Value Observing) cho phép một object quan sát thay đổi trong property của một object khác mà không cần callback trực tiếp. Khi observed property thay đổi, observer nhận notified thông qua `observeValue(forKeyPath:of:change:context:)`. KVO là UIKit-era pattern; hôm nay Combine @Published và SwiftUI @ObservedObject là cách hiện đại hơn vì dễ dùng và không cần tự unsubscribe.
*RN: useState, useEffect đơn giản hóa việc watch/react tới thay đổi.*
*Ưu tiên thấp cho RN.*

**Interviewer:** Bạn có thể cho ví dụ nơi singletons có thể là một ý tưởng tốt?
**Candidate:** Singletons hữu ích khi bạn cần một single shared instance trong suốt lifetime của app. Ví dụ: URLSession.shared (network requests), FileManager.default (file operations), UserDefaults.standard (user preferences), AppDelegate (app lifecycle), NotificationCenter.default. Cảnh báo: singletons khó test vì shared state và khó reset, nên tốt nhất là dùng chúng cho infrastructural services, không phải domain logic.
*RN: Singletons hoặc global state — nhưng state management libraries (Redux, Zustand) thường preferrable cho test.*

**Interviewer:** Phantom types là gì và bạn sẽ dùng nó khi nào?
**Candidate:** Phantom types là types có type parameters không xuất hiện trong actual value — chúng tồn tại để cung cấp compile-time guarantees. Ví dụ, `struct Validated<T>` có thể không lưu bất kỳ "marker" data nào, nhưng type itself signals rằng giá trị đã được validate. Phantom types cho phép make invalid states unrepresentable — ví dụ, `struct ApiRequest<Authorized>` vs `struct ApiRequest<Unauthorized>` chỉ khác ở type level, nhưng compiler có thể đảm bảo chỉ Authorized requests được gửi.
*RN: TypeScript branded types gần giống — `type Validated<T> = T & { readonly __brand: "Validated" }`.*
*Ưu tiên thấp cho RN.*

## 4. Frameworks (part 1)

**Interviewer:** CloudKit khác gì Core Data?

**Candidate:** CloudKit là một framework cho phép bạn lưu và đồng bộ dữ liệu qua iCloud, hỗ trợ multi-device synchronization; Core Data là một local object-relational mapping (ORM) framework cho persistence trên thiết bị. CloudKit phù hợp khi bạn muốn dữ liệu đồng bộ qua devices, trong khi Core Data tốt hơn cho dữ liệu hoàn toàn local; bạn có thể kết hợp cả hai—lưu vào Core Data locally và đồng bộ lên CloudKit.

*RN: React Native không có CloudKit native; thay vào đó bạn thường dùng Firebase Realtime Database hoặc một REST API cho sync.*

---

**Interviewer:** SpriteKit khác gì SceneKit?

**Candidate:** SpriteKit là framework cho 2D games, với node-tree hierarchy và 2D physics engine; SceneKit là framework cho 3D graphics, lighting, animations, và complex 3D scenes. SpriteKit dùng SKNode, SKSpriteNode; SceneKit dùng SCNNode, SCNGeometry, và có perspective cameras và materials.

*Ưu tiên thấp cho RN; most mobile apps không cần game frameworks này.*

---

**Interviewer:** Bạn có kinh nghiệm dùng Core Data không? Có thể cho ví dụ không?

**Candidate:** Có, tôi đã dùng Core Data để lưu user data locally—ví dụ một ứng dụng todo hoặc contact app. Tôi tạo NSManagedObject subclasses, tạo fetch requests để query dữ liệu, và dùng NSFetchedResultsController để bind dữ liệu vào UI và handle updates. Ví dụ tôi dùng Core Data để lưu một list các items, mỗi item có title, date, completed flag, rồi fetch và filter chúng theo status.

*RN: React Native dùng AsyncStorage (key-value, không relational) hoặc thư viện như SQLite hoặc Realm cho persistence.*

---

**Interviewer:** Bạn có kinh nghiệm dùng Core Graphics không? Có thể cho ví dụ không?

**Candidate:** Có, tôi đã dùng Core Graphics để vẽ custom shapes và lines—ví dụ vẽ một pie chart bằng cách vẽ arcs, hoặc vẽ một signature pad bằng cách tracking touches và vẽ line segments. Ví dụ khác là custom UIView subclass với override `drawRect(_:)` để vẽ rectangles, circles, hoặc text với fonts và colors cụ thể.

*RN: React Native dùng SVG hoặc Canvas-like APIs; custom drawing phức tạp thường dùng native modules hoặc Skia-based libraries.*

**Interviewer:** Có những cách nào để hiển thị web content cho users?

**Interviewer:** Điều gì xảy ra khi Color hay UIColor có giá trị ngoài 0 đến 1?
**Candidate:** UIColor chấp nhận component values ngoài 0...1 mà không reject. Các giá trị này được lưu trữ dưới dạng extended-range (Display P3 hoặc wider color spaces). *RN: Like CSS allowing color values outside the standard range; iOS clamps them during rendering based on display capability.*

## 8. Performance

**Interviewer:** Làm cách nào để bạn xác định và giải quyết một retain cycle?
**Candidate:** Một retain cycle xảy ra khi hai hay nhiều object giữ strong reference tới nhau, ngăn deallocation. Để xác định: dùng Memory Graph Debugger (Debug > View Memory Graph) để visualize reference counts; tìm các mũi tên vòng tròn. Để giải quyết: dùng `weak` cho references có thể thành nil (delegates, observers) hoặc `unowned` khi reference sẽ không bao giờ outlive owner—nhưng KHÔNG bao giờ dùng unowned trừ khi bạn 100% chắc object sẽ không deallocate khi còn referenced. Ví dụ: ViewController giữ closure capture self, dùng `[weak self] in` để break cycle.
*RN: JavaScript dùng garbage collection; circular references vẫn leak memory—nullify listeners hoặc dùng weak refs.*

**Interviewer:** Cách hiệu quả nào để cache dữ liệu trong bộ nhớ?
**Candidate:** Dùng NSCache cho simple key-value caching; nó thread-safe và tự động evict objects dưới memory pressure. Để control tốt hơn, wrap Dictionary trong DispatchQueue để thread-safe access. Ví dụ: `let cache = NSCache<NSString, UIImage>()` để cache images. Cho computations expensive, cân nhắc memoization với Dictionary keyed by input params. Không bao giờ cache với plain retained Dictionary vì nó sẽ ignore memory warnings.
*RN: Dùng React Query, Apollo cache, hoặc Map with manual cleanup; web có IndexedDB hoặc localStorage.*

**Interviewer:** Những bước nào để xác định và giải quyết vấn đề battery life?
**Candidate:** Xác định: dùng Xcode's Energy Impact gauge (Organizer tab) và Profile > System Trace để detect CPU, GPU, networking, background-task usage dư thừa. Giải quyết: optimize background tasks với BGTaskScheduler (batch work, không real-time), giảm Core Location polling frequency, disable auto-refresh khi invisible, batch network requests, dùng URLSessionConfiguration.waitsForConnectivity, disable Bluetooth/WiFi scans không cần thiết. Measure trước/sau với Energy Impact.
*RN: Dùng AppState để pause work khi backgrounded; minimize networking và CPU work; dùng appropriate intervals cho location.*

**Interviewer:** Những bước nào để xác định và giải quyết crashes?
**Candidate:** Xác định: dùng Xcode console + breakpoints, hoặc on-device trong Settings > Privacy > Analytics để view crash logs. Tools: Instruments (Zombies để catch use-after-free), Memory Graph cho leaks, Address Sanitizer (Scheme > Diagnostics). Giải quyết: decode symbolicated crash logs (Xcode tự động), trace stack tới faulting line, fix root cause (thường là nil unwrap, out-of-bounds, race conditions), thêm unit tests.
*RN: Dùng React Native Debugger, Flipper, hoặc Sentry; crashes thường là JS exceptions hoặc native module misuse.*

**Interviewer:** Swift xử lý memory management như thế nào?
**Candidate:** Swift dùng Automatic Reference Counting (ARC): compiler insert retain/release calls tại compile time để track ownership. Khi retain count của object về zero, ARC deallocate ngay. Value types (struct, enum) được copy, không reference-counted. Cho reference types (class), bạn quản lý ownership via strong (default), weak (auto-nils on dealloc), và unowned (non-nil, crashes nếu access sau dealloc). Closures capture variables; capture lists control weak/unowned.
*RN: JavaScript dùng garbage collection; không manual memory management, nhưng vẫn leak khi circular refs trong closures.*

**Interviewer:** Làm cách nào để giải thích ARC cho developer mới?
**Candidate:** ARC là compile-time memory-management system: mỗi object track bao nhiêu phần code hold reference tới nó (retain count). Khi tạo reference, ARC tăng count; khi release (end of scope, assign nil), ARC giảm. Khi count về zero, object deallocate ngay. Bạn không call retain/release manual—compiler insert. Rủi ro: retain cycles, A → B và B → A, counts không bao giờ về zero; break với weak hoặc unowned.
*RN: Giải thích garbage collection thay: GC periodically scan unreachable objects và free chúng.*

**Interviewer:** Những bước nào để xác định và giải quyết memory leak?
**Candidate:** Xác định: chạy app với Memory Graph Debugger (Product > Profile > double-click Memory Graph). Tìm purple "Leaked Object" badges và cycle warnings (circular arrows). Dùng Instruments > Leaks để track object lifetimes. Giải quyết: break cycles với weak/unowned, đảm bảo delegates/observers unregistered (NotificationCenter.default.removeObserver), close file handles và network connections, check closures cho unintended self captures.
*RN: Dùng Chrome DevTools hoặc Flipper inspect object graphs; profile với heap snapshots để find persistent refs.*

**Interviewer:** Những bước nào để xác định và giải quyết performance issues?
**Candidate:** Xác định: dùng Instruments (Time Profiler cho CPU hot spots, Core Animation cho frame drops, Core Data cho slow queries, Leaks cho memory). Profile trên real device, không simulator. Check frame rate (target 60 FPS, 120 trên ProMotion). Giải quyết: optimize slow loops, cache computed values, dùng lazy properties, offload work tới background threads với DispatchQueue, reduce view hierarchy depth, optimize UITableView/UICollectionView cell reuse. Measure before/after profile để validate fix.
*RN: Profile với React DevTools Profiler, Chrome DevTools, hoặc Flipper; focus re-render counts, JS thread blocking, bridge traffic.*

## 9. Security

**Interviewer:** Bạn có kinh nghiệm sử dụng Face ID hoặc Touch ID không? Có thể cho ví dụ cụ thể?

**Candidate:** Bạn sử dụng framework LocalAuthentication để request biometric auth từ người dùng. Bạn tạo một LAContext, gọi `evaluatePolicy(_:localizedReason:reply:)` với `.deviceOwnerAuthenticationWithBiometrics`, và xử lý kết quả trong completion handler. Ví dụ: nếu người dùng xác thực thành công khi unlock một feature có phí, bạn lưu một access token vào Keychain để phiên tiếp theo không cần request lại. Bạn cũng nên check `biometryType` để hiển thị UI phù hợp (Face ID vs Touch ID).

*RN: react-native-biometrics wraps LocalAuthentication; under the hood it calls evaluatePolicy() identically.*

---

**Interviewer:** Bạn sẽ giải thích App Transport Security (ATS) cho một iOS developer mới?

**Candidate:** ATS là bảo mật mặc định trong iOS 9+ yêu cầu tất cả HTTP connections phải dùng HTTPS với TLS 1.2+ và các cipher suites mạnh. Bạn configure nó trong Info.plist bằng dictionary `NSAppTransportSecurity`. Nếu bạn cần kết nối tới HTTP endpoint (ví dụ localhost dev server), thêm `NSExceptionDomains` với tên domain và set `NSIncludesSubdomains = true`, `NSExceptionAllowsInsecureHTTPLoads = true` cho domain đó. Ở production, luôn dùng HTTPS vì ATS bảo vệ người dùng khỏi man-in-the-middle attacks.

*RN: Networking libraries (Axios, fetch) on iOS respect ATS policy; violations cause SSL errors identical to native code.*

---

**Interviewer:** Bạn có kinh nghiệm sử dụng Keychain không?

**Candidate:** Keychain là secure storage cho passwords, tokens, và sensitive data. Ở iOS 11+, dùng CryptoKit hoặc `SecItemAdd`/`SecItemCopyMatching` từ Security framework. Để lưu một authentication token: gọi `SecItemAdd` với dictionary chứa `kSecClass: kSecClassGenericPassword`, `kSecAttrAccount: "user@example.com"`, `kSecValueData: tokenData`. Để retrieve, gọi `SecItemCopyMatching` với query dictionary tương tự. Một cách đơn giản hơn là dùng library như KeychainAccess (third-party Swift) hoặc Apple's Credential Manager.

*RN: react-native-keychain wraps SecItemAdd/SecItemCopyMatching; never store secrets in AsyncStorage (plaintext).*

---

**Interviewer:** Bạn sẽ tính secure hash value cho dữ liệu như thế nào?

**Candidate:** Dùng CryptoKit framework (preferred, từ iOS 13+). Import CryptoKit, tạo instance của hash algorithm như `SHA256`, call `update(data:)` với byte data, gọi `finalize()` để lấy digest. Ví dụ: `let digest = SHA256.hash(data: myData); let hashString = digest.map { String(format: "%02hhx", $0) }.joined()` để convert thành hex string. Nếu cần hỗ trợ iOS < 13, dùng CommonCrypto từ Security framework, nhưng CryptoKit được khuyên dùng. Luôn dùng SHA256 trở lên; MD5 và SHA1 không còn secure.

*RN: crypto-js or TweetNaCl.js in JavaScript; both produce identical SHA256 hashes if encoding matches (ensure UTF-8).*

## 10. Swift language (part 1)

**Interviewer:** Làm cách nào để so sánh hai tuples để đảm bảo các giá trị của chúng giống hệt nhau?
**Candidate:** Tuples tự động conform to Equatable nếu tất cả các phần tử của chúng conform to Equatable. Bạn có thể sử dụng toán tử == để so sánh trực tiếp: `let t1 = (1, "a"), t2 = (1, "a"); t1 == t2 // true`. Không cần tạo hàm so sánh tùy chỉnh trừ khi tuples chứa các phần tử không conform to Equatable.
*RN: Trong JS, phải so sánh từng phần tử hoặc sử dụng JSON.stringify().*

**Interviewer:** Làm cách nào để giải thích operator overloading cho một nhà phát triển junior?
**Candidate:** Operator overloading là viết lại cách các toán tử (như +, ==, <) hoạt động với custom types bằng cách định nghĩa static functions có tên là toán tử đó. Ví dụ, `static func +(left: Vector, right: Vector) -> Vector` cho phép cộng hai Vector. Điều này làm cho code trực quan hơn khi làm việc với domain-specific types.
*RN: JavaScript không hỗ trợ operator overloading; dùng helper functions hoặc method chaining.*

**Interviewer:** Làm cách nào để giải thích protocols cho một lập trình viên Swift mới?
**Candidate:** Protocol là một hợp đồng (contract) mô tả các property và method mà một type phải cung cấp nếu conform. Ví dụ, protocol Drawable yêu cầu method `draw()`; bất kỳ struct, class hay enum nào conform phải cài đặt nó, nhưng cách thực hiện tùy từng type. Protocols là cơ sở cho polymorphism và loose coupling.
*RN: Giống TypeScript interfaces hoặc abstract classes—định nghĩa hình dạng của một object.*

**Interviewer:** Trong trường hợp nào các function Swift không cần return keyword?
**Candidate:** Các function với single-expression body (không dấu ngoặc nhọn) tự động return kết quả: `func double(_ x: Int) -> Int { x * 2 }`. Ngoài ra, functions có return type Void không cần explicit return statement. Nếu function có ngoặc nhọn, phải sử dụng return để trả về giá trị.
*RN: Arrow functions trong JS với implicit return: `const double = x => x * 2`.*

**Interviewer:** Property observers là gì?
**Candidate:** Property observers là closures (willSet, didSet) chạy trước hoặc sau khi property thay đổi, cho phép phản ứng với sự thay đổi mà không override toàn bộ property. `var name: String { didSet { print("Tên đổi thành \(name)") } }` cập nhật UI khi name thay đổi. Observers chỉ có sẵn trên stored properties.
*RN: Property setters trong class hoặc useEffect hooks trong React.*

**Interviewer:** Raw strings là gì?
**Candidate:** Raw strings dùng cú pháp `#"..."#` và coi backslash như ký tự literal, không phải escape sequences. Hữu ích cho regex patterns, file paths, hoặc JSON: `let regex = #"\\d+"#` chứa literal backslash. Có thể thêm # bổ sung để tăng độ sâu.
*RN: String.raw hoặc template literals—`String.raw\`\\d+\` hoặc /\\d+/ cho regex.*

**Interviewer:** Directive #error compiler làm gì?
**Candidate:** `#error("message")` dừng compile lại và hiển thị thông báo lỗi tuỳ chỉnh. Rất hữu ích ngăn code không hoàn thiện ship sang production. Đây là compile-time error, không phải runtime error.
*RN: TypeScript errors hoặc throw Error() tại runtime—không có tương đương compile-time.*

**Interviewer:** #if swift syntax làm gì?
**Candidate:** `#if swift(>=5.5) ... #endif` conditionally compiles code dựa trên phiên bản Swift; code chỉ bao gồm nếu điều kiện đúng. Cho phép hỗ trợ nhiều phiên bản Swift và dùng tính năng mới an toàn khi tương thích với phiên bản cũ hơn.
*RN: Environment variables (NODE_ENV) hoặc feature flags tại runtime.*

**Interviewer:** Hàm assert() làm gì?
**Candidate:** `assert(condition, "message")` kiểm tra một điều kiện và crash app trong debug builds nếu false; toàn bộ assert bị loại bỏ trong Release builds để tối ưu hiệu suất. Là công cụ phát triển bắt lỗi logic sớm, không phải cơ chế xử lý lỗi production.
*RN: console.assert() ghi log nhưng không crash—unit tests hoặc throw Error() là gần nhất.*

**Interviewer:** Compiler condition canImport() làm gì?
**Candidate:** `canImport(FrameworkName)` kiểm tra tại compile-time xem framework có sẵn không. Dùng để conditionally import modules cho platform khác nhau: `#if canImport(UIKit) ... #endif` cho code chỉ iOS, không watchOS.
*RN: Conditional requires hoặc feature detection tại runtime.*

**Interviewer:** CaseIterable protocol làm gì?
**Candidate:** CaseIterable tự động synthesize static property `allCases` trả về array tất cả enum cases. Cho phép lặp qua các cases hoặc đếm chúng: `enum Color: CaseIterable { case red, green, blue }; Color.allCases.count // 3`.
*RN: Manual enum object với a .values array, hoặc const + Object.values() trong TypeScript.*

**Interviewer:** Từ khóa final làm gì, và tại sao dùng nó?
**Candidate:** final trên class hoặc method ngăn chặn subclassing hoặc overriding. Dùng khi chắc chắn subclassing không an toàn hoặc phá vỡ bất biến lớp: `final class SecureHandler { ... }`. Cũng cho phép compiler tối ưu hóa aggressively vì không có subclass.
*RN: final là compile-time ở Swift; JS/TS dựa vào documentation và private# fields.*

**Interviewer:** Nil coalescing operator làm gì?
**Candidate:** `optional ?? default` trả về giá trị của optional nếu không nil, nếu không trả về giá trị mặc định. Là cách ngắn gọn cho `optional != nil ? optional! : default`: `let name = userInput ?? "Guest"`. Giảm nesting và dễ đọc hơn.
*RN: `optional || default` hoặc `optional ?? default` trong hiện đại JavaScript/TypeScript.*

**Interviewer:** Sự khác biệt giữa if let và guard let là gì?
**Candidate:** if let unwraps optional chỉ bên trong scope của if block (dẫn đến nesting). guard let unwraps optional và exit sớm nếu nil, giữ biến unwrapped trong scope hiện tại, giảm nesting. guard let được ưu tiên cho nhiều unwraps hoặc khi "happy path" là main logic.
*RN: if (const val = optional) { ... } là JavaScript mới; guard giống early return với `if (!val) return`.*

**Interviewer:** Sự khác biệt giữa try, try?, và try! trong Swift là gì?
**Candidate:** try yêu cầu xử lý error bằng do-catch hoặc propagating; try? chuyển error thành nil (trả về optional), bỏ chi tiết error; try! force-unwraps kết quả và crashes nếu error xảy ra. Dùng try? khi không cần chi tiết error; tránh try! trừ khi absolutely chắc chắn.
*RN: await với try-catch, hoặc .catch((err) => null) cho try?—không có try! analogue.*

**Interviewer:** Optional chaining giải quyết vấn đề gì?
**Candidate:** Optional chaining (`obj?.prop?[index]?.method()`) an toàn gọi properties hoặc methods trên optionals. Nếu bất kỳ link nào nil, toàn bộ expression trả về nil thay vì crashing. Cho phép code defensive mà không unwrap từng optional hoặc nested ifs.
*RN: Optional chaining (`obj?.prop?.method?.()`) trong TypeScript 4.0+; fallback là `obj && obj.prop && obj.prop.method()`.*

**Interviewer:** Sự khác biệt giữa String? và String! trong Swift là gì?
**Candidate:** String? là optional String (giá trị hoặc nil); String! là implicitly unwrapped optional (tự động unwrap, nhưng crash nếu nil). String! hiếm khi cần thiết và thường là code smell—dùng String? với guard let hoặc if let thay thế. Implicitly unwrapped chỉ hữu ích với outlets hoặc guaranteed non-nil sau initialization.
*RN: `string | null | undefined` vs `string!` (non-null assertion, đều nhau nguy hiểm).*

**Interviewer:** Khi nào sử dụng keyword guard trong Swift?
**Candidate:** Dùng guard để unwrap optionals và exit sớm nếu nil, hoặc kiểm tra preconditions. guard giảm nesting so với if let và làm "happy path" rõ ràng: `guard let user = currentUser else { return }; processUser(user)`. Hữu ích cho xác thực input ở đầu function—nếu thất bại, return/throw ngay.
*RN: Early returns với `if (!val) return;` hoặc `if (val == null) throw Error()` trong JavaScript.*

**Interviewer:** Ngoài các property wrappers built-in, cho một ví dụ về property wrappers không?
**Candidate:** @Clamped wraps numeric property và clamps giá trị thành range khi set: `@Clamped(0...100) var score: Int`. @Uppercased wraps String và auto-capitalize khi set. @UserDefaults wraps value và backs nó với UserDefaults, persist dữ liệu qua sessions. Encapsulate logic lặp lại, làm code sạch hơn.
*RN: Class getters/setters hoặc Proxy objects—React dùng custom hooks.*

## 11. Swift language (part 2)

**Interviewer:** Can you give useful examples of enum associated values?

**Candidate:** Associated values let an enum case carry additional data. `enum Result<T, E> { case success(T), failure(E) }` wraps a value or error; `enum UIControl.Event` bundles specific UI events; `enum Payment { case creditCard(number: String, cvv: String), applePay(token: String) }` models payment methods with their details. Each case can hold different types and counts of data.

*RN: Like union types with attached data—similar to `type PaymentMethod = { type: 'creditCard', number, cvv } | { type: 'applePay', token }`.*

---

**Interviewer:** How would you explain closures to a new Swift developer?

**Candidate:** Closures are blocks of executable code you can pass as arguments, store in variables, or return from functions. They capture variables from their enclosing scope (value or reference). `let double = { $0 * 2 }` is a simple closure; closures in trailing position let you write `DispatchQueue.main.async { print("done") }` naturally. They're first-class values in Swift.

*RN: Closures are Swift's answer to JavaScript callbacks/arrow functions—they capture scope and can be passed around.*

---

**Interviewer:** What are generics and why are they useful?

**Candidate:** Generics let you write type-safe code that works with any type, using type parameters like `<T>`. `func first<T>(_ array: [T]) -> T?` works for any array; `struct Stack<T>` is reusable for any element type. Generics eliminate repetition, keep compile-time type checking, and avoid the need for casting or Any.

*RN: TypeScript generics (`function identity<T>(x: T): T`) solve the same problem—code that works for any type while staying type-safe.*

---

**Interviewer:** What are multi-pattern catch clauses?

**Candidate:** You can catch multiple error patterns in a single case using commas: `catch NetworkError.timeout, NetworkError.noConnection { }` handles both. You can also use pattern matching: `catch let error as NetworkError where error.code == 404 { }` adds conditions. This reduces repetition and groups related error handlers together.

*RN: Similar to JavaScript's pattern matching or catching multiple error types in a single catch block (though JS doesn't have pattern-matching syntax natively).*

---

**Interviewer:** What does the @main attribute do?

**Candidate:** `@main` marks the entry point of an executable program, replacing the need to write a top-level `main()` function. You apply it to a struct or class: `@main struct MyApp { static func main() { print("Start") } }`. Only one `@main` entry point is allowed per executable; SwiftUI's `@main` app uses a protocol to boot the app.

*RN: Ưu tiên thấp cho RN—this is specific to executable targets, not app frameworks.*

---

**Interviewer:** What does the #available syntax do?

**Candidate:** `#available(iOS 14, *)` checks if a specific OS version is available at compile time. Code inside the if block compiles only for that version or later; the `*` is a catch-all for other platforms. `@available(iOS 14, *)` marks a declaration as available only from that version. It enables you to use new APIs safely without runtime crashes on older versions.

*RN: Similar to runtime `Platform.OS_ANDROID` checks or conditional compilations in TypeScript with build flags.*

---

**Interviewer:** What is a variadic function?

**Candidate:** A variadic function accepts a variable number of arguments of the same type using `...` in the parameter: `func sum(_ numbers: Int...) -> Int { numbers.reduce(0, +) }` lets you call `sum(1, 2, 3, 4)`. Inside the function, the parameter is an array. You can have only one variadic parameter per function, and it must be the last parameter (except for trailing closures).

*RN: Rest parameters in JS/TS (`function sum(...numbers: number[])`); `...numbers` captures all remaining args as an array.*

---

**Interviewer:** What is the difference between weak and unowned?

**Candidate:** `weak` is an Optional reference that automatically becomes `nil` when the referent deallocates—safe but requires unwrapping. `unowned` is a non-Optional reference that does NOT become `nil` and does NOT retain; accessing it after deallocation CRASHES. Use `weak` when the reference can become `nil` (delegates, parent pointers); use `unowned` only when you can guarantee the referent outlives the holder (captured `self` in a closure run before the object dies). Both break retain cycles with classes.

*RN: JS/TS have garbage collection, so neither is needed—but the mental model is: weak ≈ optional observer pattern, unowned ≈ guaranteed non-null parent.*

---

**Interviewer:** What is the difference between an escaping closure and a non-escaping closure?

**Candidate:** An escaping closure outlives the function that receives it—it's stored, returned, or called asynchronously. A non-escaping closure is called before the function returns (the default). In escaping closures, you must explicitly reference `self` to capture it; non-escaping can use implicit `self`. `@escaping` marks a parameter as escaping: `func fetch(completion: @escaping (Data) -> Void)`. Non-escaping closures are faster and safer.

*RN: Escaping ≈ callback stored for later; non-escaping ≈ callback run synchronously. React has no escaping vs. non-escaping distinction—all callbacks are technically escaping.*

---

**Interviewer:** What is the difference between an extension and a protocol extension?

**Candidate:** An extension on a concrete type (e.g., `extension String { }`) adds methods to that type only. A protocol extension (e.g., `extension Equatable { }`) adds methods to all types conforming to that protocol, and can provide default implementations. Protocol extensions enable retroactive conformance—you can make an existing type conform to a protocol without modifying its source. Extensions on protocols are more powerful for generic code.

*RN: Somewhat like mixins or class inheritance—protocol extensions add behavior to a whole family of types at once.*

---

**Interviewer:** When would you use the defer keyword in Swift?

**Candidate:** `defer` registers cleanup code to run just before the current scope exits, whether via return, error, or natural completion. Use it to guarantee resource cleanup (closing files, releasing locks, logging). `defer { file.close() }` right after `file.open()` ensures cleanup regardless of how the function exits. Multiple defers run in reverse order (LIFO).

*RN: Similar to finally blocks in try/finally or destructors—ensures cleanup runs no matter what.*

---

**Interviewer:** How would you explain key paths to a new Swift developer?

**Candidate:** Key paths are compile-time safe references to properties: `\String.count` or `\Person.name`. They capture the type and property statically, so you can't typo a property name. You use them for sorting (`array.sorted(by: <)` with key paths), KVC-style updates, or SwiftUI bindings. `WritableKeyPath` lets you modify properties through the key path.

*RN: Ưu tiên thấp cho RN—key paths are Swift-specific, though TypeScript has had indexed access types.*

---

**Interviewer:** What are conditional conformances?

**Candidate:** A type conforms to a protocol only when its generic constraints are met: `extension Array: Equatable where Element: Equatable`. This is not explicit—you don't list it, Swift infers it. `extension Dictionary: Equatable where Key: Equatable, Value: Equatable` is another example. Conditional conformances keep APIs flexible and avoid unnecessary constraints.

*RN: Like TypeScript conditional types (`T extends U ? X : Y`), but for protocol conformance instead of type inference.*

---

**Interviewer:** What are opaque return types?

**Candidate:** `some Protocol` hides the concrete type but guarantees each call returns the same concrete type conforming to the protocol. `func makeTapped() -> some View { Button(...) }` returns a Button but the caller sees it as a View. Unlike `-> View` (existential type, which can change), opaque types are specific—optimization and type safety. SwiftUI uses them heavily.

*RN: Similar to generics, but from the function's perspective: the function "owns" the concrete type, caller only knows the protocol.*

---

**Interviewer:** What are result builders and when are they used in Swift?

**Candidate:** Result builders (marked `@resultBuilder`) transform a domain-specific syntax into function calls. `@ViewBuilder` in SwiftUI lets you write `VStack { Text("A"); Text("B") }` instead of nested function calls. You implement `buildBlock`, `buildIf`, `buildEither`, `buildArray` to define composition rules. They're used in SwiftUI layouts, argument builders, and custom DSLs.

*RN: Ưu tiên thấp cho RN—this is a Swift compile-time feature unique to SwiftUI and advanced DSLs.*

---

**Interviewer:** What does the targetEnvironment() compiler condition do?

**Candidate:** `#if targetEnvironment(simulator)` compiles code only when building for the simulator, not for a real device. Other values: `macCatalyst`, `iOSAppOnMac`. These are compile-time checks—code inside excluded branches is completely removed. Useful for mocking, debugging utilities, or hardware-specific code (camera hardware doesn't work in simulator).

*RN: Ưu tiên thấp cho RN—this is iOS/Xcode-specific; React Native abstracts platform differences away.*

---

**Interviewer:** What is the difference between self and Self?

**Candidate:** `self` refers to the current instance or value (the runtime object). `Self` is a type alias for the type of `self`—it refers to the type itself. In a method, `func copy() -> Self` returns the same type as the caller; in a protocol, `Self` lets each conforming type return its own type. `Self` is compile-time; `self` is runtime.

*RN: Similar to `this` vs. `this.constructor` in JS, or `this` vs. `typeof this` in TypeScript.*

---

**Interviewer:** When would you use @autoclosure?

**Candidate:** `@autoclosure` turns an expression into a closure automatically, delaying evaluation. Used for short boolean operators: `&& { evaluate right side only if left is true }`. `func logIfDebug(@autoclosure message: () -> String)` lets you call `logIfDebug("expensive: \(compute())")` without wrapping in braces; the closure is created automatically. Avoids unnecessary computation in short-circuit evaluation.

*RN: Similar to lazy evaluation or passing thunks in JS—delays a computation until it's actually needed.*

## 12. SwiftUI

**Interviewer:** SwiftUI environment là gì và nó hoạt động như thế nào?

**Candidate:** SwiftUI environment là một cơ chế để chia sẻ dữ liệu xuống view hierarchy mà không cần truyền qua init parameters. Dữ liệu được lưu dưới dạng key-value pairs thông qua EnvironmentKey protocol, và các views con có thể đọc nó bằng @Environment property wrapper. Khi environment value thay đổi, tất cả views sử dụng nó sẽ tự động re-render.
*RN: React Context API — chia sẻ dữ liệu qua hierarchy mà tránh prop drilling.*

---

**Interviewer:** @Published property wrapper làm gì?

**Candidate:** @Published dùng trong các class tuân theo ObservableObject protocol và tự động thông báo cho SwiftUI khi property thay đổi. Khi bạn gán giá trị mới cho một @Published property, nó kích hoạt objectWillChange publisher, do đó bất kỳ view nào đang observe object đó sẽ re-render.
```swift
@Published var count = 0  // SwiftUI automatically subscribes
```
*RN: Redux dispatch hoặc Zustand notify — thông báo state change cho subscribers.*

---

**Interviewer:** @State property wrapper dùng để làm gì?

**Candidate:** @State là source of truth cho state cục bộ của một view và được sở hữu bởi chính view đó. SwiftUI quản lý bộ nhớ của nó và tự động cập nhật giao diện khi giá trị thay đổi. @State không chia sẻ được với views khác — nếu cần chia sẻ, phải chuyển thành @Binding hoặc đưa lên parent view.
```swift
@State private var name = ""  // Each view instance has its own storage
```
*RN: useState hook — local component state không được chia sẻ.*

---

**Interviewer:** View initializer và onAppear() có gì khác nhau?

**Candidate:** Initializer chạy mỗi lần view được tạo, bao gồm cả quá trình re-render. onAppear() chạy sau khi view xuất hiện trên màn hình — thường là lần đầu tiên hoặc sau khi quay lại từ navigation. Bạn nên dùng onAppear() cho các side effects như fetch dữ liệu, vì initializer chạy quá thường xuyên và có thể gây lãng phí tài nguyên.
*RN: useEffect([], []) chạy một lần khi component mount — tương tự onAppear().*

---

**Interviewer:** Khi nào nên dùng @StateObject thay vì @ObservedObject?

**Candidate:** @StateObject được dùng khi view tạo ra observable object lần đầu tiên — nó sở hữu object và giữ nó sống qua các lần re-render. @ObservedObject được dùng khi nhận object từ parent view và không sở hữu nó. Nếu dùng @ObservedObject ở nơi tạo object, nó sẽ bị tạo lại mỗi lần parent re-render, làm mất state.
*RN: @StateObject giống useState — tạo state ở component. @ObservedObject giống props — nhận state từ parent.*

---

**Interviewer:** Observable object thông báo thay đổi cho SwiftUI như thế nào?

**Candidate:** Cách tự động nhất là dùng @Published property wrapper trên các properties trong class tuân theo ObservableObject. Khi giá trị thay đổi, SwiftUI tự động được thông báo. Nếu cần kiểm soát chính xác, bạn có thể gọi objectWillChange.send() hoặc dùng didSet trên properties để kích hoạt thông báo.
```swift
class MyViewModel: ObservableObject {
    @Published var data = ""  // Automatically notifies
}
```
*RN: Action dispatch trong Redux hoặc Zustand — tự động thông báo subscribers.*

---

**Interviewer:** Làm thế nào tạo programmatic navigation trong SwiftUI?

**Candidate:** Có nhiều cách: dùng @State kết hợp NavigationLink và NavigationStack (iOS 16+), hoặc dùng navigationDestination(for:destination:) modifier. Ngoài ra có thể dùng if/switch statement để điều khiển conditional navigation. Cách phổ biến nhất hiện nay là NavigationStack với @State để quản lý navigation path.
*RN: React Navigation imperative API — navigation.navigate() hoặc useNavigation hook.*

---

**Interviewer:** ButtonStyle protocol dùng để làm gì?

**Candidate:** ButtonStyle protocol cho phép tùy chỉnh giao diện và hành vi của button. Bạn conform vào protocol và implement makeBody(configuration:) method, nơi configuration cho phép truy cập pressed state và customize style. Đây là cách tạo reusable button styles trong ứng dụng.
```swift
struct MyButtonStyle: ButtonStyle {
    func makeBody(configuration: Configuration) -> some View {
        configuration.label
            .scaleEffect(configuration.isPressed ? 0.95 : 1.0)
    }
}
```
*RN: Custom styled components hoặc Pressable wrapper để control styling khi pressed.*

---

**Interviewer:** Khi nào nên dùng GeometryReader?

**Candidate:** GeometryReader cung cấp truy cập vào size và position của parent container, dùng để xây dựng responsive layouts dựa trên không gian sẵn có. Tuy nhiên nó có chi phí hiệu năng vì yêu cầu multiple layout passes. Nên dùng để tạo proportional layouts hoặc adaptive designs, nhưng tránh nested GeometryReaders vì sẽ gây hiệu năng.
*RN: Dimensions API hoặc useWindowDimensions hook — lấy kích thước màn hình cho responsive design.*

---

**Interviewer:** Tại sao SwiftUI dùng structs cho views?

**Candidate:** Structs có value semantics, không tạo reference cycles hay lifetime issues. SwiftUI có thể efficiently diff value types để biết view nào cần re-render. Structs cũng khuyến khích functional/immutable mindset — bạn tạo view từ combinations của smaller views, không mutate state in-place. Điều này làm code dễ lý luận và debug hơn.
*RN: Functional components trong React cũng stateless/immutable — dùng props và callbacks, không mutate props.*

## 13. UIKit

**Interviewer:** How are XIBs different from storyboards?
**Candidate:** XIB files define a single view or view controller's interface, while storyboards are composite documents showing multiple view controllers and their navigation connections. XIBs are more modular and easier to merge in version control; storyboards provide a visual overview of app flow but can become unwieldy in large apps and cause merge conflicts.
*RN: JavaScript navigation libraries (React Navigation) handle routing and composition; no direct XIB/storyboard equivalent.*

**Interviewer:** How would you explain UIKit segues to a new iOS developer?
**Candidate:** Segues are named transitions between view controllers, defined in storyboards or triggered programmatically. When a segue fires, UIKit instantiates the destination view controller, calls `prepare(for:sender:)` on the source for data passing, and animates the transition. You can customize transition type (push, modal, popover, unwind) and animation.
*RN: Navigation actions in React Navigation (push, navigate, replace) serve the same role.*

**Interviewer:** What are storyboard identifiers for?
**Candidate:** Storyboard identifiers let you instantiate view controllers programmatically at runtime using `instantiateViewController(withIdentifier:)`. This is useful when you don't have a segue, or when the destination depends on conditional logic.
*RN: Route names in React Navigation navigation stacks provide equivalent functionality.*

**Interviewer:** What are the benefits of using child view controllers?
**Candidate:** Child view controllers let you compose complex interfaces from simpler, reusable components. Each child manages its own view hierarchy and lifecycle. You can swap children dynamically, isolate logic, and reuse the same child in multiple parents without duplication.
*RN: Component composition in React (nesting, reusable custom components) achieves the same modularity.*

**Interviewer:** What are the pros and cons of using viewWithTag()?
**Candidate:** `viewWithTag()` quickly finds a view by its integer tag without storing an IBOutlet. Cons: not type-safe, tags are error-prone and require manual management, hard to refactor, unreadable, and lookup is O(n) in the worst case. Modern Swift strongly prefers IBOutlets or property references.
*RN: DOM queries by ID/class in React (via refs) have similar drawbacks; prefer direct references.*

**Interviewer:** What is the difference between @IBOutlet and @IBAction?
**Candidate:** `@IBOutlet` connects a UI element (button, label) to a property, letting you programmatically read or modify it. `@IBAction` connects a user event (tap, drag) to a method, letting you respond to interaction. Both are Interface Builder connectors.
*RN: JSX elements are props or state variables; event handlers are callback functions passed as props.*

**Interviewer:** What is the difference between a UIImage and a UIImageView?
**Candidate:** `UIImage` is an immutable data object representing image content (loaded from file, network, or drawn). `UIImageView` is a view that displays a UIImage on screen, handling layout, scaling, and rendering. One image can be shown in multiple image views.
*RN: Image component wraps both the data (source URI) and the display view.*

**Interviewer:** What is the difference between aspect fill and aspect fit when displaying an image?
**Candidate:** `aspectFill` scales the image to fill the entire bounds, clipping content if necessary. `aspectFit` scales to fit entirely within bounds without clipping, which may leave empty space (letterbox or pillarbox). Choose based on whether you want to cover the space or preserve the full image.
*RN: `resizeMode` prop ('cover' = aspectFill, 'contain' = aspectFit).*

**Interviewer:** What is the purpose of UIActivityViewController?
**Candidate:** `UIActivityViewController` presents a system activity sheet letting users share, print, copy, or save content via email, messaging, social apps, AirDrop, Files, and other installed services. You provide the content (text, image, URL) and UIActivityViewController handles the rest.
*RN: Share API (native module or @react-native-share library) provides similar sharing functionality.*

**Interviewer:** What is the purpose of UIVisualEffectView?
**Candidate:** `UIVisualEffectView` applies visual effects (blur, vibrancy) to the content behind it, creating a modern, layered iOS aesthetic. You add a `UIBlurEffect` (light, dark, extraLight, regularMaterial, etc.) and optionally a `UIVibrancyEffect` for secondary text. Commonly used in Control Center, modals, and custom HUDs.
*RN: Libraries like react-native-blur provide blur overlays; @react-native-camera's Camera.Constants.ViewFinder is an analogy.*

**Interviewer:** What is the purpose of reuse identifiers for table view cells?
**Candidate:** `UITableView` maintains a queue of reusable cells with a given identifier. When a cell scrolls off-screen, it's dequeued and reused for new data at a new index path, rather than creating a new cell. This dramatically improves memory efficiency and scrolling performance in large lists.
*RN: FlatList and SectionList recycle rendered components automatically with a similar recycling pool pattern.*

**Interviewer:** When would you choose to use a collection view rather than a table view?
**Candidate:** Use `UICollectionView` when you need multi-column, grid, or custom 2D layouts. `UITableView` enforces a single-column vertical list. Collection views support arbitrary item positioning, flowing layouts (grid, waterfall), and rotation of layouts. For simple linear lists, table view is simpler; for anything more complex, collection view is the right choice.
*RN: ScrollView, FlatList (single column), or specialized libraries (e.g., react-native-draggable-flatlist) handle list layouts; no direct collection view equivalent.*

**Interviewer:** Which parts of UIKit are you least familiar with?
**Candidate:** <This is a self-reflection question. A good answer is honest and shows awareness of the ecosystem. For example:> "I haven't done much custom gesture recognition or complex CALayer animations. I'm comfortable with standard table/collection views and navigation, but advanced layout techniques like compositional layouts are something I'd want to deepen." Show willingness to learn and name real areas of growth.
*RN: Similar self-reflection applies to React Native; name real gaps (animations, accessibility, performance profiling, etc.).*

**Interviewer:** How does a view intrinsic content size aid in Auto Layout?
**Candidate:** Views like UILabel, UIButton, UIImageView have an intrinsic content size based on their content (text length, image dimensions). Auto Layout uses this size to determine preferred dimensions without explicit width/height constraints. This reduces constraint boilerplate and makes layouts more flexible and maintainable.
*RN: Flexbox's automatic sizing (flex-wrap, flex-shrink, flex-grow) and `flex: 1` achieve similar content-aware layout.*

**Interviewer:** What is the function of anchors in Auto Layout?
**Candidate:** `NSLayoutAnchor` objects (`topAnchor`, `leadingAnchor`, `widthAnchor`, etc.) provide a type-safe, fluent API for creating constraints programmatically. Instead of `NSLayoutConstraint(item:attribute:relatedBy:toItem:attribute:multiplier:constant:)`, you write `view.topAnchor.constraint(equalTo: parent.topAnchor).isActive = true`, which is more readable and catches errors at compile time.
*RN: Flexbox properties (alignItems, justifyContent) and absolute/relative positioning are the conceptual equivalent.*

**Interviewer:** What is the purpose of IBDesignable?
**Candidate:** `@IBDesignable` marks a custom UIView subclass so Interface Builder renders it live in the canvas instead of a gray placeholder. As you edit the code, the canvas updates in real-time, letting you see your custom view design immediately without building and running the app.
*RN: Hot-reload in React Native provides instant preview of code changes during development.*

**Interviewer:** What is the purpose of UIMenuController?
**Candidate:** `UIMenuController` displays a floating context menu (Copy, Paste, Delete, etc.) at a point on screen in response to a long press or custom gesture. You define which menu actions apply by subclassing and implementing `canPerformAction(_:withSender:)`. Largely deprecated in favor of `UIContextMenuInteraction` (iOS 13+) and context menus.
*Ưu tiên thấp cho RN.*
*RN: Native context menu APIs in Android/iOS; react-native-context-menu-view and similar libraries provide RN wrappers.*
