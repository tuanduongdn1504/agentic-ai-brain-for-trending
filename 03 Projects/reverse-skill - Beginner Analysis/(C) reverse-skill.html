what it is

When an AI coding agent is handed an APK, an ELF, encrypted frontend JS, or an authorized pentest target, reverse-skill routes it to exactly one methodology, forces it through a hard authorization gate before any target action, and runs a repeatable workflow instead of guessing commands. It is deliberately not an autonomous system — its own identity file defines it against the red-team platforms it refuses to become. A router and an instruction manual, git clone and go.

the spine

Two systems, opposite directions

The same 585-file repository builds the corpus's most careful pre-action authorization gate and its most explicit manual for suppressing agent hesitation. One is engineered to make the agent stop until it is authorized. The next folder is engineered to make it never stop once it is working.

◧ STOP · the auth gate

case-guard reads a contract

auth.status=granted + a legal network profile before ACT. Fields forged outside their ## section are ignored. --force prints a refusal and exit 2 anyway — no code path yields exit 0 with unmet auth. CI proves it on every push.

▶ GO · the obedience layer

"If you only reply 'understood' — you have failed"

An excuse-rebuttal table, RFC-2119 directives, opaque "code words" for 100% param compliance, attention-window exploits. ~73% of rebuttals suppress hesitation with no user re-involvement. No "do not use for" scope disclaimer.

Coherent only if a single check at the front door is enough to trust everything the agent does after it — on an offensive-security toolchain, forever. That assumption is the one thing in the repo no test can check.

where the discipline stops

What it gates reveals what it fears

The CI protects exactly what can drift and be machine-checked. It ignores exactly what can harm and can't. The seam runs precisely between the router and the skills.

the mint call

No mint — and the honest reason

The subject leads with "Skills Router," but routing a task to a skill is the universal convention of every agent skill system — form-factor within the cybersecurity Domain-Vertical genre (already confirmed via v98), the ground v238 declined a routing preset on. The genuinely corpus-first thing here is not the router: it is the hard, un-bypassable, section-scoped pre-action authorization state machine. It ships, it's CI-tested, no corpus subject implements its shape. But it is bundled inside a form-factor package — so it is recorded as the audit-reviewable §C-2 candidate, not minted by a ship. Also recorded: #18 B1-MCP ≈N=16 → ≈N=17 (the 78-tool first-party Burp MCP server).

the blunt line

v278 gated nothing and put a debugger's memory-write on the open internet with no password. v279 gates almost everything a machine can check — 173 routing cases, a supply-chain pin gate that fails on one unpinned dependency, a doc-count derived from source, a consent gate whose --force flag prints a refusal and exits nonzero anyway — and gates nothing a machine cannot: forty-four skill modules, forty-one CTF competitions, seventy-eight offensive tools, verified by nothing but code review. The discipline stops exactly where the artifact stops being machine-checkable. And the folder engineered to make the agent stop until authorized sits beside the folder engineered to make it never stop once it is.
