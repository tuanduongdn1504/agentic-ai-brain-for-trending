Tsinghua University's Open Multi-Agent Interactive Classroom: name a topic or upload a document, and it builds a full interactive course — slides, quizzes, interactive HTML simulations, project-based learning — delivered by AI teacher and AI classmate personas who speak, draw on a whiteboard, and discuss with the learner. It ships 24 SKILL.md files and an eighteen-provider seam.

Source verified twice: two independent clones, diff -rq clean both ways. 543 commits, 94 authors, 2,929 files, 547,462 lines of TypeScript, 893 test files — last commit the day before this wiki.

The rule

Every list in this repository that is derived from the tree is correct. Every list a person typed is correct only where omitting an entry breaks something loudly — and wrong everywhere it does not.

This is not a frame imposed from outside. The repository names the disease itself, in the header comment of its own best test:

“That gate was once applied at several API routes from a hand-written list that drifted from the code. This test makes the gap un-reintroducible: it walks the repository source, finds every validateUrlForSSRF call site, and fails if any call site sits inside an if block whose condition references NODE_ENV.”

They diagnosed the class exactly, and fixed it — for one invariant. Then left the same class alive in the file that decides what gets tested.

The number was false the day it was typed

README.md:52 says “20 built-in skills.” Disk holds 23 — confirmed by three independent instruments, each with the enumeration that yields it. And it was never true: the line entered in the v1.0.0 release commit, and at that very commit the directory held 22. Wrong by two on the day it was written; wrong by three now.

The same six packages, hand-written three times

postinstall builds six. The publish workflow builds six. ci.yml tests four.

64 test files, never executed

@openmaic/editor (49 test files) and @openmaic/renderer (15) each carry a "test": "vitest run" script. Both are built by two of the three lists. Neither is ever tested — by any of the five workflows.

The mechanism is the whole point. Omit a package from the first list and pnpm install breaks. Omit it from the second and the package never publishes. Omit it from the third and fewer tests run while everything stays green.

And the rule is tested, not assumed

Where gates are not the explanation

The workbench-locales set has no key-parity gate at all — the checker scans a different directory — and its ten hand-written imports have not drifted: 267 keys, in all ten files, exactly.

So the rule is not “ungated drifts.” It is the v274 distinction, reached independently: a claim is safe when a gate covers it, or when a habit covers it. Translations have an owner. A number in a README, and “which packages get tested,” have neither.

Genuinely strong engineering

This is not a careless project, which is exactly what makes the above interesting.

  • The untrusted-content boundary is wired — defined, imported, and called. The direct inverse of the previous ship, whose equivalent fence was defined once and never invoked.
  • The fetch_url origin gate is enforced three times — before the fetch, inside it so every redirect hop is re-checked, and again on the final URL: “defense in depth for injected transports and future fetch engines.”
  • Four security advisories fixed in 1.0.1, credited to named outside researchers — one of them being this vault's own recurring thesis, found by the project in itself: a guard that “ran only under NODE_ENV=production.”
  • The fix was mechanised, not documented — and the test carries anti-vacuity floors so it cannot pass by scanning nothing.
  • AI-generated HTML is sandboxed without allow-same-origin; exported HTML runs under connect-src 'none'; 2,726 of 2,726 lockfile entries hashed, no mirror override; and no paths: filter anywhere excluding files from checks.
Calibrated honestly

“Multi-agent orchestration (LangGraph 1.1)” is, at the graph level, two nodes and one conditional edge. The real orchestration is nine numbered English rules in a prompt, headed “Routing Rules (mirror the old /api/chat director).” Routing moved out of code and into the model — a legitimate, explicit choice, and simply not what the phrase suggests.

Method, disclosed

The fleet ran on the wrong model — again

Fifteen agents, 2.13M tokens — all on Haiku, despite the model parameter being deliberately omitted so they would inherit Opus. Third consecutive ship.

The security agent returned a false negative on the single most important finding, reporting no untrusted-content marking because it searched for the name it expected rather than the mechanism it wanted. I nearly made the identical error twenty minutes earlier, and caught it only by searching again by behaviour.

New rule: a zero-hit identifier search is evidence about the identifier, never about the mechanism.

A “world-first” claim and a star count also came back from that fleet. Neither is carried anywhere in this ship.

Take

  • The anti-vacuity floor — already applied. This ship's own state-file bump is the first to check its derived count against the last recorded one and refuse to write if it drops. That is precisely the defence our derivation lacked when an earlier matcher silently skipped an entry while returning a plausible number.
  • Run the three-list audit on our own repository. Where do we write the same set down twice — and does omitting an entry break anything?
  • Assert the call site, not the prompt string. A test proving the model was told about a fence proves nothing about the fence.
Never

Never point it at candidate data. Never cite its README skill count. Never assume the editor or renderer packages are covered by CI. Never set ALLOW_LOCAL_NETWORKS=true outside an isolated machine.

Blunt

A Tsinghua lab shipped, in six months, a course-generation platform with better security engineering than most funded products in this corpus. It found its own declared-but-unenforced guard, fixed it in every environment, and wrote a 260-line tree-walking test with floors so the gap can never come back. That test's header names the disease exactly: a hand-written list that drifted from the code.

Then they wrote a README saying twenty when the directory held twenty-two, and a CI file that tests four of the six packages two other files in the same repository both list completely.

Nothing here is careless. The difference between what is right and what is wrong is not effort, and it is not skill — it is whether leaving an entry out makes something turn red.
