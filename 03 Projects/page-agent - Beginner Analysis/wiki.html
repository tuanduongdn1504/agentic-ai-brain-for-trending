page-agent — the GUI agent that lives inside your web page

Every other web-agent in this vault drives a browser from the outside. alibaba/page-agent inverts it: one <script> tag makes any web page carry its own natural-language agent — driving the app's real DOM as indexed text, no extension, no headless browser, no backend, no screenshots.

GOAL-ALIGNED INCLUDE 3/4 MIT · TS 82.6% v1.11.0 · 34 releases ~25k★ (page-stated) Author Simon · Alibaba @ 35ff6d4

01The one-sentence thesis

browser-use v41 / Skyvern v24 / crawl4ai v29 are external tools: a Python or Playwright process drives a headless or remote browser, for a developer or a coding agent. page-agent is a ~50–100 KB client-side JavaScript library that a web-app owner drops into their own site — which then gives that site's end users an agent that reads and drives the app's own DOM.

The README draws the line itself: “PageAgent is designed for client-side web enhancement, not server-side automation.” In a phrase: browser-use, but living inside the page instead of driving it from outside.

02What the agent actually sees

The heart of the deep dive: page-agent never sends a screenshot. It walks the live DOM, keeps only the interactive elements, gives each a stable integer, and “dehydrates” the page into token-lean text the model reasons over — then the model acts by integer, never by CSS selector. (This DOM-as-text technique is inherited from browser-use, not invented here — the industry has converged on it.)

Dehydrated DOM — the model's entire view of the page
[33]<div>Candidates</div>
	[34]<input aria-label='Search'>Search…</input>
	*[35]<button>Filter: Hanoi</button>   ← appeared since last step
[36]<a>Nguyen T. — React, 6y</a>
data-scrollable='top=0,bottom=1840'  ← 1840px of room below

The model replies with one forced structured call — { evaluation_previous_goal, memory, next_goal, action: {click_element_by_index: {index: 36}} } — and the controller dispatches a full W3C pointer sequence so it behaves like a real user click.

03The loop, honestly built

A ReAct loop in a clean 8-package monorepo (headless core · llms client · page-controller DOM engine · ui · mcp · Chrome extension). Details that reveal the taste of the author:

  • One MacroTool per step. All tools merge into a single forced AgentOutput call carrying reflection and the chosen action — cheap and auditable.
  • Two separated streams. Persistent History (in the model's context) vs transient Activity (UI only) — and transient errors are kept out of the model's reasoning.
  • Human-in-the-loop is first-class. An ask_user tool and a user_takeover memory event when a person grabs the wheel.
  • Honesty over success theatre (verbatim system prompt): “It is ok to fail the task… Trying too hard can be harmful… Never assume an action succeeded.”
  • autoFixer repairs malformed model output (JSON-in-content, double-stringified args, missing-action → wait) so even weak local models can drive a UI.
  • Safe-to-embed levers: execute_javascript off by default · a transformPageContent redaction hook · per-route getPageInstructions(url).

Claude is first-class and tested: v1.9.0 shipped “Claude Opus 4.8 support”; v1.11.0 rewrote per-model patching “for GPT, Claude, Qwen, Gemini, and DeepSeek.” It is otherwise LLM-agnostic (BYOK incl. local Ollama).

05Apply it — the pilot ladder

Because hireui is a recruitment SaaS web app and page-agent is literally “ship an AI copilot in your product, no backend rewrite,” this is an unusually direct product pilot. The ⭐ one-thing path is A1 → C11 → D16. Full 24-method menu lives in the project folder.

  1. A1 · Read the loop + dehydration engine. Zero install. Internalize “give the model a compact indexed surface, let it act by integer.”
  2. B5–B9 · Borrow patterns, zero install. The MacroTool call, autoFixer repair layer, the two-stream state model, a transformPageContent-style redaction seam — into hireui's LLM-feature spec.
  3. C11 · Drive a scratch hireui clone with your own Claude key. BYOK, not the demo proxy. Prove the observe→think→act loop; read usage to measure the token economy (C13).
  4. D16 · A read-only recruiter copilot on an agent-* branch. “Find candidates in Hanoi with React, open the top match.” No writes. The first real Goal-#2 product artifact.
  5. D17 · Wire PII redaction first. Candidate data lives in the dehydrated DOM — redact + pick a no-training provider before anything real.
The fence (load-bearing)

BYOK, never the free demo proxy (it egresses page HTML to Alibaba Cloud China — tech-eval only, EU do-not-use). HTML dehydration does not guarantee PII removal → redact candidate data + no-training provider. Never inline a real API key in a shipped browser bundle. Leave execute_javascript off. Scratch clone before real hireui. Pin page-agent@1.11.0. On hireui, follow its CONSTITUTION (I-2 agent-* branch, I-8 operator-installs, GitNexus-first).
