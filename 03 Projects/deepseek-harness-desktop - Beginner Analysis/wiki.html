The rule · D19

A clone’s git metadata is authoritative about the repository, never about the project. Where history is inherited — fork, graft, or in-place re-purposing — provenance must be measured from the divergence point. Commit counts, author counts and “age” over an inherited history describe the parent.

Detector, cheap and general: find paths with heavy commit history that no longer exist in the tree; count root commits; scan merge subjects for foreign org names.

This corrects last ship’s headline method — v240 was praised for “provenance measured without the mocked API.” The method is sound only when the history belongs to the subject.

And it exonerates the project. I first read ten @deepseek.com addresses against a “not affiliated with or endorsed by DeepSeek” disclaimer as a real tension. Every one of those commits predates the product. The disclaimer is accurate, and the repository advertises no commit count anywhere.

Doc integrity

The mechanism is here. So is the gap.

Seven consecutive ships have handed the vault machinery for its own documentation drift. This one hands over the most — and supplies the sharpest counter-example to itself.

Inventory
rule

It exists here as working code

dsh-community-fabric/scripts/verify-docs.mjs declares an explicit 33-file inventory and walks the tree recursively — enumerating both ways. That is precisely the rule derived last ship: pair every equivalence check with an inventory check that enumerates by a different rule than the parser uses.

…and the
irony

Those files include a four-RFC suite the index never mentions

docs/README.en.md calls itself the full documentation and README map. It contains zero occurrences of rfcs — hand-verified. Roughly 25 files are absent from it. Fabric’s own README indexes all four RFCs at lines 46–49.

The workspace that solved the inventory problem is invisible from the front door, because the top-level index is hand-maintained and has no inventory check of its own.

Stale
prose

AGENTS.md still calls a shipped marketplace a scaffold

It reads: “until its runtime is implemented, it remains a private documentation scaffold and must not declare loadable DSH or package entry points.” The manifest declares main, exports, and dsh.client.inject behind ~18,748 lines of code and a 15-file test suite.

The sharp part: in the very commit that added the runtime, verify-docs.mjs flipped polarity — from forbidding those keys to requiring them. The machine contract advanced as a state machine. The file the AI agents read did not.

Counter-
balance

67 links tested. Zero dead.

Every relative markdown link across five index files resolves. The recorded bilingual blob hashes match. Last ship had README.ja.md broken on line 5 of both READMEs. This project’s failure is omission, not breakage.

The gate

verify-layout.mjs — 136 lines, and the strongest structural gate of the run

It makes “we do not modify upstream” a property of the build: the submodule pin must match the index and the checked-out HEAD, its working tree must be clean, and no dependency may bypass the published-package boundary — any workspace:, portal:, link: range fails the build. It hashes the committed blob rather than the working tree, commented “checkout line endings differ per host” — solving last ship’s CRLF defect.

Its limit, inverted from v240’s: line 21 hardcodes one note name. Twelve notes carry blob-hash records — a perfect 12/12/12 pairing — and eleven are checked by nothing. v240’s loader globbed and silently skipped a file; this checker hardcodes a constant and silently ignores eleven that would match. Both are inventory failures.

Architecture

The container is a plugin of the contained

The Electron launcher is neither the host nor embedded in one. It starts the Cordis host, injects itself in via hostCtx.provide('desktopRuntime', runtime), and mounts its own services as ordinary plugins. src/index.ts exports name = 'desktop-shell' and a standard apply(ctx, config) — and silently returns if the runtime is absent.

Compatibility mode is the default and deliberately additive: “keeps upstream ownership of the browser carrier and rendered UI.” Work profiles are real directories, written with a 0600 temp file and same-directory atomic rename, tracking active / pending / lastKnownGood — promoted only after the app boots and the window loads.

Novelty · refuted

Eclipse RCP is decisive prior art. Eclipse’s own plug-in-architecture article names the workbench UI itself as a self-extending plug-in contributing to its own extension points — Eclipse 1.0 shipped 2001, and 3.0 made the whole platform OSGi bundles. JupyterLab’s lumino shell and Theia populate the same space.

And the project never claims novelty. Its own docs/research/ holds mature-plugin-frameworks.md and vscode-extension-model.md. 「桌面本身也是「插件」」 is a design commitment, not a priority claim. Minting here would over-claim on the subject’s behalf.

Supply chain

Best hygiene of the run, and four real risks

Deny by default

.yarnrc.yml sets enableScripts: false, then dependenciesMeta allow-lists exactly five packages to build and explicitly denies three. 1,001 lockfile resolutions, zero from npmmirror, taobao or cnpm — a direct contrast with last ship’s mirror-resolved lockfile.

Applied to users too

Its marketplace refuses any package declaring preinstall, install, postinstall or prepare, verifies SHA-512 integrity, requires a repository backlink matching the npm manifest, and pins exact stable versions only.

The honest limit, in their words

“These checks establish package identity and a narrow compatibility boundary; they do not review the plugin or its dependency tree for malicious or unsafe behavior.”

Last ship published a catalogue that scans nothing and said so. This ship consumes catalogues, gates the install structurally, and says just as plainly that structural gating is not code review. Publisher and consumer, one ship apart, both honest about the same hole — and nothing anywhere in this ecosystem scans plugin code.

  • 01
    Updates route through a third-party domain. It polls dshdesktop.cn/api/desktop/version and downloads installers from the same host — no electron-updater, no GitHub Releases fallback, and validation is format-only (DMG magic, PE header), not signature or digest verification against a trusted manifest.
  • 02
    Windows builds carry no code-signing configuration while the NSIS installer sets allowElevation: true. macOS is hardened-runtime and notarized, with signing credentials withheld from the build subprocess. The asymmetry lands on the only platform shipping an installer target.
  • 03
    electronFuses: { runAsNode: true } — a documented hardening gap. Fair caveat: this app must run Node, and the Windows sandbox sets ELECTRON_RUN_AS_NODE deliberately. A considered trade-off, but it weakens the notarized story.
  • 04
    Telemetry is opt-out, default-on — the upstream OTel session plugin is disabled only when DSH_TELEMETRY_DISABLED is non-empty.

The patches — a disclosure gap, not deception

Four of five patches modify upstream’s published @deepseek-ai/* packages at install time, while the README says the project “does not fork or modify upstream source.” Narrowly true — the submodule genuinely is unmodified, and CI proves it — but an installed product’s node_modules/ contains four patched packages.

Every patch is benign or beneficial: a real streaming tool-call identity fix shipped with a 100-line spec; a Windows console fix that preserves ACL confinement; two inert UI markers; and an app-builder-lib fix that strengthens code signing. All are documented — in .agents/notes/, and nowhere user-facing.

The inverse of last ship’s shape: there, documentation was more precise than marketing. Here, the internal agent notes are more complete than the user-facing docs.

Governance · now a pattern, not an incident
