- **A1 ⭐** Read the 10 rules + the 5 neurocognitive facts + the override conditions in `SKILL.md`. ~10 min. The whole idea: action-first, restate-state, one-concrete-next-step, cap-lists, no-preamble.
- **A2** Read it as a **prompt-engineering case study** — how a good output-style skill is written (grounded in a source, explicit override conditions, enumerated named rules = Pattern #88 88b, machinery = 88c).
- **A3** Compare against **Claude Code's native output styles** (`/output-style`: Default/Explanatory/Learning; `/output-style:new`). Ask: what does i-have-adhd add? (answer: cross-harness + accessibility-grounding + an eval harness). This is the world-first-denial calibration.
- **A4** Read the `evals/` idea (even without cloning) — a behavior skill *with* an eval harness is the SkillOpt v178 / ponytail v168 discipline; note it for your own `05 Skills/` authoring.

## B — Borrow patterns (zero install, highest ROI for the vault)

- **B5 ⭐** Distil the 10 rules into a **`05 Skills/` output-discipline note** (or fold the best few into the vault's own `CLAUDE.md` response-style guidance) so the vault's own agent output stays action-first.
