Everything Is a Plugin

deepseek-ai/deepseek-harness  ·  dsh  ·  MIT  ·  v0.1.0-rc.5

DeepSeek open-sourced not a coding-agent product but the agent runtime — where the model, the tools, the sandbox, the scheduler, the UI, and even the main agent loop are all hot-swappable plugins. It ships Claude Code as one of them.

What it is

Run npx @deepseek-ai/dsh web and you get a local web UI on port 3080. Underneath is a plugin kernel — Cordis, which is not DeepSeek's: it is an independent meta-framework by the developer shigma that has powered the Koishi chatbot framework for four years. Its one defining capability is disposability: load, unload and reload a plugin with complete cleanup of side effects.

That is what makes the tagline operational rather than decorative. The swappable set, verbatim from DeepSeek: models, tools, skills, sessions, sandboxes, storage, loops, scheduling, and the UI.

DeepSeek Harness is currently in developer preview and is iterating rapidly. THERE WILL BE COMPATIBILITY-BREAKING CHANGES.

Three verified findings

Finding 01 — corpus linkhand-verified

Its model seam runs on Pi — a corpus subject

packages/llm/ holds only five directories, and there is no llm-anthropic. Breadth comes from one package: llm-pi-ai, described as a "generic multi-provider adapter for the harness LLM seam backed by @earendil-works/pi-ai." That is the npm package of Pi — corpus subject v228, the revisit of v36 pi-mono.

So a frontier lab's flagship runtime gets OpenAI, Anthropic, Azure, Bedrock and Vertex from one solo developer's SDK. Pi is now depended on by two labs — ByteDance's llm-space v221 and this. And the sharpest critique of dsh — token usage roughly 10× versus Pi — measures it against the very project it is built on.

Finding 02 — Goal #1hand-verified

It ships Claude Code as a delegatable subagent

packages/subagent/subagent-claude-code "starts a real Claude Code child through the official Claude Agent SDK." Alongside it, subagent-codex starts a real Codex app-server child, and packages/hooks/ bridges your existing hooks.json. Both off by default.

This is the mirror image of harness emulation. One wiki earlier, openinterpreter v223 minted a class for reimplementing a rival's harness to squeeze performance from cheap models. DeepSeek does the opposite: it spawns the real thing through the vendor's own SDK. Emulate versus delegate — two opposite answers to the same problem, twelve wikis apart.

Finding 03 — the borrowable ideahand-verified

Traceability as an architectural guarantee

Session logs are append-only: anything visible to the model is permanently recorded. Not a logging policy — an invariant of the runtime. The main loop is decomposed into interceptable Turn/Step stages rather than hardcoded control flow, which is what lets the loop itself be a plugin.

That first rule is almost verbatim the audit requirement in the vault's ratified candidate-LLM legibility ADR. It is the single most transferable thing in 453,000 lines.

The pattern call

The natural home is an existing registry row — "Open-Sourced First-Party Frontier-Lab Agentic Coding CLI/TUI," anchored at N=1 by grok-build v215. deepseek-harness satisfies every essential axis of it: a frontier lab, its own official agent, fully open-sourced, studiable as a primary subject, in the Claude Code peer class.

It differs only on two descriptive clauses — that row says "terminal-TUI-first, single-vendor-model"; dsh is web-UI-first and multi-vendor. The v212 audit has generalized exactly that kind of clause before.

But that row is promotion-eligible at N=2.

Declaring the N=2 here would silently fire a promotion to CONFIRMED and change the headline counts. The v232 ship refused precisely this move on the record: a promotion is an audit act. So the candidacy is recorded and flagged to the badly-overdue audit — not executed. Counts stay 46 / 11.

The reviewable alternative — mint a new standalone for a "frontier-lab plugin-composable agent runtime" — is recorded and declined: a well-fitting row already exists, "plugin architecture" is a crowded world class the corpus has twice declined to mint on (cortex-hub v181, lobehub v222 at 80.6k stars), and a four-day-old preview is a weak anchor.

What is actually wrong with it

  • Ecosystem compatibility ~19% — 41 of 219 integrations succeeding.
  • ~10× token usage versus Pi, plus a confirmed context-duplication bug.
  • No evaluation story at all. BENCHMARK.md is a three-line stub; there is no eval harness anywhere in the tree and zero evaluation claims — striking for a runtime this size.
  • Squashed-merge history. The whole codebase arrived as one commit; contributors called it hostile, and it means real provenance opacity.
  • A postinstall script — pointed, given it depends on Pi, the corpus's strongest supply-chain positive exemplar for --ignore-scripts discipline.
  • Windows sandboxing is partial — reads, network and process visibility stay unrestricted. Credit where due: DeepSeek documents this rather than hiding it.

Its own reviewers suggest waiting three to six months before production adoption. The ~92,700 stars in 28 hours are page-stated only and, under this vault's provenance rule, not a velocity claim.

What to do about it

Read-and-borrow. Not a tool to adopt, and not a hireui component.

A1 · read the seam taxonomy→B5 · name your own seams→B6 · steal append-only traceability

The seam list is the best available checklist for what should be swappable in an agent system, and the append-only rule drops straight into hireui's LLM-integration ADR. Note too that this is the second consecutive ship — after agentic-local-brain v234 — to hand the vault machinery for its own stale-derived-artifact backlog: dsh ships verify-doc-refs, verify-doc-budgets and verify-md-links as CI gates.

Fence: install-snapshot first (there is a postinstall), scratch directory only, pin the version and expect breakage, route the pi-ai seam at Claude rather than the DeepSeek default to avoid PRC cloud egress, never point it at candidate data, and never enable self-modifying toolsets.
