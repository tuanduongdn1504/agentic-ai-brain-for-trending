Which Safe Defaults Were Free

Tencent Cloud built an excellent lock for the filing cabinet and shipped the building with the front door open. Both decisions were reasoned. Both were written down. The difference was cost.

What it is

One memory server, seven coding agents, no MCP

A self-hosted, team-scoped memory platform: conversations distilled L0 → L1 → L2 → L3, plus Skills, a Wiki and a CodeGraph, all registered as Memory Assets under one ownership, ACL and versioning model. Claude Code, DeepSeek Harness, Codex, CodeBuddy, WorkBuddy, Hermes and OpenClaw share it.

The integration model is the thesis, and it is genuinely clever — §5 explains how it works without a plugin, a hook, or an MCP server.

Finding 01 · Provenance

Three histories that never meet, and the newest orphan is the default

merge-base main feat/server_team returns no common ancestor. Each major version was published as a fresh orphan branch rather than a continuation — so a plain clone reports 17 commits and 4 authors for a repository that holds 148 commits and 26 authors.

The cost is 21 people. Twenty-four authors have committed to main; four to the default branch; twenty-one only to main — a real [good first issue] programme with PR numbers into the 900s, invisible on the branch the world clones.

Correction against my own first reading

The files mostly survived, under a MemoryCore/ prefix. What was lost is history, attribution — and one security fix.

Finding 02 · The gate

A guard that prints PASS on the file it exists to block

The single CI workflow fires on: pull_request: branches: [main] — but the default branch is feat/server_team, so a PR opened against it (GitHub's default base) runs nothing. And main, the only branch it does fire on, has no MemoryCore/ directory — which is the workflow's working-directory.

Its red-line guard lists forbidden paths as src/core/state/types.ts and tests them with grep -qx, an exact whole-line match. On this branch the code lives at MemoryCore/src/…, and git diff --name-only always emits repo-root-relative paths. So I appended one line to the first file on the forbidden list and ran the guard exactly as CI does:

--- git diff --name-only, from inside MemoryCore ---
MemoryCore/src/core/state/types.ts
--- the guard, run as CI runs it ---
[skill-queue-isolation] BASE_REF=origin/main MODE=working-tree
[skill-queue-isolation] PASS
GUARD EXIT=0

Three independent ways for one guard never to protect anything: the script is missing on the branch CI fires on; CI never fires on the branch the script is on; and where it does run, its paths cannot match.

And the remediation pointer is dangling too

The guard's failure message ends “参考 ADR: docs/design/2026-06-16-skill-extract-queue.md”. That file has never existed on any commit on any ref. The broken pointer is protected from discovery by the broken gate — the one moment a developer would read that line is a moment the guard cannot produce.

Finding 03 · The reversion

A merged security fix, undone by the rewrite, with its test deleted in the same move

On main, commit 823b478 — “fix(security): enable L1 prompt injection filtering (#175)”, from an outside contributor — uncommented one line and added 22 lines of regression test.

-  // if (looksLikePromptInjection(text)) return false;
+  if (looksLikePromptInjection(text)) return false;

On the default branch — the published v2.0.1-beta.2 — it is commented out again, sanitize.test.ts is gone, and looksLikePromptInjection is exported at sanitize.ts:217 with exactly zero callers. No superseding filter exists anywhere in the three source trees.

The detector is expert work — seventeen-plus patterns across instruction override, role hijack and system-prompt probing, including one that guards their own context-boundary tag. And the live call site still advertises the filter:

Quality gate: filter messages through L1 extraction rules (length, symbols, prompt injection, etc.) before sending to the LLM. l1-extractor.ts:161–164 — of the three responsibilities named, exactly one is implemented

It matters because of where memory lands. Injection point is system.suffix: untrusted conversation text → L1 extraction with the filter off → persisted memory atom → re-injected into the system prompt of every future request, across sessions and across agents. One poisoned memory becomes a persistent, cross-agent, system-level instruction.

Finding 04 · The export boundary

Ninety-seven pointers to a directory that has never existed

Twenty-six distinct design documents are cited 97 times — credential plans, a multinode state audit referenced by its P0-2 item, an internal telemetry plan cited by section number from five files. The whole repository contains two files under any docs/ path, and docs/design/ has never existed on any commit on any ref.

These were not comments that went stale. They were correct in the repository they were written in, and were invalidated by the act of publishing. Nothing rotted — the code was copied across a boundary and the thing it pointed at was not.

The transferable rule

When you export, mirror or extract a subset of a repository, every internal cross-reference in the copied files silently becomes a dangling pointer — and no linter in either repository can see it. In the source they all resolve; in the destination nothing knows they were ever supposed to.

Finding 05 · The mechanism

How to extend an agent you cannot modify

L3 persona goes straight into the system field as <l3_core_memory>. L2 goes in as a path index only. L0 and L1 are never auto-recalled — instead the proxy appends a curl recipe to the system prompt and lets the agent fetch them with the shell it already has, while the proxy injects the credentials on the way out so the recipe holds no secrets.

⚠️ 重要：这不是文档，这是你的可用能力 … 禁止回答类似「我没有这个工具 / 需要 MCP / 需要斜杠命令」 tdai-profile-memory-injector.ts:164 — “this is not documentation, this is your available capability” … “forbidden: answering ‘I don't have this tool / this needs MCP’”

They discovered the model's trained instinct is to reply “I'd need an MCP server for that”, and wrote a prohibition against it into the prompt. The read surface is properly fenced: the bridge allow-list contains only search, query, ls and read.

One more detail worth the whole file: the Anthropic adapter preserves cache_control prompt-cache breakpoints across its parse-and-reserialize round trip. A naive rewriting proxy would silently destroy Claude's prompt caching and multiply your bill.

Finding 06 · The thesis

The lock is excellent. The door ships open.

The asset ACL is a small masterclass. private refuses team admins, enforced by ordering — the owner check returns first, so admin-ness is never consulted. The comment enumerates its own blast radius. The only escape hatch requires the owner to act. And a second predicate closes the door an ACL over human reads would leave open: restricted assets cannot be bound to an agent at all.

Its default was changed to private in July.

Meanwhile the gateway that stores those assets ships with authentication disabled. The team did not overlook this — their startup logging is the best I have read in a corpus subject, warning harder when the service is non-loopback without a key and naming the four exposed endpoints. Their own comment says that combination “is what the security audit flagged as a real exposure.”

And the documented one-command install produces exactly it:

  1. .env.example:80 ships MEMORY_CORE_GATEWAY_API_KEY= — empty, and with no REPLACE_ME marker, while the two keys you are told to fill both have one
  2. the installer passes it through as an empty string
  3. config.ts:815 coerces "" to undefined — return v || undefined
  4. server.ts:1118 — if (!expected) return "ok"; // auth disabled

Two of my drafts died here, and the truth is better than both. It is not that the installer is careless, and it is not that they forgot. The .env.example says so outright:

留空（默认）—— 关闭 Bearer gate … 非空 —— proxy 目前不发这个 header，因此 proxy 的 auth/sessionInit 会失败。生产环境后续需在 proxy 侧修复后再启用非空 key。 .env.example:74–79 — “empty (default) turns off the Bearer gate … non-empty: the proxy does not send this header, so its auth/sessionInit will fail. For production this must be fixed on the proxy side before enabling a non-empty key.”

Authentication is off by default because turning it on breaks the product. The two available states are off-and-working or on-and-broken — and that sentence ships inside the default configuration of a released version.

The rule this ship contributes

The ACL default moved to safety because nothing broke. The auth default stayed unsafe because the proxy would break. Same organisation, same release, both reasoned, both written down. A discipline travels freely wherever it is free, and stops wherever the safe choice would cost something.

Which means “do they take security seriously?” is the wrong audit question. The right one is: which of your safe defaults were free?

Credit where it is due

What is good here, stated plainly

A default chosen by asymmetric harm, with the reasoning in the code. The billing path picks the fallback that under-charges rather than over-charges, and says why: “风险不对称” — the risk is asymmetric.

Telemetry off by default, endpoint a placeholder, writes architecturally forbidden from throwing, a 90-day TTL, and a field cap specifically to stop a log-wording change exploding column cardinality. No covert phone-home anywhere. The SDK does not default to Tencent's cloud — that address appears only in docstrings.

Attribution disclosed, not hidden. The README credits colbymchenry/codegraph — a prior subject in this corpus — with “uses code from this project”, credits Hermes Agent, and credits Karpathy's LLM Wiki gist by URL as the direct influence on its Wiki layer. That is this vault's own founding pattern, productized by a cloud vendor, and the sharp contrast to a prior subject that bundled corpus code silently and uncredited.

But

There is no NOTICE file and no third-party licence file — only a LICENSE naming Tencent alone, while MIT requires the notice in all copies. The acknowledgement is in the README; the obligation is in the LICENSE file. Prose credit is not licence compliance.

Method

What went wrong on my side

Hand-verified throughout, with a twenty-agent fleet for breadth and adversarial verification. Two dimensions hit the structured-output retry cap; both were areas I had already covered by hand.

One refuter disputed my commit count with a reproduction string showing the command returning 50. The same command returns 108, as do two other methods. A refuter's reproduction string is itself a claim, not a check — it will present a wrong number in the format of a verified one.

✕

“The README's clone command is broken.” It redirects and works.

✕

“The installer takes the safe default and makes it unsafe.” A container binding all interfaces behind a published port is ordinary Docker, and the installer does set the variable.

✕

“Hermes and OpenClaw are unsupported.” They use the generic path, which is the architecture's whole point.

→

Three of those are one shape: I inferred the absence of a capability from the absence of a file. The fix is not to search harder. It is to open the thing the measurement measured.

Pilot

Read and borrow. Nothing to install.

Forty-five minutes, and it pays for the ship. Add an export-boundary pointer check to the vault's inventory script: extract every internal path referenced from any vault document and assert it exists. Ten lines. It would have caught the chapter-filename drift, the five unindexed state files found at v255, and the copy-forward exposure the last audit handed forward.

Then a default-cost register in the ratified candidate-LLM policy: for each safety-relevant default, record the safe value, what it costs, whether we took it — and where we didn't, what would have to change to make the safe value free. That, not a warning, is the remediation.

Then the ACL. Port its shape into candidate-data authorization: owner check before the visibility switch, blast radius in the comment, owner-only escape hatch, and a separate bind predicate defaulting to refusal. Then write the test it enables — a private candidate record must not be bindable to a shared screening agent. That closes the standing top risk in the API-security thread with a worked example from a subject that got it right.

Never

Point it at anything containing candidate data. Leave the memory port reachable beyond loopback. Rely on the ACL without testing it — there are no tests to run. Or assume the injection filter is on. It is not.
